# 项目终稿步骤模板

将以下要求用于外部计划的最后一个文本步骤，并声明依赖及 Markdown 输出路径。
生产执行器不会额外隐式运行第二次 Aggregator。

> 综合依赖步骤提供的证据与审计结论，生成可独立阅读的报告。
> 使用原始任务的语言，说明范围、方法、主要发现、证据、局限和下一步建议。
> 区分事实、推断和建议。每条关键判断关联可核验来源；不要把模型回答当作来源原文。
> 列明缺失、部分完成和失败阶段带来的影响，以及哪些结论因此只能暂定。
> 只使用本次注入的资料；节选被截断时说明核验范围。不要编造检索、实验和附件。
> 返回 research-step-v1 契约，将报告内容放入声明的 Markdown artifact.content。

建议为终稿启用 `metadata.result_contract: "research-step-v1"`，
跨分支的尽力交付可设置 `metadata.allow_partial_dependencies: true`。
返回的多个文件分别校验；程序将终稿 Markdown 投影为报告，并保留上游失败/缺口。
存在项目研究证据时，终稿复用已有引用与数值检查；验证回退会标为部分完成。
报告导出能力及依赖以部署配置为准，不凭提示词自动生成 DOCX/PDF/PPTX。
