# 学术检索(academic-search-v2)

## 零、部署约定(先读这段)

本 skill 会被装进别的仓库当子目录用,所以有两件事**不能照后文的字面抄**,先在这里定死。
下面两个变量按你所在编排层的实际值填,后文所有命令都用它们:

```bash
SK=<本 skill 目录>       # feat-ai-researcher: .claude/skills/academic-search-v2
DEEP=<深读产物目录>      # feat-ai-researcher: work/<slug>/<stage>/deepread
```

1. **命令一律带 `$SK` 前缀,不要用裸的 `scripts/`。** CWD 通常是宿主仓库的根,不是 skill 目录。

2. **`deepread.sh` 必须传第二个参数。** 不传就落进 `./tmp/deepread/<md5>/` —— 那只够手工
   试跑:流水线里跨 step 会丢,宿主仓库多半也不许在这个位置写文件。一律写成
   `"$SK/scripts/deepread.sh" <src> "$DEEP/<md5>"`。深读产物是**过程文件**;要交给用户的
   正文摘录或图,自己另拷到宿主仓库的产物目录(feat-ai-researcher 是 `output/<slug>/<stage>/`)。

3. **默认自行决断,不要停下来等回复。** 后文凡是"先跟用户确认""问用户要不要""请用户确认",
   在无人值守场景(headless 流水线、定时任务、Vela step)**一律改成自行决断 + 把理由和取舍
   写进产物**——比如"这批 12 篇里只深读了被引最高且有开放 PDF 的 3 篇,其余 9 篇付费墙,
   已在表里标注"。收不完整就如实标 `partial` 并写清缺口,不要伪装成失败,更不要以"等待回复"
   结束。只有编排层明确告诉你有人在场时,才值得为高代价的取舍先问一句。

你是这套系统的**主 agent**。判断用户想要什么、写查询、调接口、读结果、决定要不要深读、
向用户呈现——**所有需要判断力的活都是你自己做**。结果很多时可以派子 agent 帮你从大量结果里
筛相关的,但发查询、取正文这些动作由你亲自发。
