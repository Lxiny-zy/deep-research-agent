# 长任务:时间窗口与增量落盘(跑长 step / 起 Subagent 前必读)

仓库根 `AGENTS.md`「长任务」一节的完整版。平台的窗口规则、GPU step 的切分纪律、
以及 Subagent 的委派与落盘要求都在这里。

## 长 Workflow 必须增量落盘

调用 `Workflow` / `parallel()` / 多 Agent 做长研究时，**最终 REPORT 不是唯一存储**。后台 Agent 可能被取消、超时或进程终止；只在最后返回结构化结果，会让此前所有推导不可复用。

- **慎用 Subagent**：只在子问题能够独立验证、并且并行确实会推进当前 step 时才委派。不得把整个 step 或原始问题原封不动地丢给 Subagent。
- 每个 Subagent 的 prompt 必须明确写出：**单一具体目标、必读输入/现有材料、互不冲突的落盘路径、可检查的完成条件**。模糊的“深入研究一下”不是合格委派。
- 先等待当前委派返回、读回结果并写轮次小结，再按已发现的缺口决定是否需要新的 Subagent；不要无目标地连续扩张研究分支。
- 每个 Subagent 使用互不冲突的具体路径，例如 `work/<task>/rounds/<round>-<label>.md`。不要用隔离 worktree 作为唯一存储；必须让主 Agent 在当前工作区能直接读到记录。prompt 必须要求它在读完已有材料后先写初始判断，此后每得到一个已证事实、否定一条路线或改变搜索方向就立即更新文件，最后再返回 REPORT。
- 父 Agent 每批完成后更新 `work/<task>/rounds/index.md`，至少记录：已证事实、失败路线及准确缺口、仍在运行/未启动的方向、下一批选择理由。
- 部分结果只能写 `work/`，不得混入 `output/`。即使本 step 最终失败，也必须让后续从失败步骤续跑时能直接读取这些记录，而不是重复搜索。

## 长任务时间窗口

- 单 step 每个执行窗口最多 4 小时。第一次到点后平台会保存现场并要求尽快收敛;第二次到点后会要求记录全部已有工作并在最后一个窗口收尾;第三个窗口结束仍未完成时,该 step 记为 `partial` 并继续后续步骤。
- GPU step 与 CPU step 的窗口规则相同:每窗口 4 小时、最多 3 个窗口,窗口从 GPU 容器开始运行起算(排队等机器不计入)。窗口到点时容器被终止,但**在退出前会把当时的工作区整体回传**,下一个窗口从那份状态接着跑并带上续跑提示;三个窗口用完仍未完成,该 step 记为 `partial`,后续步骤基于最后一次回传的产物继续。
- 因此 GPU step 的有效预算是 **12 小时**,而一次中断最多损失一个窗口。**但"最多损失一个窗口"只在你按 Invariant 4 逐行落盘时才成立**:回传的是文件,内存里的东西不会跟着回来。
- **GPU step 里只放非 GPU 不可的计算。** 装依赖、下数据、校验、特征预处理、dry-run 一律放到前面的 CPU step 完成并落盘;GPU 窗口应该拿到一个可以直接开跑的工作区。一次实测:准备在前一个 CPU step 用了 35 分钟,GPU step 只训练 —— 这是应有的分工。

  **训练放不进窗口时,切分,不要缩水。** 这是本节最容易做错的一条:装不下就把模型改小、epoch 砍半、seed 从 3 降到 1、数据子采样 —— 于是交付出来的是一个玩具实验,而限制被伪装成了"方法选择"。正确做法:

  - 优先靠续跑:让训练可从 `rows.jsonl` 断点继续,跨窗口自然累积,不需要你做任何事。
  - 需要更多时,按**可独立回传的单元**拆成多个 GPU step:一个 seed 一步、一个模型一步、一个数据子集一步。总时长只受 48 小时任务上限约束。
  - 规模由研究需求决定,不由窗口决定。**若某个必要实验无论怎么拆都放不下,如实写进报告和 `execution_log.md`:需要多长、卡在哪个平台限制上、已完成到哪一步。** 让限制可见、由人决定是否加资源;不要自行把科学问题改小来迁就它。
- 整个任务最长 48 小时,其中最后 4 小时保留给诚实的最终报告。不要把窗口当成应当耗尽的预算;一旦达到可检查的完成条件就立即收尾。
- 收到超时续跑提示后,先读取现有 `work/` 和超时恢复记录,基于已完成内容缩小剩余范围。不得清空重来,也不得继续无目标扩张 Subagent。
- **不要主动杀掉自己启动的、仍在正常推进的长进程。** 你看不到"还剩多少时间"——平台不会把剩余秒数告诉你,窗口起点也不在你手上,所以任何"时间快到了"的判断都是猜的。到点由平台负责:CPU step 会保存现场并给续跑窗口,GPU step 由 pod deadline 处理,两种情况工作区都会被快照。曾经有一次 agent 自行 `kill -TERM` 掉训练进程,比真实上限早了整整一小时,52 分钟的 GPU 计算因此全部作废。只有进程确实卡死(无输出、无进展)才终止,并在 `execution_log.md` 写明判据。
- 反过来:**正因为你不知道还剩多久,产出必须随时可被截断**。长进程要按 `experiment-suite` 的 Invariant 4 逐行落盘,任何时刻被杀都留下有效部分结果 —— CPU 与 GPU step 都靠这一条:平台回传的是**文件**,只存在内存里的进度不会跟着回来。
