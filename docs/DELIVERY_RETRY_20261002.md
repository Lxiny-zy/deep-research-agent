# 按格式恢复交付与不可变版本

本批仅本地修改、生成样稿及验证，未推送、未部署，没有调用真实模型。整体项目目标仍未完成。

## 现在的行为

首次生成保存定稿、格式参数、结构化导图/演示数据、统计结果和输入检查记录。图表保存在该交付版本的文件中。生成失败的格式单独列在登记的 `failures`，页面显示原因和“重新生成”按钮；正文或证据失败的正式格式标明不可通过重新导出恢复。

重试使用保存的定稿快照，只调用所选失败格式的导出器。它不会重新调用 LLM、重新统计数据或重画已有图表，其他已经生成的文件直接复用字节。Word、HTML、PDF、PPTX、导图 HTML/PNG 和统计 XLSX 的重试均有针对性回归。统计 XLSX 不因报告叙述的支持关系失败而丢失。

每次重试创建新的不可变版本，记录父版本和次数，并原子更新当前版本指针。旧版本仍可按原来的 `version` 参数下载，文件树包含各版本。跨 API 进程读取当前指针，避免本进程缓存一直返回失败包。正文或渲染输入版本已经变化时拒绝重试旧输入，要求读取最新交付。

重试请求包含 `request_id`。同一请求重发、同时到达两个进程或页面连接中断后再点，都复用原结果；相同 ID 用于另一格式/版本会拒绝。另一个重试已经发布新版本时，旧版本请求收到明确冲突，前端刷新交付列表。只读身份和不属于当前身份的任务不能触发重试。

重新生成仍接受检查。跨格式检查现在将失败定位到具体格式，PDF 错误不会把完好的 HTML/Word 一起标为失败；无法解析的文件也会记录检查失败，不拖垮整包。文件或定稿快照校验失败时不覆盖已有版本。

## 验证样稿

```powershell
python -X utf8 -m scripts.verify_delivery_retry --output artifacts/acceptance/20261002/delivery-retry-new
```

输出目录必须不存在。当前产物位于 `artifacts/acceptance/20261002/delivery-format-retry/`，包括 `before.json`、`after.json`、`summary.json` 和 `recovered/`。

样稿使用合成综述，模拟首次 PDF 异常，实际调用导出器恢复 PDF。原有三个文件的字节相同，恢复后共四个文件，旧版本可读，重复请求返回同一版本，没有模型调用。样稿的研究质量状态为 **warn**，没有将格式恢复当作科学结论验证通过。

回归覆盖旧链接、当前指针、并发防重、提交失败恢复、过期输入拒绝、身份权限、不同任务格式、统计与图表不重算、损坏 PDF 隔离以及前端失败后的请求 ID 复用。

完整回归 1,775 通过、16 个 pg 未运行，覆盖率 88.89%；前端 367 通过；静态、类型、构建、OpenAPI、体积和依赖锁检查通过。隔离 Python 基础 wheel 验证启动与部分格式交付：缺少可选 Word/PDF 依赖时对应格式明确失败，HTML/Markdown 仍可生成。

实际测试还发现 Windows 深目录下原子写入的临时文件名可能比有效目标路径更长，超过路径上限。临时文件改用短随机名称，保持原有路径检查、原子替换及最终文件名；触发该问题的统计表/图表交付用例已复验。

## 范围与后续

交付输入版本提升至 11；更早的版本继续支持下载，当前定稿会生成含恢复快照的新版本。本次没有额外数据库迁移，快照、请求登记和指针在现有交付文件存储中原子发布。重试版本仍会保存一份文件副本，尚未做跨版本磁盘去重。

共享图表预处理本身失败的独立恢复、跨进程中断后的导出后台作业恢复、交付版本的生命周期管理、公式交叉引用、各任务专用排版与真实科学质量矩阵仍需继续完善。页面验证为组件测试和构建，未做浏览器人工验收；没有部署到 Aliyun 或验证生产代理行为。
