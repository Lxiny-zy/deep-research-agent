## 当前实现的实际差距

1. **三种 PDF 路径尚未统一。** 工作台 `workbench/publish.py` 调用 `workbench/delivery/pdf.py`，用 PyMuPDF Story 排 A4；`report/pdf.py` 用 WeasyPrint；`report/latex.py` 提供 XeLaTeX 论文 PDF。普通工作台交付尚未走同一论文排版流程。
2. **论文结构已有基础。** `ReportDocument` 已有作者、机构、摘要、关键词与 `PaperSection`；块类型目前为正文、表格、数据图，没有独立公式与通用插图块。应扩展原模型，避免再建一套报告系统。
3. **公式没有论文排版语义。** LaTeX 正文投影先转义 `$`、反斜杠等字符，只保留基本 Markdown；数学表达式不能直接据此得到公式排版。需要受控数学表达、公式编号与交叉引用，同时保留现有转义边界。
4. **模板名不等于投稿格式。** 现有 IEEE 模板是 `journal,onecolumn`，ACM 是 `manuscript,screen,nonacm`；不能把它们宣传成通用双栏终稿。当前 `longtable` 设计也不能直接套进常见双栏版面。
5. **引用输出仍偏报告。** 正文的 `[n]` 保持普通文本，参考文献走 `thebibliography`；独立 BibTeX 输出全部为 `@misc`。虽有真实来源元数据，但尚未完整驱动模板要求的文献样式和引用链接。
6. **成品检查不充分。** 工作台 PDF 已做解析、页数、缺字标记和末段哨兵检查；LaTeX 编译成功后直接返回 PDF 字节，尚无统一的字体嵌入、逐页越界、图表丢失、内容覆盖与最终日志检查。
7. **线上需补编译能力。** Docker 默认 `INSTALL_TEX=false`，此前部署的中文 PDF/XLSX 冒烟验证不代表 XeLaTeX 论文 PDF 已通过。启用论文编译需要验证工具、字体、模板和资源预算；已有服务器内存较小，应先本地生成样稿和测量，再安排部署。

## 下一批优先顺序

### P1：统一报告交付输入和基础样稿

- 以审核后的 `ReportDocument` 为输入，把工作台最终正文、图表、引用与输入来源对齐；从任务卡的交付入口可追溯到同一内容版本。
- 完善通用中文学术单栏报告版式，覆盖内容摘要、正文层级、页码、参考文献和证据附录。章节按综述/结论报告组织，不自动补造作者机构、原创贡献、实验或论文投稿栏目。
- 为公式、一般插图及图/表/公式交叉引用补足结构化表达。图表引用受管资产，公式支持受控语法，不向模型开放任意 TeX 包或执行指令。
- 制作一份固定的高光谱方法比较排版样稿：中文与英文、CASSI 测量公式、多行公式、矢量图、多面板图、宽表、跨页表、长 DOI/URL、参考文献及附录。内容为明确标注的合成测试材料，不作为科研结果。

**交付：** 综述/结论报告样稿 PDF、逐页预览及排版问题记录。排版中间文件保留在后台用于复现和诊断，不将论文源包作为默认用户交付物。

### P2：报告 PDF 验收与编译诊断

- 记录编译器/模板版本、退出状态、多遍编译收敛和最终日志；缺图、未定义引用、不可解析 PDF 或缺正文阻止成功交付。
- 检查全部页面的文本覆盖、字体嵌入、图表存在性、越界和页数；自动检查与实际视觉检查分开记录，明确页码范围。
- 对孤立标题、图表漂移、留白和小字号提供可定位的诊断；不通过静默删段、删除引用或缩小页边距掩盖失败。
- 检查综述覆盖范围、结论对应证据和未确定事项是否完整；不为套用论文结构而添加未经证据支持的内容。

**交付：** 报告 PDF 和可查看的质量检查结果。固定样稿中的缺字、缺图、悬空引用、宽表越界和尾部截断故障均有能检出的回归。

### P3：版本化登记与按格式恢复

- 接通现有 `publish()` / `ArtifactStore`，登记最终内容摘要、版式版本、编译记录、质量结果与产物哈希。
- 同一版本的文件树、预览和下载一致；重复下载及进程重启不重新生成文件。
- 版式或正文修订产生新版本；失败仅重试相应格式，不能覆盖既有成功交付或混入上轮旧稿。
- 回到 Word/PPT/导图的一致性验收，特别验证正文纠错后旧 deck 不再导出。

**交付：** 论文级排版的综述与结论 PDF，具有可追溯的内容版本及一致的预览、下载和恢复行为。
