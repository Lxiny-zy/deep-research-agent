# 完成状态与交付质量绑定

日期：2026-10-04。本轮仅本地修改和验证，没有推送、部署或新增模型调用。

## 用户可见行为

有冻结任务契约的研究现在按“保存定稿 → 生成并保存承诺格式 → 检查内容、格式和可读取性 → 写入最终状态”的顺序完成。文件生成期间仍为 `running`，通过检查后才为 `done`；存在未通过的检查、告警、缺失格式或缺少必需核验记录时为 `needs_review`（待复核）。

待复核结果可查看报告、证据、交付登记和草稿，可继续内容修订或重试失败格式。普通任务 `/resume` 仅处理执行错误，不绕过质量门。论文导入材料完整时，待复核任务仍能基于原文提问。历史记录、徽标、进度流和刷新后的详情均显示同一状态及问题摘要。

当前采用保守策略：交付 gate 的任何非 pass 都阻止正式完成，包括文体类告警；没有新增忽略告警的白名单。可下载的告警版本与完成任务明确区分。内容修订复用原材料和已通过核验的证据，文件重试复用定稿，保留原版本。

## 持久化与恢复

- 完成记录位于 `orchestration.checkpoint.scratch._completion`，详情接口另返回 `completion`。记录包含输入/交付版本、必需格式、必需验收门、问题、检查时间与最终状态。
- `finalize` 在同一事务保存记录和状态，校验执行租约，并与取消竞争；已取消或已交接的任务不会被旧执行者标记完成。内存仓储也复制嵌套快照，错误参数不留下部分写入。
- 格式重试通过版本比较更新完成状态；文件提交后若数据库暂时失败，下一次读取交付或重放重试请求会从已提交文件版本补齐状态，不再渲染或调用模型。旧请求不能覆盖较新的完成记录。
- SQL 完成、恢复和完成记录更新采用一致的 workflow → run 锁顺序；PostgreSQL 并发、取消、fencing 和 CAS 已单独验证。
- 冻结契约中的章节与格式优先于当前模板。输入指纹保留材料、证据、配置等语义数据，仅排除精确列出的时钟、计量、恢复和完成记录等运维字段，避免恢复后重复生成。格式版本为 49。
- 发布前实际打开 PNG、XLSX、DOCX、PPTX、PDF，检查文本文件编码及 JSON 结构。失败写入 `file_readability` gate 和格式重试登记，而不是只在界面显示一个不可恢复的问题。

## 验证

- 前端：61 个文件、436 项测试通过，lint、TypeScript、生产构建、OpenAPI 一致性和体积门槛通过。真实组件链路验证格式重试后从“待复核”刷新为“已完成”，旧问题摘要消失。
- 后续叙事兼容修复覆盖普通研究、统计分析及有/无终态事件：待复核不再显示进行中；前端区分 live/terminal 查询，避免旧请求覆盖最后状态，并在格式重试后刷新叙事。
- 任务通路：七类任务的 28 条策略/执行模式路径，以及学术问答场景共 30 项通过。保留原最小外部模型材料；短文、引用不足等真实告警必须得到唯一的待复核结论，未用填充或忽略告警换取完成。
- 完成事务与生命周期专项：42 项通过，包含文件生成前不得 done、警告/缺文件/坏 PNG/XLSX/缺核验记录不得 done、取消竞争、重启后复用字节与文件已提交但数据库落后时的恢复。
- 新 HTTP 故障测试证明：格式文件提交后注入数据库错误，首次返回 503；读取交付补齐数据库并更新详情，重复请求仅渲染一次，不增加模型调用。
- PostgreSQL：44 项通过（原 30 项与新增完成仓储 14 项），独立本机限额临时容器已清理，未访问现有数据库或远端。
- 最终后端全量 **2,468 passed、44 个 PostgreSQL 分支 skipped，覆盖率约 90%**，日志 `artifacts/completion-regression-final.log`；跳过的 44 项已在上述隔离 PostgreSQL 中单独全部通过。Ruff、387 文件格式检查、Mypy 206 个模块和 diff 检查通过。
- 第一轮 2,452 项通过、10 项失败：旧测试错误地把最小材料运行结束当作质量通过，以及历史无检查点记录的格式重试兼容问题；修正后的对应专项通过。覆盖率复验又发现单连接内存 SQLite 测试在取消连接后丢失 schema，生命周期测试改用真实部署同类的隔离文件 SQLite 后重新执行上述完整全量。原失败均未计为成功。

## 边界与下一步

1. 历史记录与自定义工作流如果没有冻结的交付契约，不会被默认模板擅自追加一套格式义务；原历史状态不会批量追溯改写。历史 done 仍需结合实际交付登记判断，不具有新的完成审计保证。
2. 本轮将已有质量判断接入真实完成状态，没有证明所有科学结论正确，也没有补齐所有新输入的首次完成质量矩阵。保守告警会让更多任务进入待复核，需要继续改善实际内容并验证可解释的收敛过程。
3. 单个格式正常失败会保存其他结果并支持独立重试；进程在整包首次提交之前崩溃时的逐格式检查点，仍需进一步实现。
4. 按身份、任务重量和优先级的公平调度尚未实现；inline 和独立 worker 必须统一进入持久队列，不能只改 SQL 排序。
5. 生产双 worker 切换、进程故障与并发压力验收尚未执行。新状态/Event 契约要求 API、worker、前端一起升级；没有新增数据库列，但不能混用新旧事件解析版本。

整体工程化目标继续保持进行中。
