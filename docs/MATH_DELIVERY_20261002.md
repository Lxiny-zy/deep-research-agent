# 数学排版、引用与交付生成验收

本批仅本地修改、生成样稿及验证，未推送、未部署，未连接实验室服务器或调用真实模型。交付对象仍是综述、精读结论和分析报告，不新增论文投稿流程。

## 已实现

- 问答、报告预览和打印稿接入 KaTeX；支持行内、独立、多行公式及数学代码围栏。流式未完成文本可以继续更新，公式闭合后正常排版，最终正文仍保留可点击的真实引用。
- 问答和报告写作共用固定的数学格式说明：变量/单位忠实于来源，长表达式分行，中文标注使用 `\text{}`，引用放在公式外，金额美元符号转义。说明在固定 system 部分，未改变论文材料在问题之前的请求顺序。
- HTML 自包含 SVG 路径和可访问 MathML；颜色随主题变化。主 PDF 使用相同数学结构生成矢量图形，不需要 Node、浏览器、TeX 或外部字体下载。PDF 可复制原始 TeX，Word 使用可编辑的原生 Office Math。
- 标题公式保留数学结构；PDF 标题公式跟随字号。表格列宽预留公式宽度，底部留出下沉空间，防止分母紧贴底线。分页后重复表头，普通图片和公式资源分别校验。
- 引用识别、终稿重编号、写作返工和引用质量检查共用位置保留的文本遮罩，公式索引、代码及链接目标不再被当成文献。数学块仍参与终稿支持关系核验；空行不会拆断公式检查，公式中的数值仍受检查。
- 交付格式版本由 9 升至 10，终稿支持核验签名升至 3，避免复用旧版缺少公式检查的结果。
- 修复 Windows 并发创建交付锁文件的初始化竞争。操作系统支持对空文件加锁，无需在取得锁之前写入哨兵字节；已有跨进程防重机制保持生效。
- Markdown 解析所需的轻量依赖纳入基础安装；数学绘图依赖加入可选 PDF 安装组。修复 wheel 打包把 `assets/pdfjs` 目录当成普通文件的问题，显式包含数学字体、PDF cMap 和标准字体。
- 依赖审计发现原锁中的 `urllib3 2.7.0` 存在三个已公布漏洞，已更新至 `2.8.0` 并同步四组锁文件。

## 可复现样稿

```powershell
python -X utf8 -m scripts.verify_math_delivery --output artifacts/acceptance/20261002/math-final
```

生成 Markdown、HTML、PDF、DOCX、逐页 PNG 和 `summary.json`。最终样稿为四页，Word 含 45 个原生公式，PDF 仅有一张普通示意图位图，35 条表格公式均恰好出现一次。样稿含分式、根号/上下标相关回归、矩阵、分段函数、多行对齐、中文标注和下标、引用、代码及金额；内容为合成排版材料，不代表真实研究结论。

本次检查了实际 PDF 页面，发现并修复金额与公式代码相邻时误解析、标题公式过小、表格分母靠近底线的问题。PDF 文字提取中，矢量公式的替代文本顺序不一定等于视觉位置，末段完整性检查已分别处理正文和公式，避免把正常文件误判为截断。
