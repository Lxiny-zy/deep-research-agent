# N6 PDF 图像区域选择入口

状态：本地工程实现；未部署。服务端字段、冻结与实际 PPT 裁剪由 N6 后端契约负责。

## 用户路径

仅在“幻灯片”任务、PDF 上传解析完成后出现“选择图像区域”。用户选择实际页码后，可点击“开始框选”
并用鼠标/触控拖动，或用键盘输入左、上、右、下的百分比范围。填写原文图号，加入区域清单后确认使用。
界面保留所选页、图号与本页原文摘录，说明区域只是可供幻灯片采用的图像素材，仍需对应证据核验，
图像底层内容不可编辑。

- 全任务最多 4 个区域，各 PDF 共享余额。
- 同一附件的同一图号只能选择一个区域，跨页相同图号也拒绝重复，避免歧义。
- 坐标以 PDF.js 渲染后的可见页面左上角为原点，向右/下递增，范围归一化为 0–1；页码从 1 开始。
- 页码选择只列 PDF 实际页数；无效、倒置、越界或零面积范围不能加入。
- 关闭对话框会释放加载/渲染任务；读取及单页渲染都有 45 秒截止。选择器懒加载，不让工作台首屏预加载 PDF 引擎。

## 数据契约

`useAttachments` 仅在内存保留原始 PDF `File`，供本地 PDF.js 预览，不增加原件下载 API。
提交仍使用既有 `attachments`，每个附件可含：

```json
{"image_regions":[{"page":2,"figure_label":"Fig. 1","bounds":[0.1,0.2,0.5,0.6]}]}
```

原始 File 对象不序列化入任务请求。移除附件同时清理其区域；修改区域会改变提交身份指纹，
不会继续使用先前失败请求的幂等标识。未完成任务的选择只影响本次提交，不改已完成任务。

## 验证

- 坐标/图号与 File 生命周期单测，加既有附件与研究表单测试：26 项通过。
- 桌面真实浏览器：键盘选区、实际页码、跨页同图号拒重、共享 4 区域限额、payload 不含 File、
  相同附件列表下仅改区域也使用新的提交身份、移除附件后释放额度。
- 手机真实浏览器：Chromium 原生触控输入选择框，坐标与可见页面百分比一致，控件可达、对话框无横向溢出。
- 场景使用隔离真实 API 的上传解析与原始 PDF，创建任务的模型入口被测试 wrapper 禁止。
  浏览器测试验证请求载荷，不以此宣称完成了模型选图或真实科研 PPT 质量验收。

实现：`PdfRegionPicker.tsx`、`lib/pdfRegions.ts`、`useAttachments` 与 `AttachmentDropzone` 的小范围接线。
浏览器场景：`frontend/tests/browser/integration-pdf-regions.spec.ts`。
证据随 `npm run test:browser:integration` 保存在 `artifacts/browser-integration/`。
