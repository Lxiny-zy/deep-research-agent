# 检索可靠性改进计划

日期：2026-09-09

在已有检索档案与角色绑定基础上，按以下顺序修复。保留既有配置兼容性；验收使用合成凭据和临时数据库。

1. [x] 合并相同 URL 时优先保留非空正文，记录各渠道的内容哈希与选择结果，避免混合不同版本正文。
2. [x] 将检索成功、部分失败与 Key 切换接入运行事件；上游错误只记录安全分类。
3. [x] 外接搜索模型的用量计入总 Token；区分已知用量与缺失用量，记录调用次数与协议。
4. [x] Key 增加冷却、Retry-After、失效状态和并发限制；共享凭据在同一进程的任务间共用健康状态。
5. [x] 增加无付费请求的配置预检，展示角色实际资源；提交时校验必需检索凭据；提示资源停用的引用影响。
6. [x] 浏览器流程接入 CI；增加检索证据、失败恢复、并发与 PostgreSQL 引用一致性测试，更新配置指南和验收记录。

完成标准：针对缺陷的回归测试通过，后端类型/代码检查与前端测试/构建通过，浏览器流程验证成功。真实供应商费用不根据 Token 数虚构；跨进程健康共享与付费端点实测单独说明边界。

实现记录：`MultiBackendSearch` 选择有正文的重复来源并发出来源变体事件；`ApiKeyPoolSearch` 使用进程内按事件循环隔离的 Key 健康状态、并发信号量和 Retry-After 冷却；`ModelSearch` 把可识别 usage 加入 `Tracer`。`/api/resource-preflight` 是只读检查，`/api/search-resources/impact` 返回停用影响；新研究页面可以主动检查，提交时仍由后端复核。浏览器验收已加入 CI，并在锁文件中加入 Playwright。
