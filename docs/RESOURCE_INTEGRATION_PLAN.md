# 检索与角色配置整合计划

日期：2026-09-09

## 目标与边界

将检索资源、角色和提示词贯通到实际运行、证据保存与断点恢复。保留现有工作流和凭据，兼容旧角色的提示词替换语义；不把数据库迁移、前端表单或连接测试单独视为功能完成。

已有未提交的多渠道 Key 改动作为本次工作的基础，不覆盖或撤销。

## 配置模型

- 检索档案描述一个检索服务：名称、协议/渠道、端点、搜索模型以及引用的 Key。多个档案可以组合查询。
- 内置渠道保留稳定的默认档案，沿用其渠道 Key 池及环境变量兜底，旧配置无需手工重建。自定义端点明确绑定 Key，避免误用其他服务的凭据。
- 设置页只选择默认检索档案。凭据统一在角色广场维护，不再提供重复的搜索密钥输入框。
- 研究角色可继承默认检索配置，或绑定自己的一个或多个检索档案。角色绑定优先于全局默认；配置错误不静默换用其他服务。
- 新角色默认补充内置提示词；旧角色保留替换语义。固定输出契约、全局规则和角色指令独立展示，并由同一后端渲染函数生成预览和实际提示词。

## 已知限制与使用方式

- 未调用真实付费服务，生产 PostgreSQL 与服务商端点/账号配额需要在对应部署中验证；第三方协议特殊参数仍需专用适配器。
- 无法读取的引用网页保留 URL，但不提供可通过原文验证的证据。旧 checkpoint 未记录的信息无法追溯恢复。
- 构建仍提示既有 Three.js 可视化 chunk 大于 500 KB，不影响本次构建成功；本次未扩展为全站性能重构。
- 后端正常重启会按现有启动流程执行 `0024` / `0025` 迁移。重启后按 [配置指南](SEARCH_AND_ROLE_CONFIGURATION.md) 维护检索资源，再将研究角色选入工作流。
