# 连续证据与结构化字段核验

本批仅修改本地项目。使用已授权的 Aliyun 现有模型配置调用真实模型，凭据只在进程内存使用；未推送、未部署、未连接实验室服务器。

## 问题与变更

原失败精读样本共有 50 条逐字命中的发现，只有 20 条得到语义支持，另有 13 条数值检查不支持（两组有交集）。多个结论包含方法归属、多个组件或实验条件，引文却只复制其中一句；表格常只复制数字，没有保留表头和对象名称。

- 取消 `evidence_quote` 的 500 字符限制。抽取要求使用必要的完整连续原文，保留归属、条件、表头与相关行；禁止拼接不同片段冒充连续引文。界面上下文仍是短预览，完整引文、原文范围和内容哈希独立保存。
- 语义核验同时接收 `statement`、`entity`、`quantity` 和 `conditions`，检查条件是否确实属于本次测量。原实现只提供正文陈述与引文，单独填写的实验条件没有进入此核验。
- 相同 URL、来源哈希、引文的证据在单个请求内只发送一次，放在固定材料前部。待检查记录按编号引用该证据；字段字符串中的换行经 JSON 转义，不能伪装为新记录。
- 按模型实际输入容量组批，计入规则、Schema 与修订空间；不截断单条证据、不限制累计 token。单条超容量明确失败或标记不确定。没有新增单次输出限制。
- 拒绝遗漏、重复或未知核验编号，避免重复编号“最后一条覆盖前一条”误放行；租约丢失继续向上传播，不当作普通模型失败吞掉。论文问答进程缓存契约升至 6。

## 真实模型校准

`scripts/accept_evidence_contract_live.py` 使用 `deepseek-v4.1-flash` 验证六个明确标注为合成的样例：正确结构化字段、编造数据集、编造硬件、错配方法、错误单位，以及超过旧字符限制的完整表格证据。六个均得到预期结果，总消耗 3,611 token。没有把单次校准当成普遍准确率或缓存节省比例。

输入与原始响应位于 `artifacts/acceptance/20261002/evidence-contract/`。完整论文另在 `cold-paper-contract/` 从 PDF 重新解析、抽取及写作，未复用旧发现或报告。

## 新论文的实际解析缺陷

20 页《Hyperspectral Panoramic Image Stitching Using Robust Matching and Adaptive Bundle Adjustment》的本地 PDF 没有触发截断，但原解析器将摘要续句 `method using covariance correspondences...` 误判为方法标题。摘要因此分属两个不重叠章节，完整摘要识别正确地拒绝了无法证明连续的拼接。

修复在章节边界识别处完成：保留明确的章节名称、编号标题、Title Case 扩展标题和行内 Abstract 标签；不再把仅以 method/results 等词开头的普通续句直接切为章节。同一 PDF 重解析后从 22 个片段变为 19 个片段，识别出 1,219 字符完整摘要，结尾包含最终实验结论。原始与修复后的输入审计均保存，没有用正文补写原摘要。

此缺陷在完整模型任务启动后才发现，因此该任务使用原先冻结的解析片段，不能用重解析的成功冒充该模型任务已通过。

完整任务最终失败：2,541 秒、448,377 token、19 次模型响应，只有诊断 Markdown 与图，没有合格 PDF。64 条候选中 53 条逐字命中，49 条得到语义支持，结合数值等门禁最终 37 条可用于写作；8 条引文超过旧 500 字符限制，最长 778 字符。该论文与此前失败样本不同，不把这两个样本的准入比例当作同输入优化对照。

正文问题包括原论文引用号混入当前引用、表格数据行漏引用、把采用既有算法的组合写成原创性结论，以及无引文依据的指标定义、范围和绝对化表述。报告未通过后，仍有 175,777 token 用于后续检查及图示，其中可选图示链占 142,271 token。模型报告的思考 token 为 202,313；总耗时不能归因于单纯网络等待。原任务的完整结果、事件和调用汇总均保留在 `cold-paper-contract/paperRead/`。

现在只有正文通过机械、结构与支持关系检查后才生成可选图示。补充表格逐行引用、指标定义和公式记号的写作要求。`accept_paper_revision_live.py --abstract-pdf` 校验原始 PDF 与任务附件内容标识，新增独立的摘要解析资料，保留旧证据来源；已用相同文件恢复并验证不同文件会被拒绝。

恢复任务 `cold-paper-repair/` 复用这 37 条发现，没有重新抽取全文。第一版有 7 个问题；修订第二版后，37 个正文核验单元（含完整摘要翻译）通过。图示经修订后，37 个图示单元通过，得到五文件；新增 250,388 token，1,105 秒。该样本经过恢复与修订，不是最新代码下一次冷启动全部成功的证明。所有本批真实模型进程均已结束。

## PDF 实际查看与确定性重导出

重放保存的真实核验判断（校对请求长度、单元编号，拒绝缺失判断）先生成正文四格式，没有新增模型调用。实际查看发现“主要结果”标题单独留在页末：PyMuPDF Story 未可靠执行 CSS 的避免标题后分页规则。现在按标题组拆分排版流，为后文起始行留空间，连续多级标题也与表格、公式、图像衔接。

图示查看还发现，有反馈环时原拓扑算法把环及其下游全部放回首层，导致流程倒置、回线拥挤。现在先按强连通分量组织反馈环，再对分量图分层；长流程可用四列，反馈边绕开中间节点。根据实际文字边界放置关系标签，避免与节点或其他标签重叠，移动的标签保留引线；SAD 等短英文标记不再从中间断行。图的节点、关系及核验依据未改变，没有重新调用模型。

最终产物是 `artifacts/acceptance/20261002/cold-paper-layout-18/`：Markdown、HTML、DOCX、PDF、PNG 图示，五文件检查通过，PDF 六页；正文公式、三线表、标题衔接与图示页面均已查看。交付格式版本为 18，16、17 为中间验收版本，旧文件未覆盖。正文预览和早期图示版本不作为本批推荐交付。

## 边界

进一步复查旧失败数值发现三种可独立复现的误拒：`45 seconds` 无法匹配秒、`PSNR gain` 被当作未知指标，以及其他句子的 PSNR 标签干扰 β1 参数。补齐英文时间单位、识别单一指标的修饰名称，并将近邻指标判断限定到同一分句；不认识的参数和无法从文本布局确认的表头对应关系交给已补齐字段的语义核验，数值、单位与比较符仍独立检查。相关数值、证据、报告及对照表回归 154 项通过，包含错单位、错数值与错指标继续被拒绝的对照。

证据契约修改后，后端完整回归 1,829 通过；加上 PDF 解析修复后 1,830 通过；加入数值修复及图示生成前置条件后 1,839 通过；最后加入分页与图示布局修复，最终完整回归 **1,849 通过、16 个 PostgreSQL 用例未运行，覆盖率 88.92%**。Ruff、格式、Mypy（185 个源码文件）、OpenAPI、生产构建和依赖锁检查通过；包含最终版式修复的 wheel 在隔离基础环境安装后的启动、迁移、资源与部分格式导出冒烟通过。前端本批只有 API 字段说明同步，交互未改，沿用上批 368 项前端回归；没有执行浏览器验收。

本批支持同一来源片段内的连续证据。跨片段的表格、PDF 文本解析丢失的行列关系、统一文档身份与参考文献仍需继续处理；不能仅因引文变长便认定所有数值关系已恢复。概念图仍是位图，更复杂稠密关系与矢量图仍需优化。旧任务的历史语义判断不会因更新代码而自动重新核验。整体真实任务质量矩阵尚未完成。
