# 任务场景可用性与交付验收计划

更新：2026-10-03。用户要求先部署最新版本，并将后续工作重心转向完整功能场景。本次发布已完成，后续修改尚未部署。此计划为当前优先级；历史修复记录用于追溯，不直接决定下一步。

## 目标与当前边界

让用户在每个功能入口提交真实材料后，能够看到明确进度、得到符合该任务要求的结果、查看引用并下载可用产物；出错时能理解原因并恢复。交付对象是综述、精读结论、分析报告、评审意见、汇报材料等，版式遵循学术规范，不新增论文投稿流程。

现有实现与大量自动回归不能证明所有场景都已可用。真实状态以 [质量矩阵](REAL_TASK_QUALITY_MATRIX.md) 的样本和失败记录为准。用户负责浏览器手动验收，开发侧负责接口、模型链路、文件内容与导出验证。

## P1：逐类建立完整真实任务基线

先覆盖缺少真实验证的模块，避免继续集中于单个论文样本。保留当前运行中的综述结果，不重做已完成的付费读取。实际顺序为：同行评审、汇报幻灯片、自动研究、新版多输入导图；随后补齐综述、精读、连续追问与数据分析的首次完成验证。共用阻断出现时先修复，再继续未覆盖模块。

| 场景 | 代表输入与操作 | 必须交付的结果 |
| --- | --- | --- |
| 同行评审 | 一篇完整论文与明确评价维度 | 与原文对应的贡献、优缺点和可执行修改建议；评分理由一致，不能把未核实内容当缺陷 |
| 汇报幻灯片 | 已有材料、目标听众、汇报时长 | 可打开的 PPTX、合理内容密度、准确图表和讲稿备注；关键结论、引用与源材料一致 |
| 自动研究 | 范围明确的实际研究问题 | 实际检索与来源读取、支持结论的证据、回答问题的报告；检索失败不能伪装完成 |
| 思维导图 | 多份材料与指定主题 | 可用的交互/导出文件、正确概念层级与关系、覆盖用户主题，不能只有事实堆积 |
| 文献综述 | 指定多篇文献；另测开放检索 | 跨文献主题综合、比较条件、结论与局限，不能用证据摘录清单代替综述 |
| 论文精读 | 一篇此前未用于修复的完整论文 | 完整摘要处理、核心方法、关键结果与适用条件、有效原文引用及可用报告 |
| 论文追问/学术问答 | 同一会话多轮含指代、比较及新问题 | 正确保留上下文，正文/返回的思考内容持续呈现，复用已有材料，引用能定位 |
| 数据分析 | 有说明的真实或公开数据，含缺失/异常情况 | 分析方法与数据相符，可复核统计、图表、解释及可打开的数据/报告文件 |

每个场景先跑完整新任务；恢复成功单独记录，不能覆盖原首次失败。完成全部类别的初步基线后，根据失败风险扩展输入及稳定性复验，不声称单个成功样本代表全部输入。

当前执行顺序：优化配套图示的证据选取与额外调用，再验收论文连续追问。DAUHST `sc60` 五文件通过；产品内继续修订已接入，`sc61` 真实 HTTP 重放仅执行一次，正文四格式可用，但图示未通过且占用了主要额外调用。此前各任务首次失败继续保留，已有恢复记录不等于首次稳定完成，详见 [产品内修订与真实接口验收](CONTENT_REVISION_PRODUCT_20261003.md)。

## P2：修复影响所有场景的交互与运行问题

- 检查任务理解、输入完整性、模型参数与任务要求能否正确传到执行端，避免显示有选项而后端未使用。
- 验证多轮历史、固定材料前缀、已核验证据复用和按需补读。区分应用复用与供应商缓存；只报告实际观测，不承诺固定命中率。
- 检查长调用时的进度、流式响应、断线重连、取消及恢复；技术错误应明确呈现，不误报“原文没有证据”。
- 记录整条链路的阶段耗时、调用次数、输入输出 token、缓存返回值、修订次数和重复读取，用实际结果定位浪费；不重新引入累计 token 预算。
- 审视写作与核验的交互：保留成功部分，只修失败部分；区分事实/材料缺失与措辞/排版问题，修复误拒，不用降低事实要求换取通过。
- 跨运行内容修订已接入产品：创建关联原任务的新运行，保留旧结果，复用材料和已绑定检查；已有按格式重试继续单独处理渲染失败。后续验证更多输入及恢复情形，不忽略用户配置的修订次数。
- 图示生成应明确绑定其节点和关系所需的证据，避免为每一组简单关系重复发送全部材料；只修需要修订的部分，不能用放宽事实核验或随意删掉用户所需图示来减少调用。

## P3：按任务完善交付品质与容量

在场景能完成的基础上，分别检查综述的综合性、评审的可执行性、PPT 的可讲述性、导图的关系准确性及分析的可复核性。PDF/Word/HTML 应与定稿内容一致，引用、表格、公式和分页可用。内容正确性、任务适配和关键文字可读性仍属于前述场景的必要条件。

文档附件与资料库上传已在本地扩至 64 MiB，并以实际 18.9 MB PDF 检查 HTTP 输入、解析和原件读取；任务附件使用原始字节传输，避免 Base64 膨胀。表格分析入口仍为 16 MiB，其他解析资源边界仍有效；更大输入和生产代理容量待相应验收。跨页证据、复杂公式、超长表格和多文献布局按实际失败样本推进。仅有配色、间距或措辞偏好的调整排在阻断问题之后。

## 每轮产出与进度口径

- 在质量矩阵记录输入、代码版本、首次结果、恢复结果、可打开产物及剩余问题；保留失败，禁止用最终 pass 覆盖首次失败。
- 优先级按影响排列：无法提交/执行/取回结果、上下文错误、重要事实错误、必要交付缺失优先；非阻断显示问题随后处理。
- 不以“新增多少检查规则/测试/文档”作为项目主要进度。汇报哪些任务已实测可用、哪些失败、下一项能解除什么阻断。
