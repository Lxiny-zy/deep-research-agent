# 图示证据绑定与问答局部修订

更新：2026-10-03。本批本地修改；未推送、未部署。原任务、失败稿、原核验记录保留，恢复结果单独记录。

## 已定位的问题与修改

- `sc61` 正文局部修订仅需两次调用，配套图示却需要十四次调用，最终仍把一般深度学习方法的失配退化范围套给深度展开子类。旧图示的每个单元都收到全部来源，且生成阶段未明确收到已定稿正文。
- 新图示按图题/图注、节点、边分别绑定引用；边的引用须支持源节点、方向关系、目标节点的完整陈述，包括分组和公式。引用不能借用无关单元的证据。新生成图示固定使用 `scoped`，旧 `legacy` 图示保留原签名表示和原判断。
- 生成图示时提供研究问题及已定稿正文；局部修订只修改被拒单元，可纠正边的端点和引用、修订图注，不能增删结构、越权改写其他单元、使用未知引用或只改类型免检。未变化单元复用证据绑定检查。
- 真实恢复暴露“事实类型的主题标签被判为非事实”遭误当接口协议错误的问题。该分类冲突现在仍被拒绝，但作为内容问题交给写作者纠正，不以重复相同分类调用代替修订。缺失决定、非法证据映射、供应商异常仍按原规则处理；没有改变通过标准。
- 图示先核验原编号，再将可见引用映射为最终书目编号；投影不改变原图与绑定记录，保护公式及明确的数值区间。交付格式版本为 `45`。
- `sc63` 第二问正确理解“它”指代 β，但首稿增加了无支持的机制解释；整篇改写又产生对论文全文缺失实验的过度断言，最终只交付证据摘录。新问答优先复用已有段落修订机制，保留通过段落，修订后仍经过引用、数值和语义复核；供应商返回的思考事件沿原通道传递，局部替换完成时更新正文。

`sc66` 实际局部修订：核验拒绝了新增的“x^k 逐步变干净”机制链，修订请求仅 6,111 字符，模型只返回对应段落的替换文字，随后核验通过。末尾“需要针对该噪声类型重新定义退化模型并重新训练验证”被核验器作为条件性建议接受，但“必须重新训练”的必要性未获支持；下一轮要区分验证建议与必要性断言，并复用该草稿处理，不能用自动 pass 掩盖这一问题。

`sc65` 图示两次局部修订请求分别为 96,759 与 34,112 字符。第二次修订只补全被修改节点相邻边的必要引用；这些边因端点文字改变而重新核验，没有误复用旧判断。被拒图注涉及较多完整引文，不能仅凭局部编辑接口就声称请求都很小。

实际读取旧恢复样本：`sc60` 的 legacy 已通过图示仍通过；`sc61` 的 subtype 过度外推图示仍被拒绝。没有将旧失败记录升级为新格式通过。

已查看 sc65 原 PNG、PDF 第 2 页及全 11 页缩略图；DOCX ZIP 完整且含图。图注引用已映射为书目编号，报告正文与原 257 条发现字节/结构比较不变。文件能打开，但图示的多条长连线共用路径、关系标签拥挤，且最后一页仅少量参考文献续行，尚不满足目标版式品质。这些问题应使用保留的已核验内容改善确定性排版，无需重新调用模型抽取或写作。

主要剩余问题是连续追问对缺失细节的补读收敛、更多输入的首次完成稳定性、图示的内容与版式质量、书目信息及文体。用户继续负责浏览器验收；这批核心链路与文件验收不代替新的产品 HTTP/浏览器验证。
