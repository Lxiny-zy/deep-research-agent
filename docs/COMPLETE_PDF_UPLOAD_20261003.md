为验证新的完整精读任务，从 arXiv 取得 DAUHST 原版论文 *Degradation-Aware Unfolding Half-Shuffle Transformer for Spectral Compressive Imaging*，地址 `https://arxiv.org/pdf/2205.10102`。PDF 共 13 页、18,925,455 字节，超过原来的 16 MiB 附件限制；没有压缩图片、删页或换成节选来绕过。

## 上传链路修改

- 任务附件与资料库文档的单文件上限统一为 64 MiB，Base64 兼容接口按实际编码长度设置校验上限；前端大小判断和提示同步。数据分析表格入口仍有独立的 16 MiB 限制。
- 新增 `POST /api/attachments/file?filename=...`，浏览器直接发送 File 原始字节。接口增量读取，先检查声明大小，再检查实际收到的每一块，超过限制返回 413，不进入解析或保存。保留原 JSON 接口与相同的研究员权限边界。
- 附件解析直接把 bytes 交给资料解析器，取消内部再做一次 Base64 编码/解码。前端串行处理多文件，区分等待上传与正在处理；移除排队文件会跳过，移除当前文件或离开页面会取消客户端请求。
- PDF 原件按既有内容哈希保存、读取时校验；重复文件复用同一存储。完整文本容量、页数、来源访问规则和磁盘配额继续执行，不静默裁剪。
- Nginx 示例补齐 96 MiB 请求体限制，兼容原始文件和 Base64 包装；实际生产代理配置需在获授权部署时检查，本轮未修改远程配置。上传及资料导入客户端允许两分钟完成请求。

## 实际验证

原 DAUHST 文件经本地 ASGI HTTP 接口得到 201，解析出 51,066 字符、19 个片段，覆盖到第 13 页；原文件取回与上传内容逐字节一致，未截断。此次本机 HTTP/解析/保存约 0.45 秒，整进程峰值工作集约 229 MiB；这不是公网延迟或任意 64 MiB 输入的性能保证。证据在 `artifacts/sc55-upload/acceptance.json` 与 `attachment.json`。

自动回归验证原始字节/旧接口的解析一致性、超过旧限制的 PDF 原件保存、声明超限与未知长度流超限在解析前被拒、只读身份不能上传；前端验证直接发送 File、容量判断、串行队列与移除排队项。

后端完整 **2,132 项通过**，覆盖率 89.56%；前端完整 **393 项通过**，后续队列状态调整的 28 项定向检查通过。Ruff、格式、Mypy（196 个源码文件）、ESLint 与 OpenAPI 一致性通过；生产构建通过。日志 `artifacts/regression-sc55.log`、`frontend-sc55.log`、`frontend-build-sc55.log`。16 项 PostgreSQL 仍沿用本地迁移至 0037 后的已通过记录，本轮没有数据库变更。
