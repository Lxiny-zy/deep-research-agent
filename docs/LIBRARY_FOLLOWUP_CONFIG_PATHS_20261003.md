# 资料库、研究追问与配置联动

更新：2026-10-03。本批继续优先打通任务通路，尚未推送或部署。

## 修复追问丢失资料库

原“继续追问”只保存问题历史并跳转 `/?followup=1`，新任务草稿的资料库项目为空，导致原来绑定私有资料库的研究在下一轮默认失去这部分来源。

现在从任务详情携带原 `project_id`，追问编辑器将它作为初始资料库选择。草稿上下文同时包含该项目，避免不同资料库的追问草稿混用；已保存的当前草稿仍保留用户修改。用户可以显式更换或清空资料库。项目已不可用时显示对应选项，并在提交前提示重新选择，不悄悄改为不用资料库。切换追问 URL 的项目时重新初始化编辑器。服务端仍按当前身份验证项目访问权限。

同步补齐前端 `RunDetail.project_id` 类型；后端已有该字段，本批未改变接口结构。前端测试覆盖原项目传递、创建请求携带该项目、不可用项目显式清空及既有流程。

## 资料库到实际研究和问答

`tests/test_library_task_paths.py` 使用公开 HTTP 创建项目、导入 Markdown、排除另一来源，再分别执行自动研究、综述、幻灯片和导图，以及带历史的后续研究和“仅资料库”问答。inline 与 worker 两种模式共八项通过。

执行器、队列领取、SQLite、资料库检索、证据核验绑定和文件生成均实际运行；只有模型与公网搜索返回固定响应。公网搜索无结果，报告引用必须指向纳入的资料库来源，排除的来源不得进入模型输入。仅资料库问答不得触发公网搜索。结果页的公开详情包含原项目标识，后续任务继续使用相同项目。

这证明来源与任务之间的连接，不是模型事实准确率、真实检索召回或用户浏览器验收。

## 配置到任务执行

`tests/test_catalog_task_paths.py` 从 HTTP 创建默认模型档案、研究角色专属模型、检索档案和角色卡片，保存全局设置，再提交任务直至四种报告格式可取回。inline / worker 两项通过。

测试观察到实际被调用的默认模型和专属模型、角色提示词、上下文容量、输出容量、温度、请求超时、并发参数及检索档案均与提交时配置一致。worker 领取任务前修改模型、角色提示词及全局配置，已排队任务仍保持创建时的行为快照；凭据不进入任务公开响应或 checkpoint。模型与搜索客户端使用测试替身，没有调用真实服务。

## 真实模型 HTTP 验收

新增 `scripts/accept_library_http_live.py`：只读使用此前授权的阿里云模型配置，本地通过 ASGI HTTP 导入真实项目记录、提交资料库研究、下载并核对各文件哈希，再发起资料库流式问答。SQLite 与输出均本地保存，凭据仅在内存；公网搜索关闭，不把该测试称为公网召回验收。

sc76 因验收脚本的运行设置未携带凭据，在发出模型请求前停止；数据库和失败记录保留，不计场景成功。修正后 sc77 已启动，来源为已有的通路验收和来源阅读记录。截至本批代码归档仍在运行，已保存前三次模型响应，第四次调用持续返回流式内容；尚未完成报告下载和后续问答，不计真实场景成功。日志 `artifacts/sc77.log`，SQLite 和响应记录位于 `artifacts/sc77/`；后续先确认原进程状态，不因观察中断重新发起任务。
