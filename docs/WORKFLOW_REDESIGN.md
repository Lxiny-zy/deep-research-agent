# 工作流重构说明

当前工作台将底层 Agent、研究步骤和交付验收统一投影为八个产品阶段：任务理解、证据准备、要求覆盖、正文生成、内容核验、定向修订、格式生成、交付验收。

阶段状态由运行 checkpoint、正文版本、证据结果和交付门派生，不另建一套会漂移的状态真源。每个问题同时带有下一步动作类型：补充检索、补读原文、修订正文、重试格式、处理安全问题或继续核验。前端只消费这份阶段状态，不再通过猜测 Agent 名称判断用户下一步该做什么。

旧任务没有阶段记录时，后端按已有结果、正文、验收门和交付记录即时推导；新任务在交付完成时持久化同一结构。这样不会破坏旧 checkpoint，也让恢复、内容修订和格式重试能够显示一致的任务进度。

阶段状态不是安全放行机制。引用越界、无依据数值、来源快照冲突、文件损坏和权限问题继续由原有硬门阻断；阶段状态只负责把可修复问题送回正确环节，避免所有问题都汇总成“报告未通过”。
