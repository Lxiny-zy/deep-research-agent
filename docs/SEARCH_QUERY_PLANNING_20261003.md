# 完整研究问题与实际检索式分离

日期：2026-10-03。接续 `e5bd763`，仅本地实现、验证；没有推送、部署或迁移生产数据库。

## 实际问题与修改

自动研究首次真实任务把数百字的研究子问题直接发送给 arXiv/OpenAlex，其中两个查询返回空结果。完整研究问题应指导证据收集与回答，但通常不是适合搜索索引的查询。

本地实现现在区分两者：

- `SubQuestion.question` 保留完整研究目标；新增 `search_queries` 保存简洁、互补的检索式。规划在同一次模型调用中生成两者，不为每个子问题再增加一次模型调用。
- 提示词要求保留明确的年份、地域、对象和任务范围；国际学术主题优先使用通行英文术语，地域性事务与中文专名保留适当原名。不同具名方法需要分别查找时使用不同查询，不把所有条件挤进一个长字符串。
- 执行器按去重后的检索式查询，按来源 URL 保留一致的内容快照；某一查询失败不会丢弃其他查询的结果。证据抽取仍接收完整问题和前驱发现，不用短关键词替代研究目标。旧计划缺少检索式时沿用原问题，不额外调用规划模型。
- DAG 调度、JSON checkpoint 恢复、反思新增问题均传递检索式。数据库的计划写入、反思追加、原子替换与读取也保留该字段，避免重开任务后丢失。

新增迁移 **0037**，为 `sub_question` 增加 JSON 检索式列。旧记录默认空列表，原问题不变；升级兼容已经通过 `create_all` 创建完整列的本地库。仅执行了临时本地 SQLite 的升级、回退和结构检查，生产数据库仍为 0036。
