## 3. 验收标准

### 3.1 所有场景共用的最终质量门

- 结论能回到已读取的原文、数据或用户材料，引用编号、具体依据和来源文件一致；关键主张无依据时
  明确说明，不补写成事实。
- 用户要求的主题、章节、比较对象、数据范围和交付格式都有覆盖；材料缺失与模型遗漏要区分。
- 正文、表格、图、公式、书目和导出文件使用同一份定稿快照；承诺的 PDF、Word、HTML、PPTX、XLSX
  等格式可打开且内容一致。
- 表格数据由代码从已核验的发现渲染，模型只写叙述；缺失值写“未报告”。
- 确定性检查与模型复核都通过；涉及统计、数值、公式、实验条件和比较关系时，执行专门的一致性校验。
- 失败后恢复不重复已成功的昂贵步骤，不丢失已核验证据、用户配置、输入范围或历史上下文。

### 3.2 各场景要求

| 场景 | 代表输入 | 必须交付 | 质量通过标准 |
| --- | --- | --- | --- |
| 自动研究与资料库研究 | 范围明确的研究问题；指定资料库 | 实际检索和来源读取、支持结论的证据、回答问题的报告 | 新问题首次运行形成完整报告；每项核心结论有充分来源；检索或读取失败明确暴露；恢复后不重复已完成子问题 |
| 文献综述 | 指定多篇文献；另测开放检索 | 跨文献主题综合、比较条件、结论与局限，不能用证据摘录清单代替 | 主题覆盖与用户范围一致；主要观点有多篇文献支撑；冲突结论分别呈现；公式、行内引用和书目可用 |
| 论文精读 | 一篇未用于修复的完整论文 | 完整摘要处理、核心方法、关键结果与适用条件、有效原文引用 | 方法、实验设置、主要结果和适用边界都能定位到原文；不把局部片段写成全文结论 |
| 学术问答与精读追问 | 同一会话多轮，含指代、比较和新问题 | 正确保留上下文，正文和思考内容持续呈现，复用已有材料，引用能定位 | 连续多轮上下文正确；新增读取范围可解释；回答简洁，每项引用可定位；无依据时拒答 |
| 同行评审 | 一篇完整论文和明确的评价维度 | 与原文对应的贡献、优缺点和可执行修改建议，评分理由一致 | 贡献、优点、缺点、评分和建议彼此一致；每项事实性批评能回到论文；区分关键缺陷、一般问题和表达建议 |
| 数据分析 | 有说明的真实或公开数据，含缺失或异常 | 与数据相符的方法、可复核的统计、图表和解释，可打开的数据与报告文件 | 统计量可独立复算；总体与分组口径不混淆；方法满足数据前提；XLSX 保留原始范围、样本构成和未分析字段 |
| 汇报幻灯片 | 已有材料、目标听众、汇报时长 | 可打开的 PPTX、合理的内容密度、准确图表和讲稿备注 | 每页承担明确的叙事功能；关键图表与原数据一致；讲稿能支撑目标时长 |
| 思维导图 | 多份材料和指定主题 | 可交互、可导出的文件，正确的概念层级与关系 | 表达关系而非堆积事实；节点无明显重复；标签可读；HTML、PNG、Markdown 一致且可导航 |
| 来源阅读与 PDF 定位 | 回答或报告中的引用 | 选中依据后在原文中定位 | 选中具体依据前不显示旧定位；唯一完整引文准确定位；不能可靠定位时明确失败，不猜测 |

### 3.3 计数口径

- 质量矩阵记录输入、代码版本、首次结果、恢复结果、可打开的产物和剩余问题；恢复成功不覆盖首次失败。
- 只有经产品路径（HTTP API 或界面）完成、按新完成契约进入 done、并通过独立复核的样本，才算该场景可用。
- 优先级按影响排序：无法提交、执行或取回结果 → 上下文错误 → 重要事实错误 → 必要交付缺失 → 显示问题。
- 汇报进度时说明哪些任务实测可用、哪些失败、下一步解除什么阻断；不以新增检查、测试或文档的数量作为进度。
