## 接下来：用户线上人工验收

优先新建任务检验首次交付，再单独检查停止、恢复、追问及重新导出。历史修复样本不能替代新版新输入。
结果登记到任务页人工验收记录，必要时使用 [验收模板](N0_ACCEPTANCE_RECORD_TEMPLATE.md)，
并同步 [质量矩阵](REAL_TASK_QUALITY_MATRIX.md)。可以逐场景验收，无需一次完成全部场景。

| 验收方向 | 必须核对的用户结果 |
| --- | --- |
| 课题与资料库研究 | 主题和要求完整，结论有已读取的依据，来源失败明确暴露；报告和后续问答分别记录 |
| 文献综述 | 跨文献综合成立，比较条件一致，冲突和局限保留，不用短摘录缺失推断全文或领域缺失 |
| 同行评审 | 原文、批评、严重度、评分和修改建议一致，关键方法材料不足时说明限制 |
| 论文精读与追问 | 公式符号、图轴、子图、实验条件和适用边界正确，跨页证据可回查，改口和指代不丢失 |
| 数据分析 | 分析单位和设计正确，统计值可复算，样本构成、单位、排除原因与 XLSX 一致；不强行推断不支持的设计 |
| 幻灯片 | 在常用 PowerPoint/WPS 打开并编辑文本、公式和原生图表；检查投影可读性、分页、讲稿和目标时长 |
| 思维导图 | 总览易懂，展开含义完整，分支图可读，跨分支方向和索引可理解，引用与版本一致 |
| 共同交互 | 桌面/手机无覆盖，思考和对话状态真实，引用定位可操作，旧文件保持原字节，停止恢复无重复工作 |

必须同时保留应用版本、输入标识、任务/请求 ID、文档版本、首次结果、恢复结果、问题位置与原文/数据依据。
不能用平均分抵消错误证据、方向/单位/公式错误、错误实验设计、跨用户/版本混用或核心文件损坏。

## 保留的能力与验证边界

- 最大输出 token 是单次模型调用的输出上限，不是整轮所有生成、核验和修订的总和。
  实际 HTTP 尝试、流事件、解析和渲染重试分别计量；未知提供方计量不补零。
- 上下文超限先按预算选择完整证据并保护带来源记忆和最新约束；必要指令及最小证据仍容不下时明确停止。
  用户主动继续受新请求预算约束，并继承已消耗的自动修订额度；不重发计费状态未知的调用。
- 本次 1 GiB 容量证据峰值为 821.5 MiB，验证真实渲染子进程串行执行和回收；不包含同时真实模型负载或 PPT 并发。
- LibreOffice 7.4 未显示 PPT DrawingML 数学扩展；WPS 实际导出样本公式可见，但多文档 COM 清理出现过 RPC 错误。
  这些证据不能证明所有 Office 软件版本或自动化流程兼容。
- 可编辑原生图表限表格、柱状图和折线图。来源图片只能移动/缩放，不从截图猜测数据重绘。
- 产品面向研究、综述、评审和精读报告，不承诺期刊投稿、匿名审稿或 camera-ready 出版工作流。
