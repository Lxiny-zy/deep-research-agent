## 已修复的问题

### 一致性检查过度思考及相同输入重复调用

`ClaimConsistencyReport` 那次失败耗时 113.6 秒，思考消耗 19,201 token，最终因 `ModelOutputTruncated` 失败。该入口遗漏了其他常规核验已有的 `verification_generation_options`。

已接入同一请求级低推理策略：仅在模型档案支持时使用，不修改共享模型设置或输出容量。另为同一核验器、同一模型实例、同一提示与证据输入保存最近一次成功响应，避免重复调用。输入变化或前次失败仍会重新判断；来源独立性等确定性检查仍基于当前发现执行。

### 来源快照冲突阻断整篇自动修订

真实写作检查点显示，初始修订预算为 2，但第一稿即被标记 `can_revise=False`。原因包括：

> 全文核查未完成：ValueError: 文献存在不一致的来源快照，不能混用版本核查

后续“交付前自动修订”再次检查同一草稿，仍不允许写作者改稿。这是用户感受到“核验之后还是核验”的直接原因。

已将来源快照冲突表示为明确的证据限制，结论保持 `uncertain`，禁止混用版本证明断言；同时允许写作者删除依赖该证据的断言，或改为明确来源能支持的说法。真正的核验服务超时等故障仍停止无效重写。

### 任务页误导与噪声

- 模型请求记录保留 `schema`，区分摘录核验、正文引用、跨来源印证、全文回查、公式和覆盖范围检查。
- 有活动请求时，在折叠历史外显示当前具体步骤；运行结束后不显示“等待响应”。
- 将终稿检查已有的分段、分批进度接入任务事件，避免长时间只显示同一条笼统提示。
- 已结束但需复核的任务不再显示绿色“99%”进度条；保留结束状态、实际耗时和质量结论。
- 顶部问题列表去重，默认显示 3 项，其余可展开。该真实任务显示 3 项加 27 项可展开内容。
- 验收面板和交付面板使用不同的 React key，消除真实任务页的重复 key 警告。
