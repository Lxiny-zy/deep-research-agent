# 工作台任务调用与修订优化

日期：2026-10-10。

**本轮已修改业务代码，完成了重复返工、局部修订、全文目标判定、数据报告回退和调用额度方面的优化。** 这份文档记录实际实现；[此前的审查报告](scenario-overcall-review-20261009.md)保留优化前的证据。

改动基于现有工作区及其未提交内容，当前 Git HEAD 为 `ed97c2772fac0e9540541cd4398ad27e5f193e56`。本次完成的是本地代码优化与验证，没有部署服务或操作实验室服务器。

## 已落实的改动

### 1. 修订能够提前停止，并共用自动修订额度

[`write_with_revisions`](../deep_research/workbench/revision.py#L247)现在记录实际使用的修订次数、上限和停止原因。连续两版出现相同的问题集合时停止追加修订；失败的编辑尝试也计入额度，已有较好草稿继续保留。

写作循环与[交付前修复](../deep_research/workbench/completion_repair.py#L44)共用 `max_revisions`。设为零时不会再通过交付阶段额外生成正文；已无改善或编辑失败的内容也不会被另一层流程重新发起自动修订。

进度会保存修订用量和停止原因。恢复时复用已保存的草稿，不重新开始一个相同的无效循环。首稿仍按原有顺序生成、保存，不新增没有草稿内容的空进度写入。

### 2. 按段落和页面修订

通用报告的局部编辑失败后保留已有正文及待处理问题，取消随后自动整篇重写的分支。执行权丢失、进度写入失败等异常仍按原有边界停止。

新增 [`slide_edit.py`](../deep_research/workbench/slide_edit.py#L80)：根据核验位置确定出错页面，只提交这些页面的标题、要点、讲稿和引用进行修订。页码遗漏、重复或越界会被拒绝；其他页面、图表和图片绑定保持完整。涉及整体结构的问题仍由原有结构检查处理。

数据分析报告也接入了局部段落编辑。数字问题能够定位时只修订相关段落，编辑失败不会再启动另一份完整正文。

### 3. 合批判定全文核验目标

[`FullTextReviewer.prepare`](../deep_research/workbench/fulltext_review.py#L269)按模型容量合并多个单元的目标判定。每项仍使用自己的文献目录，不能借用其他项的来源。

返回结果中某一项缺失或重复时，只标记受影响的项，保留其他有效结果；不会把一次批量失败展开成多次单独重试。相同正文、来源及核验记录继续复用缓存。

全篇缺失判断仍检查所评价文献的完整覆盖范围；公式结构、原文引句和引用支持关系的约束继续生效。

### 4. 重复观测不再无条件覆盖描述性报告

[`DataAnalyst`](../deep_research/workbench/analysis.py)仍识别重复观测，并限制当前统计引擎不支持的推断检验。合格的描述统计正文现在可以保留，必要的限制说明由代码在首次评估前加入。

这消除了“统计阶段已知限制 → 生成和核验正文 → 无条件丢弃正文”的路径。数字或结构确实无法通过检查时，仍可交付确定性的统计摘要。

### 5. 独立段落错误不再必然替换整份报告

公共[终稿检查](../deep_research/report/validation.py#L308)增加 `preserve_valid`，工作台的报告写作者启用这一选项。能够定位的引用、数字错误会移除对应段落，再检查保留内容；全局或无法定位的问题继续使用素材摘要。

保留后的正文继续进行支持关系核验，可复用未变化的单元。交付记录保留“部分完成”标记和未获批准的原稿，避免省略段落后被误标为完整通过。结构化幻灯片、导图及默认兼容入口仍使用各自的交付规则。

### 6. 增加任务强度与请求额度配置

交付质量设置由现有的 schema 接口和设置页展示，新增两个配置项：

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| `adaptive_review` | `true` | 新建的轻量或快速任务最多自动修订一次；精读和审稿保持设定的完整额度。关闭后沿用统一额度。`max_revisions=0` 始终有效。 |
| `task_max_model_calls` | `0` | 已创建任务内的模型请求总额度，包含原生模型角色、模型检索和 HTTP 重试。零表示不限，正数表示启用上限。 |

[`TaskCallBudget`](../deep_research/task_call_budget.py)在请求发送前持久化额度预留，并在并发角色之间串行更新。恢复后继续累计，取消时也会等待正在进行的额度写入完成，防止后续写入覆盖计数。记录损坏或额度用尽时停止追加请求。

额度预留后发生取消或崩溃时，可能占用一个尚未发送请求的名额；这是保证恢复后不突破上限的处理方式。默认不为不同大小的研究任务猜测统一请求上限。

外部注入的模型副本会绑定当前运行的追踪器及额度，同时保留原客户端；模型事件附带额度与用量。普通问答和论文追问继续使用原有 direct / verified 模式及更紧的单轮额度。

文本生成和[模型型检索](../deep_research/tools/model_search.py)的两个原生请求入口均采用同一异步额度接口。已验证 Responses、chat_search 协议与回答共享额度，检索密钥切换也不能绕过上限。

旧任务没有声明的新自适应选项不会追溯改变其修订上限。[写作进度标识](../deep_research/workbench/writing_progress.py#L231)也兼容旧的冻结质量配置，避免新增默认字段导致重复生成已付费的草稿。

## 已验证的效果

以下是受控离线用例的调用边界，表示逻辑调用或生成次数，不是线上耗时、费用估算。六条建议的用例可以容纳在同一批上下文中。

| 用例 | 优化前 | 优化后 |
| --- | --- | --- |
| 相同问题连续没有改善 | 三次写作 | 两次后停止，恢复不重启循环 |
| 六条纯建议的全文目标判定与支持检查 | 七次模型逻辑调用 | 两次；相同内容再次检查新增零次 |
| 局部编辑失败 | 两次完整正文生成 | 一次完整正文生成，保留待处理问题 |
| 零次自动修订 | 交付前仍可能第二次生成 | 保持一次生成 |
| 重复观测的合格描述报告 | 生成后被统计摘要覆盖 | 保留正文并附上必要限制 |
| 一处坏引用，其他章节合格 | 整份正文回退 | 保留合格章节，并维持部分完成状态 |

新回归集中在：

- [场景效率与恢复](../tests/test_scenario_efficiency.py)：修订收敛、旧进度复用、合批判定、按页编辑和部分交付。
- [数据分析效率](../tests/test_analysis_efficiency.py)：重复观测、局部数字修订和编辑失败处理。
- [任务调用额度](../tests/test_task_call_budget.py)：并发、重试、取消、恢复、注入模型及运行入口配置。

选定 **806 个不同用例**，完成分组执行及失败项复测，目前没有未解决的测试失败。覆盖写作与恢复、引用和公式、统计分析、幻灯片、导图、论文阅读、默认问答、模型检索、图工作流和实际交付。Ruff 通过；mypy 检查 **277 个后端源文件**通过；`git diff --check` 通过。

三项 Windows 导出检查在较长临时路径下遇到路径长度限制，改用独立短目录后通过。旧问答用例分别明确了严格核验模式和默认直接回答语义；默认场景另验证了不会额外调用规划或核验模型。

模型和检索使用替身，数据分析的部分路由测试使用受控核验器；这些结果验证调度、调用边界和交付约束，不证明真实渠道的语义质量、延迟或费用。PostgreSQL 专项测试不在本次选定范围内。
