## 调用额度与任务归属

新增 `_task_model_call_scope`，在任务创建时保存标识。编排器也会为调用方自带存储的任务保存该标识；工作流的固定 ID 可用于恢复首次检查点保存前的请求额度。正常带 `run_id` 的任务继续以运行 ID 绑定计数。

损坏的标识会在发起模型请求前被拒绝。对于旧代码留下的“随机 UUID 未写入检查点”的记录，若无法找到与原任务绑定的计数文件，会停止新增请求并说明原因。这些记录无法从散列反推出原始归属，因此不会自动授予一份新额度，也没有擅自迁移旧计数文件。

检索客户端通过 `for_tracer()` 创建请求包装器。上下文随异步调用传递，原生检索、复合检索及密钥池均使用当前任务的 tracer；底层连接与客户端资源仍按原来的所有者关闭。密钥池的客户端属性访问也保留，冻结档案恢复测试已通过。

回归覆盖了两个任务并发使用同一个客户端、各自额度耗尽、原始客户端用量不被修改、自定义与自动创建的存储、不同编排模式、首次检查点前中断，以及旧标识缺失与损坏。

## 幻灯片结构修订

结构检查现在返回带页码的 `SlideQualityIssue`。缺讲稿、重复讲稿和标题过长等问题能进入对应页面的编辑请求。检查同时处理自动封面带来的页码偏移，防止修改相邻页面。

需要减少整体页数的问题进入受 `max_revisions` 限制的整稿结构修订。页面编辑失败时保留已有稿件；零修订额度不会启动编辑。新增测试通过真实的写作者入口验证了这些行为。

已复现案例的变化：原来只有初稿请求，却记录一次失败修订；现在执行 **一次初稿生成和一次页面编辑**，缺讲稿问题得到修复，其余页面保留。

## 配套图示收敛与恢复

配图流程增加内容指纹和问题签名，遇到重复图示或没有改善的问题时停止。若后续版本更差，选择问题较少的版本，并保存与该版本匹配的核验记录；持续改善的版本仍可继续修订。

修订名额在调用编辑器前保存，失败或中断的编辑也计入额度。停止原因、完成状态、选定版本和用量写入写作进度，恢复时不重新执行已完成的修订。

相同错误图示的离线案例由 **5 次整图生成降为 2 次**。这是逻辑模型调用数；HTTP 重试仍由任务请求额度约束。未通过核验的图示仍保留失败状态。
