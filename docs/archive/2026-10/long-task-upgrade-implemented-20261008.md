# 长任务完成体验：已实施升级

2026-10-08。本轮已完成代码实现、回归和浏览器验收，**已作为应用版本 `eb033b1` 部署到 Aliyun**。发布与备份信息见 [部署结果](deployment-and-next-steps-20261008.md)。线上角色卡片、模型档案和历史任务记录保持不变。

## 已落地

### 1. 表格核验合批与局部复用

- 表格核验从逐格新建核验器、串行调用，改为批量处理多个单元。
- 每格携带独立的 `allowed_evidence_ids`，即使两格使用相同引用编号，也不能借用对方证据。
- 返回结果仍检查单元编号、证据范围和原文支持关系；格式错误只进行有上限的协议修复。
- 为每格保存与内容、证据快照、核验提示和模型标识绑定的判断，修订时复用未变化的单元。
- 保留已有整表签名检查，并显示单元数、复用数和请求数。

回归场景：18 个单元由 18 次请求减少为 **2 次**；其中一格来源快照变化时，仅新增 **1 次**请求，复用其余 **17 格**。这是受控测试结果，不代表整条真实任务会提速九倍。

### 2. 依赖满足即可调度

- 取消研究 DAG 的整层等待；后续分支的直接依赖满足后即可启动。
- 仍保留前驱发现传递、稳定的返回顺序、调用方并发约束和渠道限流。
- 普通来源失败可结算为缺失，后续分支继续尽力处理；租约丢失等执行权限错误会停止并清理其他任务。
- 依赖图仍保留层次信息供界面显示，实际执行策略标为 `ready`。

回归证明：快分支的后续工作可以在无关慢分支结束前开始；丢失租约后不会新开后继任务。

### 3. 统一请求级推理策略

- 在 LLM 结构化请求入口按已知输出契约选择操作类型，避免每个调用点必须自行记得降低常规核验的推理强度。
- 普通抽取、支持关系、一致性、覆盖检查和全文定位使用低推理配置，前提是档案声明支持推理参数。
- 研究规划、复杂公式保留档案配置；调用方明确指定的推理强度优先；未知操作不猜测。
- 不修改共享模型实例，不擅自更换模型或增大输出上限。
- 模型请求记录增加操作类型、实际推理强度和配置来源。

本轮实现的是按操作选择推理配置、按角色绑定实际模型。尚未实现基于质量或延迟自动切换供应商的多模型策略。

### 4. 排队状态与执行耗时分开

- 记录模型名额等待、取得名额和排队取消状态。
- 渠道排队耗时与实际模型请求执行耗时分别记录。
- 排队时显示当前操作；排队取消不计为一次实际 HTTP 调用。
- 请求记录展示输入、输出、思考 token 和实际推理强度。
- 修复任务页未传递实时运行标记的问题，使活动请求与排队提示在真实长任务页面生效。

### 5. 科研角色卡片可以直接配置并参与任务

- 新增课题调研、综述、精读、审稿、幻灯片、思维导图六类专用写作者行为。
- 专用卡片继续使用原有科研执行器，保留模板结构、证据检查、修订和交付流程。
- 在内置角色区域增加“配置提示词与模型”入口，自动填写并锁定正确的角色标识和行为，避免创建后没有绑定。
- 角色卡显示是否绑定同名内置角色；独立卡片明确提示需要在工作流中引用。
- 明确提示修改只影响新任务，已经开始的任务使用原有冻结配置。
- 任务页增加“本次角色与模型配置”，展示实际解析的卡片、档案、模型和默认回退来源。

完整任务回归验证：同名专用写作者卡片的领域指令及绑定模型进入真实工作流执行路径，同时保留科研模板与交付登记。测试使用模拟模型，不调用线上模型。
