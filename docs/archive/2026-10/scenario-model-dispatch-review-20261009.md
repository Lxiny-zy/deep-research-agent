# 场景调度与模型参数审查（2026-10-09）

> 后续线上使用发现，第一轮优化仍保留了默认多阶段核验，普通追问实际产生 16 次请求。本文件记录第一轮检查；新的默认直接问答方案及验证见 [普通问答改造](qa-direct-routing-fix-20261009.md)。下述核验链路现在仅在用户显式选择严格核验时使用。

## 结论

“论文精读 → 对照原文提问”实际走独立问答接口：`ReaderPage → runQaRequest → qa_api → qa_jobs → answer_question`。`qa_jobs` 负责排队、取消、幂等与恢复；它不创建研究运行，也不执行研究工作流。

问题主要在问答内部和公共模型调用层：已有证据重复核验、首次补读默认扩大范围、无关模型提前加载，以及把文件执行和工作流规则传给只负责内容的模型。此次已修正这些问题，同时保留逐字引文检查、事实支持核验、显式来源范围和恢复校验。

## 场景与执行边界

| 场景 | 合理的主链路 | 本次检查与调整 |
| --- | --- | --- |
| 普通学术问答，不选来源 | 对话上下文 → 回答模型 | 短对话一次作答；不初始化检索规划、抽取和核验模型。长历史仍可按容量生成摘要。 |
| 论文内追问 | 冻结原文/历史发现 → 必要补读 → 回答 → 引用支持核验 | 按当前来源、模型和规则复用核验证据；长篇多来源材料无候选时先定向选择章节；不启动研究规划或反思。 |
| 已完成研究任务的追问 | 任务的多个原始来源 → 必要补读 → 回答 → 核验 | 保留多来源归属，不把研究报告或历史回答冒充论文原文。 |
| 问答勾选联网/资料库 | 一次检索式规划 → 所选来源检索 → 抽取/核验 → 回答 | 仅此类问答需要检索规划角色；资料库与联网保持显式选择。 |
| 课题调研 | 附件 → 子问题规划 → 检索/抽取 → 写作 | 快速模式一轮检索；深度模式保留有界反思补洞。 |
| 文献综述 | 检索或提供材料 → 证据 → 综述写作/质量检查 | 深度、快速、仅提供材料三条路径保留；仅提供材料不再抽取没有下游用途的检索实体。 |
| 论文精读报告 | 附件/指定论文导入 → 证据 → 精读写作 | 生成精读报告是多步骤任务；后续提问复用原文，不重建报告任务。 |
| 同行评审 | 指定材料 → 证据与覆盖检查 → 审稿意见 | 保留审稿所需核验，移除无用途的检索实体抽取。 |
| 数据分析 | 数据/附件 → 分析范围 → 程序计算 → 解释与交付 | 数值继续由程序计算；模型只解释统计台账，不接收文件执行流程指令。 |
| 幻灯片、思维导图 | 快速/深度检索或提供材料 → 对应写作者 → 核验/导出 | 三类输入策略分别执行；结构化生成使用各自内容契约。 |
| 修订、恢复、重新导出 | 保存的阶段材料 → 所需修订/恢复/渲染 | 保留已有机制；问答恢复不重新检索，导出不凭空增加模型调用。 |
| 用户选择的自定义编排 | 协调器/显式计划 → 工作流引擎 | 这类请求需要编排能力，执行器的全局规则继续保留。 |

## 已修正的问题

1. **意图预处理绕过角色模型绑定。** 创建任务前的意图识别原来直接构造全局 `LLM(settings)`，与工作流内的 `intent_router` 解析方式不一致。现在按意图角色或目录默认档案加载，保留参数模式、温度、推理强度、容量与调用角色；无需加载其他角色和检索档案。

2. **问答无条件加载四类模型。** 问答的运行环境指纹此前会解析规划、抽取、回答、核验全部角色，普通问答还会构造未使用的研究员。现在根据实际来源范围选择模型集合；只有角色档案、没有环境默认密钥的普通问答也能使用其已配置模型。

3. **每个新问题重新核验同一批证据。** 当前运行内产生的证据池已按来源、模型和规则隔离，却仍被送去整批语义复核。现在直接复用该证据池；历史报告的发现经过当前规则准入后也会缓存。缓存包含来源内容和元数据、模型及参数、凭据摘要、提示约束、核验规则与来源范围，发生变化时重新准入。

4. **无候选证据等同于全篇扫描。** 紧凑材料可一次完整读取时直接抽取，省去额外选择调用；长篇多来源材料先根据问题和章节目录选择补读目标。只有一个来源时直接按容量定位相关节选，不花一次模型调用重复选择唯一目标；节选仍明确标注未覆盖全部原文。已读完且没有可用证据时直接保留缺口，不再付费做无意义的选择。

5. **内容模型收到执行器规则。** 论文抽取、证据选择、子问题规划、反思、报告写作、评审、数据解释及幻灯片/思维导图生成改为接收共享事实约束与当前内容契约。租约、文件写入、checkpoint 和任务完成状态由程序负责。用户补充约束与角色卡片内容继续保留，角色编辑器的最终提示词预览同步更新。

6. **模型档案丢失当前运行设置。** `LLM.from_params` 原先重新调用 `Settings()`，可能把当前运行的输入容量等配置换回环境默认值。现在从调用方的运行设置派生，仅覆盖档案声明的模型字段。连通性测试也使用档案实际温度。

7. **重复探测不支持的流式参数。** 不支持 `stream_options` 的渠道此前每次调用都会先失败再重试。现在在当前模型客户端及其角色副本之间复用已确认的协议能力，后续调用直接使用兼容参数。

8. **惰性模型暴露错误的参数元数据。** 惰性代理继承的默认温度和推理强度可能遮住实际模型配置。现在转发真实档案值，避免缓存及恢复指纹使用错误参数。

9. **固定材料任务抽取无用途的规划实体。** 论文精读、同行评审、数据分析及仅用提供材料的任务仍会为检索规划补抽实体。现在这些路径跳过该调用，意图门禁仍然执行；需要开放检索的任务保留实体抽取。

10. **资料库叠加结果被忽略。** 不经过来源记录器的直接 `RunContext` 中，叠加检索对象构造后没有返回。现在返回合并后的检索对象；存在来源记录器时继续通过记录器保存来源。

11. **引文长度约束不一致。** 附件和论文导入现在在构造研究员时传入当前质量配置；批次容量按实际抽取提示词计算。删除“引文不受固定字符数限制”与运行时长度上限相互矛盾的指令。

## 模型参数规则

| 参数/任务 | 当前行为 |
| --- | --- |
| 温度模式 | 发送 `temperature`；档案显式温度优先于调用点的默认采样建议。 |
| 推理模式 | 发送 `reasoning_effort`，不同时发送 `temperature`。 |
| 常规意图、检索式、证据选择、摘要、格式分类与核验 | 对声明为推理模式的模型使用轻量推理；不修改共享模型档案。 |
| 研究规划、科学综合、复杂推导、公式验证 | 保留档案配置的推理强度。 |
| 显式输出容量 | 温度模式用 `max_tokens`；推理模式用 `max_completion_tokens`。 |
| 输出容量留空 | 遵循渠道默认，不把内部预算估算伪装成输出上限。 |
| 输入容量、超时、用户代理及端点策略 | 从当前运行继承；模型档案声明的上下文容量继续按既有规则生效。 |
| 重试 | 保留已有传输/结构化重试边界；已经返回正文或可见推理后不重启同一次生成。 |
