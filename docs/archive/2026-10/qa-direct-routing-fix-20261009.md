## 线上问题与根因

用户的“按照最好的创新点分析原理”一轮最终产生 16 次模型请求，结果为 fallback。
第一轮缓存、提示词和角色加载优化没有改变默认问答的多阶段核验流程，未解决交互成本问题。

## 新的默认执行方式

普通问答和论文追问默认使用 `answer_mode=direct`：读取原文和对话上下文 → 一次回答模型请求。

- 不默认调用规划、证据抽取、语义核验、公式核验、支持关系核验或自动修订。
- 长对话按容量本地选取完整轮次，不为普通追问额外调用摘要模型。
- 原文可容纳时完整提供；超长材料本地选择相关片段并说明节选范围，不让模型反复规划补读。
- 不启用附加来源时，常规一次回答，整个请求最多两次模型 HTTP 尝试（含生成前失败重试）。
- 用户选择联网或资料库后，直接使用带必要上下文的问题检索，不再增加查询规划模型。模型型搜索与回答共用最多三次请求，并为回答保留最后一次名额。
- 流式连接重连继续读取同一请求，不重新生成。

`answer_mode=verified` 是显式选择的严格核验模式。界面的“严格核验（较慢）”默认关闭；选择后才执行原来的核验与局部修订。历史核验请求的重连、恢复与修订仍保留原语义。

直接回答的原文片段仅标作“本轮参考原文”，不伪装成逐项核验通过；页面也不再默认显示“回答草稿·正在核验”。正式研究、精读报告与审稿等任务的核验流程继续由各自任务契约控制。

## 验证

- 接口级测试直接计数模型 HTTP 调用：论文冷启动、后续问题、JSON/SSE、同请求重连均验证常规一次请求；失败不会突破两次尝试。
- 验证带公式的普通回答不会触发公式核验，长对话不会触发隐藏摘要请求。
- 验证多个模型搜索后端争用预算时，最终回答仍有保留名额。
- 问答、论文范围、恢复与严格核验兼容回归：324 项通过。
- 前端全量：528 项通过；前端类型和 OpenAPI 契约检查通过。
- 线上同问题回放使用真实原文与原始历史，单独设置最多一次模型请求；实际结果保存在发布回执中，不写回用户原会话。

同一问题“按照最好的创新点分析原理”实际回放：保留前两轮原始对话，读取原任务的 31 个来源片段，模型请求 **1 次**，首段正文 **27.832 秒**，完整回答 **47.503 秒**、3392 字符，未降级。以上是本次实际测量，不是所有问题的延迟保证；这次没有运行独立事实核验。

回放结果（含回答）保留在服务器私有发布目录 `scenario-release-20261009T082938Z/live-replay.json`，没有向原会话追加消息。
