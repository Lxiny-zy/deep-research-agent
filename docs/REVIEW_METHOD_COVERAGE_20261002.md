# 综述方法证据覆盖与定向补读

更新：2026-10-02。本地开发，未推送、未部署；整体目标仍未完成。

## 真实发现

固定快照 `dd4c9ee` 的三篇综述恢复已结束，其输入只有原先保留的 178 条发现，最终仍回退为证据摘录。核读新稿发现 DGSMP 的方法描述停留在 MAP/GSM 先验层面，并把“未抽取到深度展开术语”写成需要回原文核查。这说明逐篇有引用、拥有很多发现，并不能证明关键方法已经覆盖。

原 PDF 第 4 页明确写道：`we construct the end-to-end network with T stages corresponding to T iterations for iteratively optimizing x and w`。该段在冻结来源的第 9 个片段中，初次抽取却没有保留这条核心方法证据。

使用已有证据选择器做真实模型探测时，它正确判断当前候选不足，从 19 个片段中选出第 9、10、11 个补读。补读获得 25 条通过逐字、数值和语义核验的发现，包括 T 个网络阶段与 T 次优化迭代的对应、可学习算子、权重生成器及参数共享等。没有重读整篇，使用的仍是同一 PDF 冻结文本。该探测共记录 67,723 token；输入、选择结果、模型响应及补充发现保存在 `artifacts/acceptance/20261002/dgsmp-method-coverage-probe/`。

这 25 条发现未加入旧快照任务，不能把两次实验混称为一次完成的综述验收。

旧恢复还为回退摘录执行了 12 次成品核验调用，共 219,889 token，而它已不能作为正式综述交付。新路径保留原草稿及其已完成核验，直接给诊断摘录绑定失败记录；写作者和终态检查不再重复付费核验这些摘录。记录明确显示未执行成品语义核验，不能拿来放行正式格式或填入通过缓存；有效的确定性统计报告仍按原流程核验。

旧恢复的模型工作和冻结任务已经保存，导出持久化因本地验收目录过深触发 Windows 长路径错误。用较短存储目录恢复导出时没有新增模型调用，当前结果为 fail、仅有 Markdown。验收脚本新增 `--storage-root`，并未声称解决任意 Windows 路径长度。

## 产品流程改进

“仅指定文献”工作流现在依次执行：附件阅读 → 指定论文导入 → 逐篇关键证据检查与补读 → 综述写作。检查围绕用户的实际比较需求，核对方法或论证如何运作，适用于不同研究主题，不强求所有文献都有可学习模型或实验。

优先使用目录定位缺口并补读相关片段；目录不能定位时扩大到尚未补读的材料，按实际模型容量组批。保留已有发现和补读审计，不重复本轮已补读片段。新发现经过原有证据核验与整体一致性检查；若一致性检查排除了发现，受影响文献会重新评估覆盖。

覆盖记录绑定原始需求、真实来源文本及当前可用发现。来源内容或研究问题变化后不能复用旧通过记录；找不到对应来源快照的旧发现不参与覆盖判断。没有覆盖记录、记录过期或关键内容仍不足时，正式格式被拦截，Markdown 明确标记未通过。资料齐全与正文实际引用仍由原有指定文献覆盖门分别检查。

交付质量设置新增“综述关键证据补读轮数”，默认 1，范围 0–4；0 只检查、不补读。该设置不限制累计 token。前端增加相应流程名称及“指定文献覆盖 / 关键证据覆盖 / 任务正文完整性”的说明。交付格式版本为 29，材料覆盖记录版本为 1。

同时修复了精读来源辅助函数可能把闭域综述的长任务指令当作粘贴论文的问题。
