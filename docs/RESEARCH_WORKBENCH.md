# Science Research 科研工作台使用指南

本指南对应当前已上线的 `8edb37e`。发布状态和环境限制见 [RELEASE.md](RELEASE.md)，后续工作见 [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md)。系统执行完成、工程检查通过和人工科研验收是不同状态；结论、评审判断、统计解释与交付效果仍需使用者核对。

模型通过外部 API 调用；统计计算和文件生成在服务器执行。本项目不提供 GPU 训练调度。

## 开始一次任务

1. 使用服务端分配的访问密钥登录，登录框不填写模型提供方的密钥。默认仅保留本次标签页会话；需要长期保存时再勾选“记住此设备”。
2. 在工作台选择任务，填写问题、对象和要求，添加材料。手机任务栏出现滑动提示时可横向浏览，键盘方向键也可切换任务。
3. 选择检索策略、研究档位及可用的资料库项目，检查“任务确认”中的论文、数据范围和交付要求。高级参数按需展开。
4. 点击开始，在任务详情查看进度、正文、来源与交付物。提交失败时先看错误提示，再修改已保留的输入；不要因页面断开就重复新建任务。
5. 核对出处与版本后下载；需要登记问题时使用[人工验收记录](#人工验收记录)。

工作台、学术问答、任务记录和资料库按身份提供。管理员还可管理模型、检索资源、工作流和服务设置；研究者操作自己的任务与资料库；访客查看有权访问的记录和文件，不能创建研究或保存人工验收记录。

## 任务、策略与研究档位

检索策略决定怎样获取材料，任务类型决定怎样组织结果。`none` 只使用提供的材料，仍可能调用模型阅读、生成与核验，提供 URL 时也可能联网读取该来源。`quick` 进行较短的检索流程，`deep` 按子问题检索并补充缺口。

| 任务 | 可选策略（默认加粗） | 主要输入与典型交付 |
| --- | --- | --- |
| 课题调研 `autoResearch` | **deep** / quick | 问题、范围与材料；Markdown、Word、PDF、HTML |
| 文献综述 `litReview` | **deep** / quick / none | 综述主题或指定文献；综合报告、比较表及上述文档格式 |
| 同行评审 `peerReview` | **none** | 指定论文与评价重点；评审意见、评分及上述文档格式 |
| 论文精读 `paperRead` | **none** | 论文文件、链接或文本；精读报告、原文阅读与后续问答 |
| 数据分析 `dataAnalysis` | **none** | 数据、字段含义和分析问题；报告、XLSX 及实际生成的图表 |
| 幻灯片 `slides` | **quick** / deep / none | 材料、听众与汇报要求；PPTX、Markdown 讲稿 |
| 思维导图 `mindmap` | **quick** / deep / none | 主题或材料；交互 HTML、总览/分支 PNG、Markdown 与索引 |

最终可用格式以该任务的交付登记和服务器能力为准。API 创建任务使用 `template`、`strategy`；不支持的策略返回 `422 unsupported_strategy`。课题调研仍可选用自定义研究流程。

轻量、标准、深度三档调节子问题数量、补洞轮数和每次检索结果数，显式高级参数优先。档位不等于单次模型最大输出，也不代表整项任务的累计费用上限。

创建时冻结问题、选定材料、策略、档位、有效配置和交付要求，后续修改设置不会追溯改写已创建任务。`POST /api/templates/contract` 可预览要求，`POST /api/runs` 创建任务；正式创建仍会检查权限、材料与参数。

## 材料与数据输入

- 通用附件支持 PDF、Word、PPT、Excel、Markdown、文本、CSV 等，最多 8 个文件，单文件不超过 **64 MiB**；支持类型以文件选择器为准。上传即解析，未完整解析、超限或读取失败会显示错误。
- PDF 原件在服务端保存，供有权访问该任务的用户阅读与定位；不能再按“原文件完全不落盘”理解。解析片段带页码、章节等定位并随任务冻结。导入成功不表示每段都已被模型读取，仍应查看阅读范围说明。
- 资料库只使用本轮明确选中且有权访问的项目及其已纳入材料；库中有文件不表示它已进入本轮证据范围。
- 数据分析的专用 CSV / TSV / XLSX 入口上限为 **16 MiB**。多工作表需要选择目标表，或配置并预览合并关系。所用行列、数据范围、缺失/异常和未采用材料应结合报告及 XLSX 核对。
- 也可把表格粘贴到分析问题下方。示例数据必须主动勾选，其结果不代表真实实验。请说明配对关系、重复测量、字段单位和分组含义，以便确定适用的统计方法。

统计量由代码计算，模型负责解释。未记录的字段不等于原文未报告，也不能把未知条件当作相同条件比较。

## 进度、质量与调用记录

任务详情保留步骤进度、正文、交付物、文件树和诊断信息，小屏按可用空间排列。步骤重试、补救与最终失败有各自记录。

| 显示状态 | 使用时应注意 |
| --- | --- |
| 排队 / 运行中 | 等待资源、读取、生成、核验和渲染是不同阶段；等待不等于新增模型调用 |
| 待复核 / 部分完成 | 查看未通过项、材料缺口或失败格式；已有内容不自动成为合格成品 |
| 已完成 | 可以读取已保存结果；不等于科研事实正确，历史记录也不自动获得新规则的核验结论 |
| 已停止 / 失败 | 保留历史和已保存结果；能否继续取决于是否存在可复用阶段 |

检查包括来源读取、逐字引文、语义支持、数字与条件、章节覆盖、格式及文件完整性。数值通过不表示实验条件已核验；评审评分需结合贡献、缺陷、证据和修改建议阅读，不是自动加权得到的事实。

管理员可在“设置 → 交付质量”调整阈值，API 使用 `PUT /api/config` 的 `quality`，字段说明由 `GET /api/config/quality-schema` 提供。默认综述引用下限 20、课题调研 3、单处引用上限 7；常规写作修订默认最多 2 次，问答自动局部修订默认 1 次。任务和实际配置会限制修订范围，不能理解为无限整稿重写。未通过要求时保持明确状态，不以放宽质量门掩盖问题。

**单次最大输出 token 只约束一次模型响应。** 一项任务可包含检索、抽取、生成、核验和修订等多次请求。“模型请求记录”展示已记录的实际请求、失败、重试和用量，与提供方返回的思考内容分开；流式片段及刷新重放不重复计数，未返回用量保持未知，不显示为零。

任务记录页可展开“运行与请求统计”，查看场景状态、首次/恢复、用量、每日趋势和渲染情况。默认仅统计当前身份，管理员可选整个工作区。读取截断和计量缺失会明示；没有核实计价时费用未知。系统完成比例不代表人工科研正确率。

## 学术问答与停止恢复

普通问答默认使用模型自身知识，不自动联网或读取私有资料库；本轮明确勾选后才增加相应来源。精读追问默认保留本次论文材料，额外资料库和联网来源仍由用户选择。没有外部依据的回答不应当作已有引用支持的研究结论。

当前问题、约束和选中证据按上下文预算组织；长对话可能使用压缩记忆，记忆不替代原文证据，也不保证任意长度历史逐字保留。跨主题时可新建会话并明确本轮材料与条件。

- **关闭页面或断线只中断观察，不等于停止执行。** 刷新后先查已保存状态或重新连接。
- **停止本轮**保留历史、已落盘事件和阶段结果；已经完成的回答不改为取消。系统暂时不能确认终态时会说明，不应当作已成功停止或完成。
- **继续未完成的回答**是用户发起的新请求，可能产生新费用。仅在显示可恢复时使用，沿用原问题和来源范围，保留已消耗的修订额度，不把旧轮改写为成功。
- 只有部分响应、没有完整阶段或阶段材料过大时，不保证可恢复；纯模型知识回答也不承诺阶段复用。达到调用或时间上限后不会自动重发结果未知的付费请求。
- 原材料、历史、身份、模型/提示词、配置或核验规则变化可能使恢复失效，返回 `409 qa_recovery_unavailable`，不会静默换用新材料。

可复用阶段分别为：已保存证据后继续作答、完整草稿后继续核验、已有审核记录后完成剩余有限修订或保存。排队忙会返回 429；重连既有请求和创建新的继续请求是不同操作。

API 单轮停止使用 `POST /api/qa/conversations/{cid}/requests/{rid}/cancel`。显式继续沿用原问题和来源参数，提交新的 `request_id` 与 `resume_message_id`；相同请求重复提交不创建多轮。
接单、阶段复用和失效规则见 [QA_RECOVERY_CONTRACT.md](QA_RECOVERY_CONTRACT.md)。

## 阅读导览与原文定位

在报告区展开“阅读导览与原文依据”，或进入精读的“阅读导览”页签。按段落、公式/图形说明、任务关注点和评审意见阅读，再查看依据候选；列表、长文本和候选分别分页。

“当前版本有审核记录”只表示绑定有效，还需看各段状态和待处理项。数值与实验条件、来源读取范围和检索边界随已有记录呈现；发现数量不代表问题已回答，来源清单不代表检索了整个领域。

全文回查与反例单列，不冒充新的支持证据。没有逐字片段的缺失核查只显示范围状态，不生成推测引文。“没有任何研究”等无范围否定应结合实际检索范围核对。

多个候选先显示上下文，由用户选择。只有确认可用 PDF 且引文完整、未遮盖时才提供精确定位；页码提示不是最终定位结果。定位前重新核对版本与依据，过期时要求刷新；切换段落清除旧高亮，迟到结果不能把页面拉回旧选择。

重复引文在 PDF 中仍不唯一时会明确失败，不把保存文本的字符偏移猜成 PDF 坐标；可按来源和上下文手动核对。报告到精读页的选择不会把私有引文放入 URL。
来源记录中的逐字匹配或规范化匹配只描述文本命中，不提供 PDF 几何坐标。

## 交付版本与下载

交付从冻结的正文、结构化表格/图形及证据生成，不再把所有格式简单理解为一份 Markdown 的视觉复制。以交付登记中的可用文件、检查状态和版本为准。

| 格式 | 阅读与使用方式 |
| --- | --- |
| Markdown / HTML | 保留内容和来源；HTML 阅读版可离线打开，外部来源仍需网络；Markdown 含版本与范围说明 |
| PDF / Word | 核对实际分页、长表、公式、图像与书目；普通 PDF 不要求 TeX，学术排版 PDF 依赖服务器相应能力 |
| PPTX | 含页面内容与讲稿；原文图片/截图是图像素材，不保证其中底层文字或数据可编辑 |
| XLSX / 图表 | 核对数据范围、字段、统计口径和输出；缺失或未分析字段不能视为零值 |
| 导图文件 | 交互 HTML 和分支说明页承载完整内容，见[思维导图](#思维导图) |

报告预览的**文档版本**与一组文件的**交付版本**不同，不能混用。页面提示交付是否与当前报告同源，固定某版的导出不会悄悄换成另一版。

- 文档变化后，固定旧版的新读取/导出可能返回 `409 document_version_changed`；明确加载当前版本，或取回已完成的历史导出。
- 导出有持久回执。响应丢失或页面断开时，先“重新连接导出”找回原操作；完成回执仍指向冻结文件，后续改稿不改变旧字节。
- 一个文件缺失或损坏时，完整文件可单独下载；整包 ZIP 必须全部通过完整性检查。修复格式产生新交付版本，保留旧版本与原文件。
- 格式不支持或失败时按对应提示处理。离线正文副本保留版本、核验范围和限制，不能当作已通过审核的完整交付包。

API 中，`GET /api/runs/{id}/document` 的 `content_version` 用于文档导出；文档 `source_version` 对应交付登记的 `input_version`。`include_hsi_tables` 在预览、导览、验收和导出链路中须保持一致。

`POST /api/runs/{id}/render-operations` 使用稳定 `request_id`，`kind` 为 `bundle`、`retry` 或 `export`，后两者指定 `version`、`format`。按回执完整 `status_url` 查询，完成后使用 `result_url`；首响应丢失可按 `GET /render-operations?request_id=...` 找回。同 ID 更改参数返回 409，下载带版本和 SHA-256 校验。访客可对有权读取的任务导出，生成/修复需要研究权限。
完整协议见 [DELIVERY_VERSION_CONTRACT.md](DELIVERY_VERSION_CONTRACT.md)。

## 幻灯片中的 PDF 图像区域

在幻灯片任务中，PDF 上传解析完成后可“选择图像区域”：选实际页码，点击“开始框选”后鼠标/触控拖动，或键盘填写左、上、右、下百分比；填写图号，如 `Fig. 1`、`Figure 1a`、`图1`，加入清单后确认使用。

各附件共享每任务最多 4 个区域的限额，同一附件同图号不能跨页重复选择。选区保留页码、图号和原文上下文，是可供采用的素材，是否使用仍需对应证据核验。移除附件也会清除其区域；重复添加同内容附件而选区不一致时会报错，应先整理重复材料。
源页、图号和区域随任务材料冻结。论文原图和用户裁剪区域可作为图片移动、缩放，不能当作可编辑底层数据的原生图表。

预览使用本次选择的原始 File，仅在浏览器内存保留。API `attachments[].image_regions` 使用 `page`、`figure_label` 和可见页面左上角起算的归一化 `[x0,y0,x1,y1]`。修改选区会改变提交身份，不能误用旧失败请求标识；本次选择不改写已完成任务。

## 思维导图

短标签是阅读软预算，不应通过截断丢掉限定条件；完整说明、数字、条件、公式与引用保留在详情中，详情里的事实同样需要核验。

- `*-mindmap.html`：离线完整导图，可用键盘看详情、折叠分支和定位引用。
- `*-mindmap.png` 及必要的总览续页：只展示一级分支，不代表全部内容。
- `*-mindmap-bNNN-pNNN.png`：分支图块与说明页，避免把整图压成不可读缩略图。
- `*-mindmap-index.json`：节点路径、分支、图块、跨分支索引、关系方向与引用映射；Markdown 保留完整大纲与说明。

节点路径如 `[N0.1]` 是结构标识，不是文献编号。不同条件、数值或引用的节点不因短标签相同就合并；重复候选供使用者检查，不自动删除。各格式来自同一冻结图，层级与关系是否合理仍需人工评价。

## 人工验收记录

在报告与交付物之间展开“人工验收记录”。总体结论默认“待人工确认”，首次实际结果默认“未记录”。
问题包的 `initial_status` 是首次登记时观察到的系统状态，`first_attempt_status` 是用户填报的首次实际结果，`observed_status` 是本次观察状态；不能用当前成功反推首次成功，没有可靠记录时保留未记录。

1. 确认文档版本，选择正文/图表位置、任务要求或来源，填写具体观察。
2. 位置和原文只在主动选择后读取；片段默认不附入记录，明确勾选后才保存，可删减。问题加入清单后再保存记录。
3. 后续用“恢复观察”另建记录并选择先前记录，首次结果由后端继承；恢复成功不覆盖首次失败或原人工结论。
4. 从历史记录查看冻结版本，下载校验过的最小 JSON 问题包。

版本变化时保留未提交内容并返回 409，不自动改绑。需明确加载最新报告，再选择清空未提交内容并登记当前版本；旧记录与问题包仍可读取。未提交表单只在当前页面保留，不承诺刷新恢复。

问题包不默认带正文全文、私有来源全文、全对话、模型思考或配置。已遮盖片段不能作为逐字原文提交，只记录位置/来源和观察。人工记录也不改写正式质量门或原任务状态。字段及 API 用法见 [N0_ACCEPTANCE_RECORD_TEMPLATE.md](N0_ACCEPTANCE_RECORD_TEMPLATE.md)。

## 配置、额度与高级工作流

管理员配置模型与检索资源后，可先运行工作台的配置检查；开始任务时仍会再次校验。`GET /api/tiers`、`GET /api/usage` 提供档位和用量。若启用 `DAILY_RUN_QUOTA` 或 `DAILY_TOKEN_QUOTA`，按身份和 UTC 自然日检查创建额度，超出返回 `429 quota_exhausted`；档位本身不替代额度限制。

高级工作流可设置步骤质量检查和有限重规划。系统记录补救、重试与失败原因；租约、鉴权、存储、预算及取消问题不能靠无限重规划解决。并发、队列、超时及资源配置以服务设置与 [RELEASE.md](RELEASE.md) 为准，不应直接提高并发来绕过排队。
自定义步骤用 `enable_check` 启用产物检查，`max_check_attempts` 限制重做次数；检查仍不合格时保留相应失败/部分完成状态，供后续处理。

文件生成还会检查章节、篇幅、学术表达、引用、公式、可读性和地名规范。概念图可从已有结构化描述生成；图像模型能力如启用，会产生相应外部调用。概念示意图、论文原图和统计图应按各自来源与用途阅读，不能当作新增实验依据。
