# 导图内容契约与完整渲染

日期：2026-10-02。继续完整项目目标中的交付质量和模型调用优化。本批只修改本地代码、执行本地模型验证，没有推送或部署，没有连接实验室服务器。

## 修复的实际问题

1. 生成提示与质量门原先要求至少六个分支、每分支至少五个节点。这会让小主题凑内容，与输入要求不一致。现在由用户范围和证据决定结构，检查空结构、重复节点、引用范围与父子关系。
2. 旧节点只有 label/children，概念与事实没有区别。现在明确 concept（概念）、claim（结论）、question（待研究），保留 relation 和 citations。事实节点必须绑定素材引用；标成 concept 也不能免除对隐含事实断言的核对。
3. 旧 SVG/PNG 只画到有限深度，每组孙节点只保留前四个，标签只显示前 40 字符。现在采用同一套递归树布局，按子树高度和实际换行分配空间，完整保留所有层级、节点、关系和标签。交互 HTML 保留完整大纲，引用可跳到来源条目，外部来源可打开；内部上传资料不伪装成可访问的公网链接。
4. 原通用报告终检把概念大纲当成每段都必须引用的论文正文，导致完成的导图被替换成素材摘要。现在导图使用绑定当前大纲和证据的节点核对记录；缺少记录、记录过期或正文已被修改，不能借旧记录跳过检查。
5. 验收图被改写后曾可能继续导出旧结构。现在校验 Markdown 投影、完整节点集合和输入摘要；不一致或节点核验失败时不导出正式图，只保留标记失败的 Markdown 用于诊断。旧历史导图没有新核验记录时明确标为待关注，不能宣称已完成节点核验。
6. 全量回归还复现了 Windows 并发目录创建时的路径表示差异：一条路径被 resolve 为普通 DOS 路径，另一条带 `\\?\` 前缀，造成错误的越界判断。`ArtifactStore` 在解析链接后规范化等价 DOS/UNC 表示，仍拒绝真正越界路径。
7. 完整任务暴露了旧附件读取的固定四片段批次：这次实际 21 个附件片段被拆成六次串行抽取，附件阅读阶段持续约 1,399 秒。现在按模型容量、真实 Schema/提示词和完整来源格式计算批次；同一输入在 200,000 字符配置下可组成一批，全部 21 个片段均保留。记录为 `mindmap-input/batching-plan.json`；这是请求组装对照，不据此推算实际节省比例。单个片段也放不下时明确报错，不截断原文。

## 节点核对机制与成本边界

`workbench/support.py` 接收最终单元和已准入的原文证据，按批完整核对。稳定证据在请求前面，动态节点在后面；单批不超过 16 个单元，并按模型容量继续拆批，不抽样、不截断单元。输入放不下则明确记为未完成。

模型必须对每个单元返回一个决定；supported 必须附可回查的证据 ID，且证据属于该单元自己的引用，不能偷用同批其他节点的来源。缺失、重复决定、引用范围外的证据或核验调用失败，均不记为通过。校验记录绑定大纲、引用和实际研究结果，记录模型和提示摘要；这些是模型判断，不能冒充人工确认的事实真值。

同一返工循环中，文本、层级上下文和引用证据不变的已确定判断可复用；uncertain 不缓存为最终决定。核验调用失败或输入容量不足不会触发无效的全文重写。正常事实/结构问题仍按已有质量策略返工，并保留被选中版本对应的图结构和核对记录。

PNG 超出单张图片的可读尺寸或像素资源界限时明确报告格式失败；已经生成的完整 HTML 仍可交付，不通过删节点或静默缩小文字来掩盖问题。
