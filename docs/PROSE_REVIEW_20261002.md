# 终稿支持关系核验与统计交付验收

日期：2026-10-02。本批继续完整项目目标中的模型交互、任务编排和交付质量。所有修改和运行均在本地；未推送、未部署、未迁移线上数据。使用用户已授权读取的阿里云模型配置，密钥仅在进程内存中使用。

## 实现范围

- 有来源的学术/论文问答增加最终表述核对：引用编号和数字通过后，还要判断句子是否受到该引用支持。新增的因果、机制、比较与作者归属不再仅凭存在引用就被接受。
- 综述、课题研究、精读、评审、幻灯片文字投影及数据分析的写作循环接入终稿核对。原有确定性检查继续保留；事实问题参与返工，核验调用或容量失败不触发无效的全文重写。
- 核对覆盖标题、段落、嵌套列表、每个表格行和代码块，不抽样、不裁短长段。保留前文指代和表题/表头语境；问答核验也收到完整对话上下文。前文变化会让受影响单元重新核验，其他不变单元可在本次返工中复用判断。
- 核验记录绑定最终完整 Markdown、证据快照、引用范围和摘要等版式政策；每个单元必须有唯一决定。程序检查覆盖完整性和证据 ID 范围，模型负责语义判断；两者不能被说成开放世界事实真值。
- 写作者、最终任务检查和下载入口使用相同记录，避免审核一稿、导出另一稿。补回主观审稿评分的类型边界，并让选中的最好草稿带回自己的评分，避免后稿评分混入前稿。
- 已知核验失败或记录失效时，工作台不生成正式报告格式；两个旧 PDF 路由也返回明确的 409。统计 Excel/图表仍可保留，诊断 Markdown/TeX 与打印稿标注待核验，前端区分输入证据状态和最终正文核验状态。
- 移除写作素材默认只保留前 120 条发现的静默限制。真实导图任务曾有 125 条可准入发现，这种固定数量裁剪没有模型容量依据。

主要入口：`workbench/prose_review.py`、`support.py`、`qa.py`、`writers.py`、`analysis.py`、`orchestrator.py`、`report/service.py`。API 和前端同步扩展 `FinalReportValidation` 的作用范围及结果状态。

## 实际发现与迭代

旧数据报告的数字和引用检查通过，但真实终稿核对找出了“均值/中位数接近，因此未见明显单侧偏移”等未经验证的分布判断，以及“所有数字照抄、未作改写”的生产过程保证。新提示明确区分各方法的标准差、配对差值标准差和平均差，不再把这些量统称为残余或总体离散。

首次核对也暴露了核验输入的问题：原先只发送统计快照 JSON，遗漏了写作者实际收到的推断前提说明；字段 `synthetic=false` 仅表示未由程序自动生成示例，却被误解为数据不是合成的。现在统计快照版本 3 保存完整 `facts`，写作与核验使用同一份台账，并区分程序生成方式与用户声明的数据性质。版本 2 可从冻结值恢复台账文字，不重新计算统计；线上 `f6a9c61` 更早的快照缺少列角色和缺失值字段，只提供实际留存字段并明确未知，不补造缺失信息或导致历史报告读取失败。

实物检查发现数据报告标题直接截取长操作指令，末尾甚至停在逗号，页头还显示“引用 0 个来源”。现在数据报告按实际分析类型使用简洁标题，显示数据文件和行数；工作台、旧文档出口及打印视图保持一致。交付格式版本升为 6，已有成功版本不覆盖。
