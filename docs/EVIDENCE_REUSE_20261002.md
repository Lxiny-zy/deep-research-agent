# 论文证据复用、缓存实测与精读质量问题

本批只在本地修改和验证。经既有授权，只读获取 Aliyun 模型配置，密钥仅在进程内存中使用；没有推送、部署、修改线上数据或连接实验室服务器。以下真实调用均为授权配置的 `deepseek-v4.1-flash`。

## 已实现

- 论文问答先检查任务中已有的核验发现，以及当前进程同一论文/身份范围内积累的证据。来源 URL 与正文 SHA-256 必须匹配，重新通过来源策略、原文引句、数值和撤稿状态检查。未知、过期、异源或未通过核验的内容不会进入复用候选。
- 模型只选择候选 ID，并判断能否覆盖整个问题。覆盖不足时仍查阅原文并走原有抽取/核验；无效 ID 或调用异常直接报告，不把技术错误变成一次额外的付费全文抽取。回答仍经过引用、数值和最终表述支持关系检查。历史对话只解释指代，不充当证据。
- 固定论文、已核验素材和动态问题/修订信息使用独立用户消息。材料没有提升到 system 角色。字符串适配器保持原文本行为，JSON 修订保留固定消息；明确要求 user/assistant 交替的渠道在生成前收到 400/422 后回退为原来的单消息结构。
- 流中已收到思考内容或正文后，连接异常不自动重发；完成响应后的连接清理异常也不触发重新生成。没有增加累计 token 预算或隐藏输出上限。
- 图、表、公式编号和加粗列表序号不再被误作实验数值；实际数值仍受核对。上传论文的多个定位片段按一个文献计数，同时保留全部定位角标。来源不足仍报告不足，不要求写作者删掉合法片段或凑文献数。
- 抽取提示强调一个引句必须完整支持一个最小事实，多组件/多动作拆分，不复制原论文文献编号到论断正文。写作与问答区分本次引用号与引句中的原编号；回退后保存被拒草稿，便于继续修复。交付输入版本升至 12。

## 真实调用结果

### 数据分析复核

使用 `prose-context-final/local-detail.pickle` 中既有完整结果，未重跑统计或写作。当前终稿复核检查 34 个单元：26 个 supported、8 个 non_factual，生成七个通过现有检查的文件，消耗 26,664 token。

记录：`artifacts/acceptance/20261002/current-prose-review/`。这是既有合成配对数据报告的复核，不代表新增真实实验数据或多数据集统计质量验收。

### 论文问答复用

同一论文的 21 个冻结片段共 71,921 字符，已有 125 条可准入发现，其中来源正文哈希全部匹配。真实问题为“三个组件分别是什么、区分既有方法与论文贡献”和“第二个组件怎样检测遮挡”。

第一轮试验两问均未回退，分别选择 19/6 条证据，共 85,605 token；没有 `ExtractedFindingList` 或抽取后的语义核验调用。第二轮使用生产消息分隔路径及后续提示调整，同样两问未回退，选择 21/9 条证据，共 108,580 token，同样没有重复全文抽取。两问的固定候选前缀哈希相同。

记录分别在 `paper-evidence-reuse/` 和 `paper-evidence-native/`。第二轮总 token 更多，支持关系核验和修订消耗明显；**不能据此宣称总成本下降或固定节省比例**。实际减少的是重复抽取阶段，不是取消回答检查。后续仍需减少不必要的全文修订，并保持对引用范围和条件的核对。

### 缓存对照

使用同一段标注为传输试验的材料，每次只请求短标记，单次输入约 4,110 token：

| 试验 | 消息方式顺序 | 渠道报告的缓存输入 token |
| --- | --- | --- |
| 初次手动拆消息 | 单条、单条、拆分、拆分、单条 | 0、0、3978、3978、0 |
| 生产 PrefixPrompt 复验 | 单条、单条、拆分、拆分、单条 | 0、3978、3974、0、0 |

记录为 `prompt-cache-probe/` 与 `prompt-cache-native/`。复验否定了“消息拆分必然命中、单条消息必然不命中”的解释。请求内容与分隔可由项目控制，渠道缓存策略、路由和写入时机未能确认；不能把固定前缀等同于确定命中。生产代码仍保留稳定消息边界及兼容回退，但不强行承诺供应商缓存效果。

## 精读完整任务仍未验收通过

完整论文输入经过当前链路，约 1,073 秒、252,037 token，50 条候选中有 16 条可准入。生成五个文件，但终稿回退为约 606 字的素材摘要，登记为 warn。该案例**不是合格精读交付**。

1. 多条候选把多个事实合为一句，却只附支持其中一部分的引句，导致核心贡献/流程信息被合理拒绝。已加强抽取提示，尚未用新提示重新测量完整任务的准入率。
2. 写作三版的剩余错误包括“表 1 的数字 1 没在素材里”和同一论文分段重复计数。这是代码误判，已修复。由保存的事件恢复三版原文；第三版在新确定性检查下无机械问题，但没有据此直接发布。
3. 第三版“摘要翻译”实际拼接多个正文片段，并明确承认没有完整摘要。任务承诺的是原摘要的完整翻译，现有“只把核验发现交给写作者”的输入不满足这一要求。确定性门通过不能证明任务质量合格。

完整记录：`artifacts/acceptance/20261002/current-paper-read/paperRead/`；恢复草稿及现有检查：`current-paper-read/recovered-drafts/`。原失败版本未覆盖。

下一步必须提供单独、可回查的摘要原文输入，按完整摘要检查翻译，不允许用正文拼接代替；并利用已有核验材料继续修订，避免重新读取整篇论文。摘要来源还需经过原有来源门禁，且不得借翻译输入绕过其他章节的证据要求。
