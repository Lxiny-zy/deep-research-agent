# 角色、提示词与上下文管理改造方案

## 目标与验收

同一个用户问题可以由多个模型步骤完成，但每步职责、输入范围和结束条件应明确。
本轮保留现有模型档案、证据门禁与历史记录，改造调用方式和上下文组织；同时修复用户截图中的
任务配置栏遮挡、文字溢出和论文精读流式回答缺少助手头像。

验收覆盖：长对话继承主题和约束、摘要来源可追溯、超大单轮可处理、跨会话隔离、网页分批且
引用仍匹配完整原文、核验输出完整、模型调用有界，以及桌面和窄屏布局。

## 一、按步骤选择推理强度

- 意图、指代、检索词、会话摘要、明确格式整理：声明推理能力的模型使用每次请求独立的低强度。
- 科学综合、研究规划、复杂推导和公式核验：保留模型档案配置。
- 不修改共享模型对象或用户的模型档案；普通模型不发送不支持的推理参数。
- 叶子任务只接收基本来源纪律与其自身输出契约；执行器的目录、文件、预算状态规则仍归执行步骤。

## 二、统一容量估算与原文分批

- 使用共享容量对象计算系统提示词、用户输入、输出预留及安全余量；公开说明估算性质，
  不把配置窗口或字符换算当作真实 tokenizer / 网关能力验证。
- 模型未填写输出上限时仍为输入组装预留合理输出空间；不把规划用预留误当作硬输出上限发送。
- 多网页材料按来源和可追溯片段有界分批抽取；核验始终针对完整原文，不将窗口冒充完整文献。
- 保存每批来源 URL、原始内容 hash、字符范围，便于问题定位和恢复。空新增元数据兼容旧快照。
- 单条超大材料应分段或明确容量不足；不无限重试、不将截断后材料标记为完整。

## 三、可追溯的对话记忆

- 继续保存完整历史。容量足够时直接使用；窗口压力较大时保留首问、最近完整轮次与有来源的摘要。
- 摘要区分研究主题、用户约束、历史结论背景、未决问题；每项引用原始轮次、字段及逐字引句。
  历史助手结论不能替代本轮核验证据，摘要不是新的高权限指令。
- 通过前缀内容 hash 验证旧摘要；源记录改变或范围不匹配时拒用。只对新增旧轮次做有界增量整理，
  每次问答至多新增一次摘要调用，不反复摘要整段历史。
- 在现有消息内部 thoughts 中持久化摘要，不新增数据库表；公开消息隐藏内部结构，仅显示必要提示。
- 超大单轮允许明确标记的摘录；摘要失败保留可验证旧记忆和原文摘录，标注遗漏，不假称完整保留。
- 检索、抽取和写作共用同一份已准备的记忆；检索使用主题、约束和用户问题，不把历史答案当证据。

## 四、问答调用边界与收敛

- 为单次问答设置独立模型尝试次数上限（初始默认 16），包含摘要、规划、核验和协议重试。
  到达上限停止新增模型请求，保留已经完成的核验结果，不能用未检查草稿冒充终稿。
- 收紧问答默认执行时间至 10 分钟，显式运行配置可覆盖；排队与数据库收尾的实际语义在文档中说明。
- 普通问答默认最多一次局部修订，局部修订失败不再启动整篇重写；保留重复稿、往返改稿和
  分项次数保护。复杂问题可显式提高问答总上限或使用研究工作流。此处不恢复全局日配额。
- 模型失败、容量不足、调用额度耗尽与资料不足使用不同诊断，避免让用户无谓更换检索词。

## 五、前端一致性

- 流式回答统一由共享组件绘制品牌头像，覆盖普通问答和论文精读，防止入口各自拼装造成遗漏。
- 配置栏高度适配可视区域和底部操作条，长配置可滚动到末尾；小屏恢复自然文档布局。
- 高级设置说明允许换行，按钮和正文不横向溢出；保留主题和减少动效支持。
- 已核验前的流式内容明确标记为草稿；移动端仍显示品牌头像，开始研究按钮至少 48px 高。

## 明确边界

- 容量是保守估算，不是渠道真实 tokenizer。档案窗口配置错误时仍可能收到上游容量错误；
  本轮没有通过无限重试来猜测渠道上限。
- 摘要是有损的背景信息。来源引句、hash 和范围证明来源可追溯，不代表模型摘要语义已被再次证明；
  未覆盖部分明确标注，原始记录始终保留。
- 10 分钟限制作用于已领取后的执行，排队与取消后的持久化收尾不计入；显式配置可覆盖。
- 16 次统计经统一客户端发出的模型请求，包含联网搜索模型及失败重试；普通搜索服务不算模型请求。

## 实施与发布顺序

1. 独立模块与故障复现测试先行：容量、记忆、角色策略；同步完成前端小修。
2. 接入 QA 与原文抽取，验证旧对话、缓存前缀、所有任务场景和错误降级。
3. 执行后端/前端回归、类型与 API 契约检查；浏览器检查截图相关页面。
4. 构建已提交的独立镜像，核对线上活动任务、备份与回滚，再发布并做真实调用验收。
5. 记录实际结果与未覆盖边界，不把离线测试当成全部科研内容质量已验收。
