## 优化目标与状态

目标从“功能存在”推进到“输入准确、交付可信、质量可衡量”。以下为 2026-09-30 整理的建议路线，**均待实施，不属于上面的清理成果**。

功能覆盖清单后续区分三层：已有实现、离线场景验收通过、真实质量验收通过。66/66 符号覆盖和单元测试通过不能代替用户场景与科研质量验收。

## 第一轮：输入正确性与评测可信性

### 输入与任务契约

- [ ] 沿用现有 `TaskContract`，明确绑定本次任务使用的论文附件、指定链接和数据表；预览与执行消费同一份输入解析结果。
- [ ] 精读/评审只有论文附件时直接消费附件证据，不因缺少链接自动转为主题检索。
- [ ] `strategy=none` 禁止开放检索；用户明确指定的论文链接仍可按契约取回，不能把“不检索”误实现为“不允许取回指定论文”。
- [ ] CSV/XLSX 接入结构化统计输入，保留工作表、列名、类型和行数；禁止从截断的附件文本片段拼回统计数据。
- [ ] 多工作表或多个候选数据集需要明确选择；缺少数据时提示补充，合成示例仅在用户主动选择演示模式时启用。
- [ ] 统一指定文档、附件、资料库和 OA 检索入口的来源身份及章节/页码定位；无法获得页码时如实标注，不伪造定位。
- [ ] 展示解析失败、正文覆盖不足和截断状态，避免把局部材料描述为已经完整阅读。

主要接点：`deep_research/workbench/contract.py`、`intake.py`、`attachments.py`、`analysis.py`，以及前端 `NewResearchPage.tsx`、`ContractPreview.tsx`。

### 评测器自身可靠性

- [ ] HSI 数值指标区分 precision 与 recall；在标注完整的评测范围内同时惩罚漏提取与额外错误预测，不能把 gold 命中率单独称为准确率。
- [ ] 无样本显示 N/A；发布必测项缺失时阻止通过，不能以分母为零返回满分。
- [ ] 通用回归拒绝空结果、NaN/Infinity 和缺失必要字段，并给出可定位的失败原因。
- [ ] 来源聚类同时测应合并而未合并、独立来源被误合并；区分独立发布方与独立测量。
- [ ] 扩展 HSI 条件签名及对应标注，覆盖实际使用的实验条件；明确 `curated_draft` 不能直接作为正式发布基线。

核查依据：`eval/hsi_benchmark.py` 当前按 gold 命中数计算数值指标，零分母返回 1.0；`eval/regression.py` 对空候选结果和非有限数值还需补回归边界。

**完成标准：**附件-only 精读/评审、真实表格输入、缺数据、截断附件、空评测等固定用例全部通过；不发生未授权检索，不把不可评估显示为满分。

## 第二轮：统一定稿与交付持久化

- [ ] 复用现有报告模型和块结构，建立统一的已审核内容版本，不另造重复的报告系统。
- [ ] 正文、幻灯片要点/备注、导图事实节点关联引用与审核结果；概念节点与来源事实区分处理。
- [ ] 正文复核回退后，PPTX 不得继续导出旧 `deck`；未通过审核的结构须重新生成、明确降级或阻止对应格式交付。
- [ ] 接通现有 `publish()` 与 `ArtifactStore`，登记内容版本、输入摘要、质量结果和文件哈希。
- [ ] 文件树、预览、下载读取同一份交付登记；重复请求和跨进程并发生成具有幂等性。
- [ ] 重新导出形成新版本，不静默替换已交付文件；区分研究完成、交付生成中、部分可用和生成失败。

主要接点：`deep_research/workbench/writers.py`、`publish.py`、`api.py`、`workspace.py` 及 `delivery/`。

**完成标准：**错误数值/引用回退用例中，各格式不保留未审核原稿；同一交付版本重启后下载哈希不变，文件树与下载列表一致，单格式失败不掩盖其余文件的实际状态。

## 第三轮：高光谱科研质量

- [ ] 复用已有 HSI 数值、条件、来源和表格评测能力，从单篇草稿扩成经过独立复核的多论文样本。
- [ ] 样本覆盖 DOE/CASSI 光学编码、重建方法、仿真与实物实验，以及不同数据集、波段数、尺寸、噪声和测量协议。
- [ ] 加入 baseline 转抄、缺失/矛盾结果、条件不完整、论文不同版本及真正独立实验等错误类型。
- [ ] 报告同时呈现方法、编码方式、实验条件、数值、原文定位和不可比原因；不能忽略条件直接按 PSNR 排序。
- [ ] 分别衡量数值正确性、条件完整性、可比性、引用定位及错误合并；先建立可信基线，再制定发布阈值。

**完成标准：**多论文对照能识别不具可比性的结果，关键数值可回溯到原文与实验条件；质量分数可追溯到标注版本，不用单篇成绩代表领域准确率。

## 第四轮：基于测量优化成本、性能与体验

- [ ] 复用同一文件的解析结果；只重做失败步骤或格式，避免整条链重复执行。
- [ ] 按证据缺口决定是否继续检索，分别记录检索、解析、抽取、写作、返工和渲染的耗时与 token。
- [ ] 用固定样本比较 quick/deep、返工前后的质量与成本；性能收益不得以证据质量退化为代价。
- [ ] 完善长报告、失败态、引用定位、键盘操作与读屏体验，清楚解释等待、降级和失败。
- [ ] 分别执行干净环境安装、Docker 与桌面包验收，不能以现有环境单元测试替代安装验证。

**完成标准：**性能改善有基线对照、质量不回退；发布目标环境的安装与关键流程通过独立验收。
