## 最新调整：论文会话固定前缀与 PDF 持久缓存

- 论文问答的抽取阶段改用同一任务冻结的论文材料，先经过原有来源门禁，再按文档顺序组装固定前缀；问题在最后，不再每轮只发送随问题变化的前六个片段。容量允许时包含全部已读取材料，保留原始片段内容；“已读取”不等于原 PDF 中所有内容均成功解析。
- 超出单次模型上下文容量时，保留固定的前部材料，并在其后追加本轮相关片段。固定部分不受问题/历史长度影响，包含明确的节选提示；超长单片段也可检索后半部分。组装容量扣除实际系统规则、JSON Schema，并固定预留问题及修订空间；没有恢复累计 token 预算。回答阶段仍只接收已核验证据，避免每个阶段重复发送整篇论文。
- PDF 增加浏览器 Cache Storage 缓存：上限 96 MiB、24 小时有效，继续保留 48 MiB 的内存缓存。缓存标识为当前凭据/任务/文档的 SHA-256 摘要，不落盘原始密钥或 Authorization；退出/切换身份清理缓存，串行化读写与删除，拒绝旧登录的迟到下载。存储不可用时仍可正常从服务器读取。
- 原文与报告页签切换保留 PDF 阅读器、解析对象、缩放和滚动位置；隐藏时不重置适配宽度。刷新或重新进入需重建 PDF.js 对象，但缓存有效时直接读取本地字节。服务器原文件仍在文件存储，数据库保存元数据和引用，并非每次重新从论文网站获取。
- 供应商提示缓存通常仍需发送完整请求，由供应商复用相同前缀的计算；稳定前缀与会话亲和标识只是命中条件。首轮、过期或路由未命中仍按渠道实际规则计费，未实测真实模型缓存命中率或节省比例。前端继续隐藏用量/缓存面板。

## 最新调整：正文引用与 Fireworks 缓存适配

- 依据 [Fireworks 官方提示缓存文档](https://docs.fireworks.ai/guides/prompt-caching)（2026-10-01 读取），缓存按精确前缀、同副本复用。补充稳定的 `user` 和 `x-session-affinity`（模型/凭据/任务或会话作用域的摘要，不发送原始身份）；共享全局规则提前，角色提示后置，保持规则单次注入和优先级约束。
- 除 JSON usage 外，兼容 Fireworks 专用响应头 `fireworks-prompt-tokens` / `fireworks-cached-prompt-tokens`；JSON 没有缓存字段时不覆盖有效响应头信息。缓存统计仍只在服务端记录，前端用量/缓存面板保持隐藏。
- 当前模型入口是 `api.lxinyer.com` 网关。本机网关源码的 OpenAI 入站/出站转换支持 `user` 透传，但未核对线上网关构建版本或执行真实模型命中对照；不能由后台横线推断命中为 0，也不能把路由标识等同于实际命中。网关若丢弃上游缓存统计，仍需在网关层处理。

## 最新修复：精读对话完整流、应用缓存与引用居中

- 普通问答和精读对话都接通 `reasoning / usage / status / cache / reset` SSE 事件。接口返回的思考内容在生成时展开，完成后折叠并随消息保存；旧消息没有这些记录时不补造。正文、思考内容、缓存用量和检索核验记录分别展示。
- PDF 增加按当前身份/任务/文档区分的页面内字节缓存，最多 48 MiB、30 分钟；切换身份清空，交给 PDF.js 的是副本，避免 worker 转移字节后破坏缓存。同一页面会话内再次打开已下载文件可直接复用；刷新页面后仍依赖浏览器 HTTP 缓存，不宣称已有磁盘离线缓存。
- 增加进程内论文证据缓存（最多 64 条、30 分钟）：相同用户、任务、问题、原文及模型/提示/相关配置复用已核验抽取；依赖上下文的问题还包含历史。失败或空结果不缓存，来源版本/身份/配置变化不复用。回答仍重新生成并核验；这是应用缓存，与供应商提示缓存分别记录。
- 引文定位按 PDF 容器视口的实际几何位置将匹配段落居中，修正原来的固定顶部偏移；切换文档时旧定位任务不再污染新文档的文本缓存。
- 精读提示要求区分原创贡献、使用既有算法和常规预处理；证据不足限定为当前片段，不断言全文不存在。线上反馈对应的旧消息曾因 `uncited_paragraph` / `unsupported_number` 直接回退；现在先用相同证据修订一次，发送 reset 替换临时正文，仍未通过时才回退，未取消引用/数值检查。
