# 问答跨进程流式传输与证据完整性

本批仅本地修改与验证，未推送、未部署，未连接实验室服务器或调用真实 LLM。整体优化目标仍未完成。

## 问题与行为变化

原有 `LiveTurn` 仅保存在发起任务的 API 进程里。重复提交的请求虽然被数据库租约拦住，不会重复调用模型，但重连落到另一个进程后只能轮询最终消息，无法接收正文、模型返回的思考内容或修订重置事件。

新增迁移 `0034`，以消息 ID 和递增序号保存临时 SSE 事件。执行进程每约 200 ms 合并并批量追加新片段；其他进程按游标读取，每次最多 128 个事件，空闲约 250 ms 检查一次。同一进程仍立即转发，不等待数据库批次。这里的间隔是传输调度，不限制任务 token 或内容长度。

正文重置、不同调用的思考片段和状态事件保持顺序。查询正常运行状态不再取得共享写锁，只有疑似租约过期时才加锁重新确认。写入必须匹配当前执行者且租约有效；失败会结束本次生成并报告错误，不自动重新调用模型。

核验后的最终消息与临时事件清理在同一事务完成。最终正文和完整思考记录由原有消息保存；失败/中断保留临时痕迹供同一请求重连读取，删除会话会级联删除其事件。临时正文不写入最终 `answer`，也不作为下一轮已经确认的对话历史。

慢客户端队列达到阈值时，积压片段合并为当前正文和思考快照，使用已有的 replay/reset 事件恢复页面；不会无限堆积旧 token。该机制保留内容，不是截断回答。快照大小仍与正文及思考内容有关。

同时取消问答响应中只返回前 30 条证据的截断。已核验结果中的所有引用定位信息随最终答案返回，避免第 31 条及之后的引用缺少可定位依据。

## 验证

可复现的两个独立进程 HTTP 验证：

```powershell
python -X utf8 -m scripts.verify_qa_stream_processes --output artifacts/acceptance/20261002/qa-stream-new-run
```

输出目录必须不存在，避免旧控制文件干扰本轮。脚本先迁移本地 SQLite，再启动两个仅监听 `127.0.0.1` 的 Uvicorn 进程；模拟模型返回，实际使用 HTTP、任务执行、租约、共享事件存储和 SSE 路由。

验收先连接进程 A，收到正文后断开；随后向进程 B 重提相同 request_id，在原任务仍 running 时收到已有思考与正文，再收到修订重置、第二次思考及修订正文，最后得到持久化回答。仅进程 A 执行生成，数据库只保存一轮问答。首次观察的恢复耗时约 0.375 秒，是单次本机测量，不是生产环境延迟保证。最终复验记录在 `artifacts/acceptance/20261002/qa-shared-processes-final/summary.json`。

内存与 SQL 测试覆盖顺序/游标、防止旧执行者写入、成功清理、失败保留、删除级联、跨 API 实例流式恢复、写入失败停止生成且不重试、1,000 个分片合为两条记录、慢监听者状态重放和 44 条证据完整返回。迁移验证 `0033 → 0034 → 0033 → 0034` 保留已有回答、请求 ID 和摘要，并兼容无迁移版本的 `create_all` 数据库。

完整回归 1,762 通过、16 个 pg 未运行，覆盖率 88.79%；前端 365 通过，OpenAPI 类型一致；Ruff/格式/Mypy、依赖锁和包含迁移的 wheel 隔离启动检查通过。第二次独立进程 HTTP 复验恢复已有内容约 0.25 秒，生成仍只执行一次。

未在本批验证 PostgreSQL、多机负载、代理缓冲或真实模型延迟；没有把模拟模型的传输验收宣称为科学任务质量验收。
