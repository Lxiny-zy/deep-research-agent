# 长任务恢复与执行隔离

日期：2026-10-04。按最新场景计划推进，本轮仅本地修改和离线验证，没有新增真实模型调用、推送或部署。

## 当前行为

- 默认尝试期限按任务/档位选择：轻量 2 小时、标准 4 小时、深度研究 12 小时、问答 30 分钟。显式档位优先于工作流默认，正数 `max_run_seconds` 精确覆盖。
- 新任务排队不消耗执行期限。开始执行后冻结尝试与整个任务的截止时间；自动恢复只续尝试窗口，整个任务默认最多 48 小时。用户显式恢复失败任务授权新的窗口，排队时同样不扣尝试时间。
- 已识别的传输故障、模型供应商暂时错误及尝试超时写入持久化恢复记录，经过 2–60 秒退避再领取；默认最多 6 次自动恢复，连续两次没有新增有效结果后停止。输入、凭据及确定性质量错误保持失败，不以增加重试放宽质量要求。
- 已通过步骤与检查点保留，新的执行者继续失败单元；原始查询、资料库、任务配置、累计耗时和 token 不重置。模型客户端构造前失败也保留已有累计耗时。图分支和步骤候选异常/取消时，仅带回已持久化子问题的专用进度标记，避免错误触发无进展停止，不带回失败正文。
- 自动恢复前不发送任务终态 `error`；受管工作流中的暂时故障向上交给执行器判定。取消优先，失去租约的执行者无法覆盖新 owner。恢复冷却、状态与检查点在同一仓储事务中保存。
- worker 先停止领取、保持心跳、等待配置的退出宽限；到期后有界清理，只有不响应清理时进程退出兜底。非用户取消保留租约至到期；inline 与 worker 语义一致，未开始任务的取消仍释放资源。
- 冷交付和格式重试与普通文件读取分开，各有两个阻塞线程槽；两份大型交付不会占满普通读取容量。
- PDF 混合页面尺寸定位先更新布局再跳转，同毫秒重复定位使用递增标记；当前浏览器证据与边界见 [来源与定位记录](QA_SCOPE_AND_PDF_LOCATOR_20261003.md)。

## 配置与审计

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `MAX_RUN_SECONDS` | `0` | 自动选择尝试期限；正数为准确覆盖值 |
| `DR_RUN_TIMEOUT_PROFILES` | 空，使用内置值 | JSON 覆盖 `quick/standard/deep/qa`、具体工作流或 `paper_read:deep` 等任务档位 |
| `MAX_TASK_SECONDS` | `172800` | 整个任务最终期限，从首次执行起计算 |
| `MAX_RUN_RECOVERIES` | `6` | 自动恢复上限 |
| `MAX_NO_PROGRESS_ATTEMPTS` | `2` | 连续无新检查点结果的停止上限 |
| `DR_WORKER_SHUTDOWN_GRACE_SECONDS` | `20` | 停止领取后等待在途任务的秒数 |

已有数据库在线配置的正数 `max_run_seconds` 仍优先；需在设置中改为 0 才启用新默认策略。恢复使用任务冻结配置，不能修改当前设置来重路由旧任务。`/api/runs/{id}` 返回的 `orchestration.checkpoint.scratch._recovery` 包含恢复次数、无进展次数、原因、安排时间与最早领取时间，原事件/attempt 保留。

问答本轮只改变默认期限选择，仍使用其独立请求恢复契约。第三方插件如果吞掉原始异常、仅返回错误字符串，不能声称会自动恢复。自动恢复的无进展判断依据检查点计划、结果、报告、成功步骤以及真正落盘的子问题标记；标记使用持久化单元 ID 与内容 SHA256，重复复用同一缓存、token 增长和时间流逝都不是进展。
