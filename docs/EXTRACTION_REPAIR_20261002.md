# 抽取候选恢复与科学计数法核验

本批仅在本地修改、验证和提交。沿用用户授权只读读取 Aliyun 模型配置，凭据只在进程内存使用；没有推送、部署或连接实验室服务器。

## 候选和模型调用

抽取结果现在保存原始候选、准许使用的完整来源快照、每次提案、逐字/数值/语义检查、放弃和技术失败原因。先执行程序检查，只把符合原文和数值约束的候选交给模型判断支持关系。

失败候选可以定向修复、扩大连续引文或拆分复合论断；已通过的发现保持不变，拆分后通过的部分也可复用。不能换来源、删除原有数值/单位、用未改变的失败候选反复请求判断，或重复已接受的事实来增加数量。后续调用失败保留已取得的有效部分，不重新抽取全文。

初次抽取和修复共享 Schema 与系统提示；原来源前缀在模型容量允许时保持不变，动态诊断放后面。完整来源加诊断超容量时，使用该候选所属的完整来源，不截断来源。质量设置新增“抽取候选修复轮数”（默认 1，可设 0–4），这控制返工次数，不是累计 token 预算。

审计记录随研究结果保存；零发现任务也保留诊断。问答使用现有思考记录 JSON 保存审计，前端活动列表不显示这份内部数据。审计元数据不进入正文/导图的事实签名，增加审计不会使旧正文自动失效。只有证据本身改变才要求重新核验。进度中的已验证数量按实际可准入发现计数。

新增数据库迁移 `0035`（前置 `0034`），保存 nullable JSON `extraction_audit`；本地 SQLite 往返验证保留旧结果，未执行远程迁移。问答抽取缓存版本为 7，最终交付格式版本为 25。

## 真实冷启动暴露的问题

20 页论文 *Hyperspectral Panoramic Image Stitching Using Robust Matching and Adaptive Bundle Adjustment* 的完整任务已结束：2,189 秒、567,988 token、原流程生成五个文件。**原注册表的 pass 不等于此次任务可靠通过。**

共取得 85 个初始候选，11 个需要修复。旧逻辑记为 8 个修复成功，其中 3 个实际上错误；另外 3 个未解决：跨页页眉引文、公式引文，以及单位只在图轴标题 `Runtime/s` 中出现的测量值。全体原始响应和审计在 `artifacts/acceptance/20261002/extraction-repair-cold/paperRead/`，没有覆盖。

PDF 第 16 页原来把 `3.742 × 10⁶` 提取成 `3.742 × 106`。初始候选的结构化值 3,742,000 正确，但旧数字解析器无法匹配；修复模型把值改成 3.742，语义检查又只认可句子而漏掉结构化值的错误。EOG、DFT 同样出现 299,600,000 → 2.996、475,400,000 → 4.754 的错误。

修复包括：

- 根据 PDF 上标 span 元数据，在“尾数 × 10”后保留明确指数；不改写作者脚注，不载入嵌入图片，沿用读取顺序和文本上限。原第 16 页对比只有表格的 12 处指数新增明确标记。
- 数值、指标绑定和比较符共享完整科学计数法解析，保留位置；支持 e、显式指数和 Unicode 上标，尾数和指数不能单独冒充测量值。含义不明的旧 `×106` 不猜测成 `×10^6`。
- 显示科学计数法与结构化 value 必须一致；处理单位换算、极小数精度及溢出。历史 `quantity_status=verified` 仍须通过当前科学计数法检查。
- PDF 阅读器定位兼容服务端的指数标记与 PDF.js 分开的文本项。此处归一化只服务视觉定位，不作为数值校验依据。

用新代码重导出原任务，正式 PDF/Word/HTML 被拒绝，旧正文核验哈希也失效；诊断在 `scientific-old-result-recheck/`。这验证了旧标记不能绕过本批修复。

## 恢复与验证

受影响的三个初始候选从同一 PDF 的新解析快照恢复，保持原始完整数值，重新定位连续表格引文；新来源使用独立修订 URL，旧来源内容不改写。一次真实语义调用全部通过，新增 2,308 token，没有重新抽取论文。结果在 `scientific-recovery-verified/`，由 `scripts/accept_scientific_recovery_live.py` 生成。

定向修复另有一组明确标为合成的校准：正确的 Alpha 38.4 保留，Beta 的错数与转述引文修为 35.2，编造的 Gamma 99 放弃。3 次真实调用、9,783 token、两个有效发现；该校准不是初始抽取质量测试。记录在 `extraction-repair-calibration/`。

恢复报告先保留原正文，改数值表格的来源引用，合用 79 条有效旧发现与 3 条新核验数值。新一轮 76 单元复核拒绝了三段：无依据的普通图像比较、误写 Runtime 仅以累计分布呈现，以及把未确认内容写成全面缺失。局部修订后两段通过，剩余否定断言再次被拒绝。由此补强写作/局部修订提示：不能把“论文未报告”简单改成“所给证据未涉及”，应删除无依据的缺失断言或明确改为后续验证建议。再次修订该段后，**76 个正文单元和 29 个图示单元通过本轮核验**；已通过单元按未变内容和证据复用，正文和图示不挪用旧哈希。最后一轮局部修订、正文复核与图示复核共 4 次调用、75,367 token；模型进程已结束。

实际查看 PDF 后发现，新解析快照被错误显示为第二条文献。现将同一不可变 PDF 文件的受控解析修订参数排除在书目身份之外；完整定位 URL 和文本哈希分别保留，外部 URL、未知参数和真实版本不归并。无需再次调用模型，最终重导出为 **1 条书目、19 个定位，Markdown/HTML/Word/PDF/图示五文件全部通过，PDF 七页**。正文核验仍绑定；第六页三项科学计数法与原 PDF 表格核对一致，Word 内部文本也保留这些数值。最终目录：`artifacts/acceptance/20261002/scientific-delivery-25/`；复核结果在 `verification.json`。

最终离线完整回归 **1,908 通过、16 个 PostgreSQL 用例未运行，覆盖率 89.17%**；前端 **378 通过**。Ruff/格式（406 个文件）、Mypy（189 个源码文件）、ESLint、生产构建、OpenAPI、体积和依赖锁检查通过。最终 wheel 在隔离环境安装和冒烟通过；该最小环境不安装可选 PDF/Word 库，对应格式正常报告缺少依赖，HTML/Markdown 继续可用。主开发环境的真实 PDF/Word 导出另行验收；离线 HTML 的 216 个内部链接目标均存在。

补充写作与局部修订的否定断言提示后，相关正文核验、局部编辑和工作台定向回归 **85 通过**，也已纳入上面的最终全量回归。本次恢复流程和失败记录分别保留于 `scientific-report-recheck/`、`scientific-report-final/`、`scientific-report-final-2/`；验收脚本支持读取有版本绑定的失败核验，继续局部修订，不重抽原文。前两次失败复核的精确 token 总数没有完整落盘，不据心跳计数估算总成本，也不宣称固定节省比例。

## 尚未解决的边界

定向恢复通过不代表冷启动已经稳定一次成功。跨片段/跨页表格、图轴单位与数值的绑定、公式提取，以及不能逐字匹配的候选还需改进。本次没有浏览器或 Office 人工验收，也没有证明全场景缓存命中率或固定成本下降。其他任务，尤其多文献综述、同行评审、汇报材料和自动研究，仍需完整真实质量样本；整体项目优化目标继续进行。
