# 原文区间恢复、图例单位和精读补读范围

本批在本地完成开发和真实模型复验。只读使用已获授权的 Aliyun 模型配置，凭据保留在进程内存；没有推送、部署或连接实验室服务器。原始失败、恢复结果和旧交付版本分别保留。

## 精确原文与单位

上一轮剩余三个候选不是相同问题：跨页引文漏了完整页脚，公式引文漏了一个不可见控制字符，运行时间单位则写在 `Runtime/s` 图轴标签中。

修复阶段现在提供程序定位的连续原文区间。模型可返回 `quote_id`，由程序按来源 URL、文本哈希及起止位置恢复原始文字；模型不用重抄页眉页脚、控制字符或长表格。唯一首尾锚点用于提出区间建议，不放宽事实准入；锚点重复或反向时不猜测。必要时可选择同一来源的完整区间，完整来源不在动态诊断中重复发送。编号只能用于所属候选，错误编号、改变来源/快照、与自填引文冲突均被拒绝。恢复后仍执行原文、数值和语义核验。

单位只在明确的标题和连续的 `方法, 指标=值` 行之间关联。空行、其他指标或图注结束该范围，不能将附近任意单位借给数字。支持 `AT`、`Runtime` 和 `average Runtime (AT)` 等实际写法，同时保留精确位置、单位换算和比较符检查。历史“已核验”记录也不能删除这类明示单位来继续通过。

真实恢复 `c12/c43/c62` 成功：原文快照未改写，3 次调用、14,409 token，三个候选均通过。加上前批恢复，原 85 个候选均已有可用恢复结果；这只表示这些候选得到处理，**不证明原始抽取覆盖了论文全部内容**。记录：`artifacts/acceptance/20261002/quote-span-recovery/`。

## 真实问答暴露的统计范围问题

不能把自动核验的 pass 当作科学质量已获证明。本轮对照原图发现，图 5 的三个 Runtime 子图分别有 LAF 的 AT 值 **0.3398、0.4094、0.3353 秒**；只回答一个值，或称其为全部数据集的汇总均值，都不完整或不正确。

- 原问答复验第一问只回答了一个数；第二问补读全文取得其他数值，但第一问仍不合格。记录在 `quote-span-qa/`。
- 仅收紧“不要为范围问题索取无关软硬件清单”的提示，确实避免了补读，却仍产生汇总范围错误；该样本不能作为成本优化成功案例。记录在 `quote-span-qa-scoped/`。
- 加入分组提示后，模型仍可能只选一个数值并声明“足够”。因此增加程序层面的同源图例值覆盖检查：同一方法、指标、单位和来源快照中存在其他明确图例值时，必须补读核验；目录中的文字计数不自动变成事实。已核验的其他同组数值也不能被选择器悄悄省略。
- 首次启用该检查又暴露了复合指标名 `average Runtime (AT)` 被严格字符串匹配误拒的问题，已修正指标族匹配，并补充比较符回归。该次失败过程保留于 `quote-span-qa-inventory/`。

## 补读和核验

候选证据及来源目录放在固定提示前部，对话、当前问题和已读来源放后部。目录只含标题、定位、章节及图表标识，不能作为事实证据。模型不足时选择目录中的相关 URL；程序只发送这些完整来源片段，拒绝外部或未知 URL。

补读后重新选择证据。仍不足则扩展到尚未读过的必要片段，范围不明时保留全文回退；同一片段在本轮不重复读取。已经核验的新发现及时放入同论文缓存池，后续选择调用失败也不抹掉已取得材料。活动显示实际补读数量，不把“文档有 20 段”误写成本轮读取 20 段。

抽取、写作和核验共享分组统计范围约束：一个子图的均值不等于跨分组均值，不根据图中覆盖多个数据集推断它们被合并计算。核验策略版本加入正文、图示、导图的绑定哈希和交付缓存指纹；旧通过记录不能直接为新规则背书，旧文件历史仍保留。

已有报告按新规则复核后，发现一处“来自作者此前工作”的归属缺少明确证据，已局部修订。最终正文和图示重新通过，五文件恢复可用，记录在 `panel-scope-report-review/`、`panel-scope-report-repair/` 和 `panel-scope-report-final/`。这轮原报告复核 174,465 token，局部修订 25,831 token，图示及最终复核 62,300 token；没有重新抽取该报告的整篇材料。

最新精读双轮复验在 `quote-span-qa-final/`，模型进程已结束：第一问仅补读 **1/20 个片段**，取得五条新发现并完整列出三个 Runtime 面板值；第二问不再抽取，复用已核验数据解释均值和外推边界。两轮均完成当前回答检查，分别消耗 60,818 和 43,263 token。第一次补读后的选择前缀与第二问相同，但这不代表固定缓存命中率或稳定节省比例。图例值与具体数据集的关联仍保留不确定性，回答也仍有可压缩的文字；不能将此结果当作全部精读质量已经成熟。

源码回归最终 **1,932 通过、16 个 PostgreSQL 用例未运行，覆盖率 89.19%**。前端 **378 通过**；Ruff、格式、Mypy（190 个源码文件）、ESLint、OpenAPI 类型、最终构建、体积检查及最终 wheel 的隔离安装/冒烟通过。最小安装环境不含可选 PDF/Word 库，相应缺依赖诊断不影响 HTML/Markdown；开发环境的五文件交付另行通过。新测试还覆盖局部补读、补读后扩大范围、不重复读取、未知 URL 拒绝、选择失败后保留已付费取得的证据，以及核验策略变化时更新交付版本。
