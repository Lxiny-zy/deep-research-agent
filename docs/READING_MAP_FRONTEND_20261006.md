# 阅读导览、依据候选与全文回查入口

状态：本地工程实现，未部署；科研结论与评审判断仍待用户人工评价。

## 页面与状态

- 已结束任务的研究报告区新增折叠的“阅读导览与原文依据”；论文精读新增“阅读导览”页签。
- 共享页面使用同一版本绑定的 reading-map API，分页展示关注点、段落、公式/图形说明、评审意见及其选用的依据。
- `review_bound` 仅说明当前版本存在有效审核绑定，界面同时显示逐段状态与未通过项，不把它渲染为整体通过。
- 数值与实验条件单独展开，保留比较符号、原数值写法、误差与单位；缺失值显示未记录，不变成 0，也不推断论文没有报告。
- 全文回查与反例单列，独立分页，不生成新的 evidence_id；没有逐字片段的缺失核查只展示范围状态，不编造引文。

## 原文定位

多候选先显示各自上下文，由用户选择。只有服务端确认 document_id、pdf_available，且引文完整、未遮盖时
提供定位入口；复用现有 PDF.js 完整引文定位器，不把保存 Source 的字符偏移当 PDF 坐标。
page_hint 仅显示为页码提示。

从报告跳论文精读使用小型 navigation state，包含文档版本、HSI 文档变体和选中的引文；不把私有引文放 URL，
消费后移除 state。精读页再次核对任务、版本与可用 PDF 文档；不以当前打开的 PDF 猜测匹配。
切换导览段落先清除旧高亮，页签之间保留导览选择及未提交问答输入。

每次实际定位前重新读取同一 unit，核对版本与锚点仍然匹配。选择、版本或可见页签已变化时，迟到的校验结果
不能触发导航。409 后隐藏旧依据操作并提供明确的报告刷新入口。

## 验证

- 真实 SQLite、合成 Source、实际两页 PDF、真实签名审核器配合受控 FakeLLM 生成专用 run；不手工设置 review_bound，不调用真实提供方模型。
- 桌面/手机验证：Alpha 的重复原文呈现两个候选且不自动跳 PDF；Beta 的唯一完整引文定位实际第 2 页；引文不进 URL，切回导览保持所选段落，旧高亮清除。
- 版本边界：先读取并缓存两个段落，再改动服务端报告；旧请求得到 409，刷新后显示审核未绑定当前新稿。
- 首次缓存加强用例失败，原因是继承了全局 10 秒 staleTime；已对导览设 0，并在定位动作前显式校验，而未改变全站缓存策略。
- 拒绝不可用 PDF、截断/遮盖引文、无效导航状态，数值精度/不确定值及无引文缺失核查有独立组件/函数测试。

实现位于 `api/readingMap.ts`、`ReadingMapPanel.tsx`、`ReadingMeasurement.tsx`、`ReadingFulltextPassages.tsx`。
真实浏览器场景为 `frontend/tests/browser/integration-reading-map.spec.ts`，按 [N9 运行方式](BROWSER_REGRESSION_N9_20261006.md)执行。

重复引文若在 PDF 中仍不唯一，现有定位器会明确失败；本批不根据 Source 字符偏移生成推测 PDF 坐标。
这些验证证明绑定与显示行为，不证明真实模型给出的科研判断正确。
