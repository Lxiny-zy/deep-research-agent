# 项目改进建议

## 已完成的方向调整

- 普通用户入口使用“研究策略”概念，不再要求用户理解 Agent、Step、Edge。
- 旧 `/workflows` 路由继续保留，避免历史链接失效；页面内容改为策略中心，底层流程编辑作为管理员高级能力。
- 任务详情使用阶段状态投影，统一显示当前阶段和下一步动作。

## 后端优先级

1. **策略契约独立于工作流定义**：策略记录任务目标、证据范围、补洞方式、修订方式和交付格式；工作流只作为运行时实现，可替换而不改变用户契约。
2. **问题驱动回流**：每个问题必须归类为 `retrieve`、`read`、`rewrite`、`render` 或 `security`，分别回到检索、全文阅读、写作者、格式渲染或安全门。禁止所有问题统一回到“继续写作”。
3. **证据覆盖前置**：开放检索任务也要在写作前生成用户要求、比较维度、方法机制和开放问题的覆盖清单；覆盖不足时先补证据，避免写完全文才发现材料不够。
4. **版本化中间产物**：正文、证据清单、覆盖记录、语义核验和格式输出各自保存版本及父版本，支持只重做受影响阶段。
5. **阶段化预算**：检索、全文阅读、写作、核验和格式生成分别计量，某一阶段失败时不重复消耗其他阶段的预算。

## 前端优先级

1. **任务详情是主工作台**：展示阶段轨道、证据覆盖、当前问题队列、正文版本和交付物；低层 Agent 日志默认折叠。
2. **问题队列可执行**：每条问题显示原因、影响范围和动作按钮，例如“补读原文”“继续修订”“重试 PDF”。
3. **策略预览**：新建研究时显示“将使用哪些材料、预计经过哪些阶段、最终交付哪些格式”，不显示内部角色名。
4. **区分三种结果**：研究完成、交付完成、事实核验完成分别展示，不再用一个“验收失败”覆盖全部情况。
5. **管理员入口隔离**：工作流画布、角色提示词、模型档案和资源配置集中在高级设置，不进入普通研究路径。

## 产品判断

工作流画布不是没有价值，而是不应成为用户理解系统的主界面。它适合管理员调试、开发新运行策略和复现实验；普通用户更需要的是“研究策略”和“下一步怎么完成报告”。
