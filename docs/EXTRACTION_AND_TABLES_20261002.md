## 模型抽取契约

研究抽取原先使用持久化 `FindingList`，其 Schema 包含程序维护的原文核验状态、语义结论、来源身份和交叉印证结果。这些字段不应要求模型生成。

新增 `FindingContent` / `ExtractedFindingList`，只包含 statement、source_url、evidence_quote、confidence、entity、quantity、conditions。`Finding` / `FindingList` 继续用于存储和外部读取；原字段不删除。任何模型或适配器返回的候选都先按内容字段白名单还原为未核验发现，再进入原文、数值、条件、语义和一致性检查。即使适配器返回带 verified 标记的对象，也不能直接带入信任状态。

同步更新了角色提示预览、论文上下文和附件组批的容量计算，以及抽取缓存版本。原文和固定规则仍在动态问题前面，没有恢复累计 token 预算或固定单次输出上限。

本批还确认了已有核验接口的语义：`EvidenceCheck.accepted` 表示原文匹配，不等于整条事实可交付；错数值会得到 quantity_status=unsupported，并由 report_eligible 拦截。新增回归保留该区别，没有因为一次测试误用 accepted 而削弱或改写已有数值保护。

## PDF 表格与图表标题

- 使用实际 Story 排版测量决定能否放入剩余空间。能在一页放下的短表与表题整体移动，避免在页末只留下表头或一行。
- 长表按完整行分段，每页重复表头和表题，续页标注“续”。不删除行、不切掉后半张表，尽量避免最后只剩一行。
- 列宽从全表计算并固定到所有分页。实物检查发现百分比列宽未按预期生效，已改为绝对点宽，并明确正文边距。
- 保存单元格实际矩形，检查文字是否覆盖相邻列或超出版心；检查续页表头。注入错误列宽的回归能够检出重叠，不能只以 PDF 可打开作为验收。
- 图表前的章节标题会随图表移动，避免页末只有“图表”标题、图片却在下一页。图片和图注的既有完整性/尺寸检查继续保留。
- 超过一页高度的单行或过长表题会明确报告失败，不裁剪、不死循环。这类超长单元格的自动拆分，以及宽表横向页面，仍需后续完善。
