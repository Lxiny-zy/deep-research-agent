# 精读摘要、局部修订与图示质量验收

本批在本地继续完整项目目标。沿用既有授权读取 Aliyun 模型配置，密钥只在进程内存使用。未推送、未部署、未更改线上任务，也没有连接实验室服务器。

## 摘要输入与完整性

之前精读写作者只有抽取后的发现，因而把正文片段拼成“摘要翻译”。现在从已读取资料中识别独立摘要，保存原文、来源 URL、正文 SHA-256 和字符位置；长摘要可重组同一文档的连续分片，并记录各组成片段的哈希。上传和链接分片须匹配已知重叠，粘贴文本按其已知分片规则连接；缺片、来源不一致或无法确定完整边界时不声称取得完整摘要。

摘要在固定用户消息内作为翻译专用资料提供，未提升为 system 指令或其他章节的事实依据。整份摘要翻译作为一个完整单元核对，包括被分成多个段落/小节的情况；核对全部事实、限定、数值及逻辑是否保留，不能用若干句正确替代全文完整性，也不能以 non_factual 跳过。正文单元不能借用摘要专用证据。

数字检查对译文使用该节原文，对其他章节继续使用其研究证据。没有完整原摘要时明确失败且不反复要求模型重写；原文或字符范围变化后旧记录失效。精读核验签名使用版本 4，其他任务保留原有签名。单次来源本身不完整且没有可信续片时，仍需要改进解析或提供完整资料。

## 局部修订与显示

当结构和数值等检查通过、仅少量正文段落存在支持关系问题时，写作者可只修订这些段落。替换必须对应当前核验记录中的 ID 和精确文本范围；不允许遗漏目标、改动其他段落、引入未提供引用、改成新章节/表格，或仅改标点后重新抽签。结构性问题仍走原有整稿修订。

复用未改变单元的已绑定核对结果，修改段落及受指代上下文影响的后续单元重新检查。保留尚未完成的最好版本；修订技术失败不偷偷增加一次整稿生成。前后端支持 token 的 replace 标记，修订稿替换旧稿而非追加，仍是待核验正文。

另修复短加粗标题与相邻表题被要求逐段印引用的问题。其数值与研究事实仍需核对；核对提示明确，本报告自己的编排说明可以依据报告结构判断，不能因此免除实验结果、指标定义或因果解释的证据要求。

## 图示与排版

真实 PDF 检查发现：概念图文字被超宽横向画布缩得很小；比较箭头还把“相机阵列优于滤光片阵列”画反，并把“除标定外均优于”解释成“标定未优于”。这些错误没有被正文核对覆盖。

现在对图题、图注、节点分组和有向关系逐项核对，记录绑定图结构和已核验材料。比较必须按源节点到目标节点解读；缺失、过期或失败的可选图示不进入正式报告，原因显示在交付面板。生成时可单独修图，不重写正文；图示不使用摘要翻译专用资料补证。去掉概念图输入只取前 6,000 字符的截断及凑固定节点数的要求。

概念图采用固定报告宽度、长流程纵向排布、文字换行和跨层连线；图例不再堆积成一长列。图放在方法章节附近，以 200 DPI PNG 生成，标签保持可读字号。它仍是位图；SVG/矢量概念图及复杂稠密图的进一步排版不是本批完成项。正文公式继续使用既有矢量数学路径。

报告标题优先采用正文一级标题；自动生成的长任务指令不再直接印为精读报告标题。旧样稿中误把页眉当论文标题的句子及与方法无关的卷期占位说明已删除并重新核对。交付输入版本最终为 15，已有版本没有覆盖。

## 真实验证链与实际失败

1. `abstract-paper-revision/`：复用与当前论文完全匹配的 141 条已核验发现，没有重复全文抽取。识别出 1,542 字符原摘要并完整翻译；三版写作/核对后，报告仍因两处正文问题失败，仅输出诊断 Markdown 和图。新增 306,293 token，约 913 秒。没有把此轮失败当通过。
2. `abstract-local-repair/`：只修复两处段落——无所引依据的 SSIM 定义、把场景关联写成因果解释。未修改的单元复用核对结果，新增 44,459 token，正文与摘要通过，得到五文件。该用量不是对不同任务的通用节省比例。
3. `abstract-quality-final/`：图示核验明确拒绝原图的两个错误关系；纠正比较方向及标定说明后，16 个图示单元通过。对两处编排性文字删除后的报告复核，35 个正文单元通过。新增 78,505 token，最终五文件通过当前检查。

最终产物位于 `artifacts/acceptance/20261002/abstract-quality-final/delivery/`，含 Markdown、HTML、DOCX、PDF、概念图。PDF 为五页；实际查看了正文、摘要译文及新版图示页面。原失败稿、各次模型响应与核验决定都保留。后续渲染器清理后图示字节哈希复核一致；受限证据的局部修订逻辑也重放了真实补丁，结果与已核验修订稿一致。

可复现的模型调用入口是 `scripts/accept_paper_revision_live.py` 和 `scripts/accept_figure_review_live.py`。只接受本项目验收脚本生成的可信本地快照，不能载入用户上传或远程下载的任意 pickle。
