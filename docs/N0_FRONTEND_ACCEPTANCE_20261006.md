# N0 人工验收页面入口

状态：本地工程完成；未部署，未代替用户人工判断。

## 使用路径

有版本化文档的已结束任务，在研究报告与交付物之间显示“人工验收记录”。默认折叠，展开后：

1. 确认本次记录绑定的文档版本。总体结论默认“待人工确认”，首次实际结果默认“未记录”，不从当前完成状态推断首次成功。
2. 在“添加具体问题”选择正文/图表位置、任务要求或来源标识，填写观察。正文和原文片段只在主动选择后读取，默认不附入问题包；明确勾选才保存必要片段，可删减至所需内容。
3. 将观察加入问题清单，再保存记录。多个问题分别保留类别、位置、所选片段及问题结论。
4. 后续恢复观察另建记录并选择先前记录，首次实际结果由后端继承；恢复成功不覆盖首次失败。
5. 从历史记录查看冻结版本和观察，下载经版本与 SHA-256 校验的最小 JSON 问题包。

当前工作树由 [AcceptancePanel](../frontend/src/components/AcceptancePanel.tsx) 与
[独立 API 模块](../frontend/src/api/acceptance.ts) 实现，[RunPage](../frontend/src/pages/RunPage.tsx) 只挂载入口。
请求类型沿用 [后端 N0 契约](N0_ACCEPTANCE_RECORD_TEMPLATE.md)，未修改主 client.ts 或手写生成的 OpenAPI 文件。

## 版本、权限与隐私

- 表单固定其打开时的文档版本。后台出现新稿时，旧版保存返回 409 并保留未提交内容，不自动切换版本重试。
- 用户需明确加载最新报告，并选择“清空未提交内容并登记当前版本”后才能改绑；旧记录始终可独立查看和下载。
- 同一表单内容的网络重试沿用同一请求 ID；更改内容后才生成新请求 ID。
- 访客只能查看记录，保存仍通过既有研究/管理权限与任务归属检查。
- `excerpt_redacted=true` 的预览不作为原文片段提交，仅允许记录位置/来源及人工观察。
- 表单不默认保存整篇正文、来源全文、全对话或模型思考；片段不写入浏览器持久存储。未提交状态仅保留在当前组件，刷新后不承诺恢复。

## 工程证据

- 3 项组件测试：503 后请求 ID 保持、409 不丢观察/不自动改版、遮盖预览不能附作原文。
- 2 项真实浏览器场景：完整登记/恢复/409/旧包链路，手机表单可达与无页面横向溢出。
- 真实链路验证：默认 pending；浏览片段后未勾选的 payload 仍为空；记录首次 error；版本冲突保留未提交说明；新版本 recovery 明确选择依据后继承首次 error；原记录仍 pending 且旧问题包字节未变。
- 运行于独立 localhost FastAPI、临时 SQLite、真实文件/渲染服务及合成身份。主报告与原文均为明确合成材料，没有模型调用或生产访问。
- 首轮 N0 浏览器脚手架失败来自精确文本 label 定位器，已改为真实可访问 combobox 名称；其后 2 项通过。完整隔离集成当前 **7 项通过**（含 N9 的 5 项）。
