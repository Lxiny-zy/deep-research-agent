# 按已核验正文单元筛选引用依据

本批仅本地修改、测试和验收。沿用用户授权只读读取 Aliyun 模型配置，凭据仅在验收进程内存使用；未推送、未部署，没有连接实验室服务器。

## 从位置关联到核验选用

同一原文片段可以产生多条发现，原界面点击该片段的引用会显示全部记录；论文问答还会按段落词项重合度猜测最相关的一条。现在复用已有终稿核验决定中的 `evidence_ids`：每次正文引用具有独立标识，关联它所在段落或表格行的核验单元，并按原始位置过滤该单元实际选用的证据。

只有正文、全部素材、问题、规则和定位仍匹配，且核验通过时才建立此关联。正文或来源哈希变化、核验失败/缺失时保留原有位置级展示，不声称完成了精细筛选。某个位置虽然被引用、却未被该单元核验选用时，不自动拿该位置的其他记录顶替；这也不等同于证明该位置不支持结论。

原 `Report`、研究结果及核验签名没有改写。新证据标识只在服务端报告/问答输出时生成，不接受模型自报的标识，也不让不合格素材获得可用于筛选的标识。重复共享摘录按身份和快照去重。

## 页面、问答与导出

- 报告页面和离线 HTML 首先展示核验选用的摘录，用户可明确切换为查看原位置的全部记录。选中摘录未加载时说明缺失，不悄悄扩大范围；正文/绑定变化后关闭失效选择。
- 同一位置在不同段落中出现时，分别使用各段的核验选择；不会把所有同编号引用一起标为当前选中。组合引用保留全部相关位置。
- 论文问答保留原回答和原编号作为对话历史，另保存引用关联。新回答的定位优先用核验结果；多条摘录都被选中时让用户选择，不再由相似度擅自决定。没有这份记录的历史问答继续使用原匹配路径，提示其匹配方式。
- 关联随问答结果原子保存，内存和 SQLite 的独立读回测试均保留标识及元数据；该元数据不进入活动列表，也不塞入下一轮对话正文。
- 图表插入同时作用于核验用正文和展示用正文，避免插图造成位置偏移后绑定到另一段。正式格式的内容检查仍使用原始正文；展示关联只影响引用与依据呈现。

## 真实验收

1. 从上一批可信报告快照重放：54 处正文引用均关联到有效的核验单元，所有 HTML 引用目标存在；原输入指纹不变，五文件检查通过，无新增报告模型调用。产物：`artifacts/acceptance/20261002/citation-occurrence-final/`，`verification.json` 保存核对结果。
2. 使用 `deepseek-v4.1-flash` 对同一论文做两轮真实追问：光谱一致性校正的方法与作用，以及它与配准步骤的先后关系。两轮最终都通过，分别有 4、6 处引用关联；第一轮一次修订，第二轮两次修订，原始回答与核验响应保留。
3. 两轮均通过已有证据选择完成，没有重新抽取全文；新增 59,466 token。两轮选择提示的固定前缀哈希一致，不据此承诺通用缓存命中率或节省比例。记录在 `artifacts/acceptance/20261002/citation-occurrence-qa/`，模型验收进程已结束。

格式版本升至 23，22 为中间验收版本。无需数据库迁移；新字段是派生报告字段及原有问答 JSON 中的附加数据。

## 验证边界

后端完整回归 **1,872 通过，16 个 PostgreSQL 用例未运行，覆盖率 89.04%**；前端 **375 通过**。Ruff、格式、Mypy（188 个源码文件）、ESLint、构建、OpenAPI、体积与依赖锁检查通过。新 wheel 在隔离环境的安装、启动、迁移、资源和部分格式导出冒烟通过。

当前核验粒度仍是段落、表格行或其他既有正文单元，并非每句话都有独立判断。同一段内多个引用若指向同一位置，可能仍显示同一组选用摘录；本批没有假装把段落判断变成句子判断。更细粒度核验、抽取失败候选恢复、跨片段表格支持，以及其他任务的真实质量矩阵仍待继续。

前端组件测试覆盖精细筛选、显式查看全部、过期绑定、缺失记录、多摘录选择和定位回调；没有新增浏览器或 Office 人工验收。真实问答验收覆盖模型引擎，API 序列化与持久化另由接口和存储回归覆盖。
