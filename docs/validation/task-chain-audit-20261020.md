# 研究任务链路与调度审查及修复记录

2026-10-20，本地工作区审查；未连接服务器、未调用付费模型。当前实现与部署状态以 `docs/IMPROVEMENT_PLAN.md` 为准。

审查发现：共用写作者传递不存在的参数；所有工作台任务均归重；来源不足时引用门下调目标；反思吞掉供应商繁忙；缺少基于已有证据继续研究的入口；检索策略与档位默认不一致。

本轮修复：

- 移除写作者错误参数；保留既有事实核验策略。
- 开放检索交付增加独立的研究充分性门，来源不足保留成果但不判定完成；仅指定材料继续遵守材料范围。
- 确定性缺口优先于模型“充分”判断，没有补救问题时生成有界补洞任务。
- 保存反思轮次、完整结果与待执行问题，资源繁忙/网络超时传播到托管恢复。
- 按冻结的实际输入规模为小数据分析、短材料任务、有限快速调研开放轻任务通道；外部计划和未知体量保持重任务。短任务有有限优先，等待老化避免研究饥饿。
- 阶段或反思轮次保存后允许主动让出任务槽；默认时间片 60 秒，只在安全边界切换，不终止在途调用。
- 新增版本绑定的继续研究模式；复用开放研究的已核验证据、针对缺口再检索，指定材料任务只补读指定输入。保留父任务与交付版本，使用既有幂等、权限与配额机制。
- 默认档位跟随检索策略，显式选择仍优先，创建时将实际档位写入任务契约。

定向回归覆盖写作修复、引用验收、反思恢复、调度、内容修订及供应商协调。完整前端测试还发现阅读器、推理面板及会话分页的失败；不得将定向通过等同于全仓通过。真实模型质量、PostgreSQL 多进程和线上混合负载尚未在本次验证。

源码入口：`deep_research/scheduling.py`、`workflow.py`、`reflection_progress.py`、`workbench/research_continuation.py`、`workbench/publish.py`。新增回归：`tests/test_task_chain_repairs.py`。
