# 开放检索通路与 PostgreSQL 验证

更新：2026-10-03。本批继续先验证真实任务通路，未推送或部署。

## 真实开放研究 sc82

arXiv 与 OpenAlex 元数据预检均返回五项结果，网络与接口可用；也存在宽泛或跨主题命中，不能把返回数量视为召回质量。

本轮使用原生“轻量 + 快速检索”配置，经 HTTP 提交完整研究问题：split conformal prediction 对单个未来样本的边际覆盖保证、交换性假设及与给定特征条件覆盖的区别。三个部分均保留，不裁剪为单一问题；要求可追溯引用且不需要额外图示。这是一个具名代表场景，不替代其他档位或所有输入的验证。

`scripts/accept_library_http_live.py` 新增可选的真实 arXiv/OpenAlex 模式，默认资料库模式保持原语义。每次检索的原始来源、模型响应和输入摘要保存本地；完成后经公开下载接口核对文件，再执行带公开来源的问答。续跑保留原检索模式和记录编号，避免覆盖此前响应。模型配置只读来自此前授权的阿里云配置，凭据不落盘。

sc82 首次执行在 3,600 秒期限到达时失败，三个子问题均已完成并保存，但综合/终稿检查尚未交付报告；日志 `artifacts/sc82.log`，失败快照 `artifacts/sc82/first-attempt-run-detail.json`。已通过正常续跑接口继续，日志 `artifacts/sc82-resume.log`；首次失败不改判，尚无最终报告、下载或问答验收结果。检索包括相关基础论文及局部化/漂移工作，也出现无关或弱相关全文，后续需要结合最终引用与结论判断。

独立检查工具 `scripts/verify_library_http.py` 已兼容公开检索模式：报告和问答引用须出现在本次实际检索记录中，核对正常终态、格式、下载哈希和可读内容。原资料库恢复样本按同一工具再次检查仍通过。

## PostgreSQL

在本机 Docker Desktop 创建独立 PostgreSQL 16 Alpine 容器，限制 1 CPU、512 MiB 内存及 128 个进程，只绑定本机回环地址；没有连接或修改生产数据库。

初次测试中的四个失败来自空数据库未初始化，已运行项目迁移后复验。最终 **18 项 PostgreSQL 用例全部通过**，其中新增两项覆盖：

- 主动续跑更新执行时段，保留原累计耗时、token，并拒绝旧执行权修改状态。
- 两个并发重新入队请求只有一个成功，数据库中的时段与成功请求一致，worker 能领取该任务。

其余用例覆盖迁移、部署锁、仓储交付契约和跨进程协调。日志为 `artifacts/postgres-migration-sc82.log`、`artifacts/postgres-sc82-final.log`。测试完成后只停止本次创建并确认归属的容器，其临时数据随容器自动清理。生产库没有升级。

后续首先完成 sc82 的报告、下载和问答独立检查，再继续其他首次真实任务；产物质量与资源优化仍排在通路验证之后。
