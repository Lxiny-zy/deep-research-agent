# 产品内继续修订与真实 HTTP 验收

更新：2026-10-03。本批在本地实现与验收，未推送或部署。

## 用户流程

交付面板在内容检查未通过且保留了可用证据时显示“继续修订内容”。点击后生成关联原任务的新运行，用户可以查看进度、取消或恢复执行；原任务及其原文件保留。新任务的任务信息提供“查看原任务”链接。

目前覆盖有完整任务契约的调研、综述、精读、评审、数据分析、幻灯片与导图。正文已通过但某种文件生成失败时仍使用按格式重试。材料检索/抽取未完成、没有已核验证据、缺少必要输入的旧任务不会通过修订伪装成完整交付。精读缺少摘要时只尝试读取并重解析已保存的附件原 PDF；无法恢复时给出补充原文的说明，不重新下载或猜测完整性。

## 执行与版本边界

- `POST /api/runs/{id}/revise` 校验原任务权限、材料/正文版本和请求标识。重复请求与完成后的重放返回同一个新运行；版本变化或同一请求标识被用于另一版本时返回冲突。
- 复用标准 inline/worker 提交、队列容量、租约、取消、运行恢复及事件流。新运行冻结当前模型配置，保留原任务质量要求，重置期限和用量记录，不继承父任务的执行计划或产物目录。
- 快照保留已解析的原材料、发现与审计、原草稿及核验记录。包含“继续”这类短请求时，执行使用父任务已消解的完整问题，并将其纳入版本校验。
- 普通研究报告与导图在绑定仍有效时复用旧检查，优先只修被拒的段落/节点。引用范围或规则变化时重新检查，不使用过期记录放行。数据分析仍从保存的数据计算，不重新取数；修订流会替换旧草稿。
- 修订次数仍遵守原任务配置；没有新增累计 token 预算。客户端保留本次操作的请求标识以应对刷新或断线，不因响应丢失再创建一项付费运行。

## 验证结果

后端测试覆盖内存与 SQLite、inline 与 worker、并发重放、队列已满时重放、身份隔离、只读拒绝、来源版本冲突、完整问题保留、旧运行不变、局部段落/节点修订、从原件补齐摘要，以及数据写作者失去租约后不得继续。前端验证按钮、只读状态、版本冲突刷新、原任务链接和请求标识持久化。

完整后端 **2,158 项通过**，16 项 PostgreSQL 沿用既有独立通过记录，覆盖率 89.61%；前端 **398 项通过**。Ruff、Mypy、ESLint、OpenAPI、构建和体积检查通过。后续进度提示与完整问题版本校验的定向回归也通过。日志：`artifacts/regression-sc61.log`、`frontend-sc61.log`、`frontend-build-sc61.log`、`content-revision-sc61-context-final-tests.log`。

`sc61` 使用冻结的真实自动研究失败稿，通过本地 Uvicorn HTTP 服务及真实模型调用产品接口。该实测使用内存仓库；SQL 排队与并发语义由上述 SQLite 测试另行验证。

- 两个相同 POST 请求返回同一修订任务，完成后重放仍返回该任务，实际执行数为 1。
- 原任务快照不变；原先可用的 Markdown 文件哈希不变。新 Markdown/HTML/Word/PDF 通过相应检查，HTTP 下载字节与登记哈希一致，PDF 九页。
- 流式接收记录了 6,136 个模型返回的思考事件，首次约 5.47 秒；局部修订在约 36.81 秒发布一次正文替换快照。该模式按完整段落替换，不把它描述成逐字生成全部正文。浏览器展示仍由用户人工验收。
- 完整运行约 1,254.8 秒、16 次模型调用、1,019,175 tokens。正文仅需两次调用；余下 14 次用于配套图示的生成、修订和核验。图示把一般深度学习方法的失配退化范围归给深度展开子类，未获支持，最终未纳入交付；登记为 warn，不能称所有交付项通过。

证据：`artifacts/sc61/live/acceptance.json`、`parent-file-check.json`、`preview/file-check.json` 与 `delivery/`。本轮没有重跑检索。当前更突出的瓶颈是图示核验经常传入接近二十万字符的证据，而非本次两段正文修订；应改进图示对具体证据的绑定与选取，同时保留事实核验要求。
