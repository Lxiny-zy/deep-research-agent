# 05 · 前端架构（React 18 + TS + Vite + React Flow）

> 定位：AI Agent 工程岗简历项目里的**加分项**。面试官若追问前端，目标是「答出深度、点到为止」——每个答案都能落到具体文件与行号，但不要把话题从 Agent 系统拽走。
> 代码根目录：`frontend/src/`（下文 file:line 均相对此目录）。测试基线：15 个测试文件、81 个用例，全部离线可跑（vitest + jsdom，零真实网络）。

## 一、设计思路总述

前端要解决的核心问题只有一个：**把一个长时间运行、会中断、会重放的多智能体后端，稳定地呈现为「实时研究直播 + 可审计报告 + 可视化编排」三个界面**。所有架构决策都围绕这条主线。

**1. SSE 用 fetch + ReadableStream 手写解析，而不是 EventSource。**
问题：后端启用 `X-API-Key` 鉴权时，`EventSource` 不能带自定义请求头，密钥只能拼进 URL（`?api_key=`），会进浏览器历史、代理日志、Referer。方案：`streamRun()` 用 `fetch` 带 `X-API-Key` 头拿到 `res.body.getReader()`，`TextDecoder(stream: true)` 处理多字节字符跨 chunk 截断，用 `/\r?\n\r?\n/` 找事件边界兼容 CRLF，只取 `data:` 行——注释心跳（`: ping`）自然被过滤（api/client.ts:217-263）。取舍：放弃了 EventSource 自带的自动重连与 Last-Event-ID，重连语义改由上层自己定义（见第 2 条）；换来密钥不进 URL（有专门测试断言 URL 不含 secret：api/client.test.ts:35）。

**2. 断线不自动重连，改「置 disconnected + 详情轮询兜底」。**
问题：后端 `/stream` 端点的语义是「进行中实时推、已结束全量回放 buffer」，重连会把整个事件 buffer 再放一遍，token.delta 会重复累加、报告文本翻倍。方案：连接中断时不重试，把状态置为 `disconnected`（hooks/useResearchStream.ts:99-101、134-147），RunPage 的 React Query 详情轮询（4s）接管，直到 DB 状态到终态（pages/RunPage.tsx:26-35）；断线后一旦有落库报告就优先展示完整版而非流式残留（RunPage.tsx:54-61）。取舍：断线后用户失去逐 token 直播，但看到明确提示「实时连接已断开，正在轮询获取进度…」（RunPage.tsx:99-101），最终一致性由 DB 保证——比「重复内容的假实时」诚实。

**3. 事件归并做成纯 reducer。**
问题：SSE 事件种类多（token/report/finding/done/error/info），且回放 buffer 里终态事件后可能还有尾随事件。方案：`reduceStream(prev, ev)` 纯函数（useResearchStream.ts:39-93）：token 累加、report 整体覆盖、只有 `ORCHESTRATOR` 的 done/error 才是终态（isTerminal，:34-36），RESEARCHER 的 error 是被隔离的单点失败只进时间线；到终态后 reducer 直接返回 prev，尾随脏事件写不进来（:45-47）。取舍：多写一层抽象，换来 10 个纯函数单测（useResearchStream.test.ts）不需要 mock 网络。

**4. 证据 UI 纯前端消费已有 API，零新增后端接口。**
问题：要做「[n] 引用 → 证据侧栏 → verified/conflicted 徽章 → 来源拦截数」。方案：remark 插件把正文 `[n]` 文本转成 `#cite-n` link 节点（lib/evidence.ts:23-72），引用序号→URL 优先用落库 citations、缺失时从「## 参考来源」回退解析（:117-127）；拦截数从事件流里 `source_policy` 审计事件累加，拿不到返回 null，概览条降级并注明（:100-110、ReportView.tsx:101-110）。取舍：前端多做解析，换来后端零改动、直播与历史回放同一套消费逻辑。

**5. React Flow 画布：受控数据 + 本地节点状态双轨同步。**
问题：positions/edges 必须由 WorkflowEditor 持有（要存库），但 React Flow 拖拽需要自己的节点状态。方案：`useNodesState` 持本地，effect 按 id 合并外部 desired 状态（WorkflowFlowCanvas.tsx:289-308）；拖拽结束用 `onNodeDragStop` 第三参数把**所有**被拖节点写回，只存锚点会让多选拖拽的其余节点被同步 effect 弹回旧坐标（:495-503，纯函数 mergeDraggedNodePositions：workflowCanvasLogic.ts:100-108）。连线前 BFS 判环（canConnectNodes：workflowCanvasLogic.ts:29-54），编辑器侧还会算出环路径给出人话报错（WorkflowEditor.tsx:195-227）。409 版本冲突时草稿不丢：编辑器保持挂载，只 refetch 服务端 version 回填进会话，下次提交带新版本（WorkflowBuilderPage.tsx:98-115）。

**6. 编辑会话隔离。**
问题：旧保存请求的迟到回调会关闭/污染用户新开的编辑器。方案：每次打开编辑器分配自增 sessionKey，错误按 key 存 `saveErrors`，所有回调先比对 key（WorkflowBuilderPage.tsx:22-27、83-124），`<WorkflowEditor key={session.key}>` 强制重挂载清空内部 state（:191-201）。

**7. 动效系统统一 token + 克制原则。**
`--ease-expo`（出场）/`--ease-spring`（微交互）/`--dur-*` 统一定义（experience.css:48-54）；滚动 reveal 只做一次性进入、不做视差，`prefers-reduced-motion` 或无 IntersectionObserver 时直接标记已显示（hooks/useRevealOnScroll.ts:13-42），CSS 层再全局兜底降级（experience.css:1104-1113）。

**8. 离线测试策略。**
不起后端：SSE 用 `ReadableStream` 手工 enqueue 分块 mock（client.test.ts:10-24）；reducer/画布逻辑抽成纯函数直测；页面级测试 mock hooks，用 deferred promise 精确控制两次请求的完成顺序复现竞态（NewResearchPage.test.tsx:46-74）。

## 二、题库（21 题）

### A 档 · 基础（讲清楚就行）

**A1. 你们前端整体结构？状态管理为什么没上 Redux？**
- 考点：架构自知之明。
- 参考答案：Vite + React 18 + TS，路由分五页（App.tsx:11-17）。服务端状态用 React Query（hooks/useRuns.ts、useCatalog.ts：queryKey 缓存 + mutation 后 invalidate，如 useCatalog.ts:123-150），实时流是独立 hook `useResearchStream` 内部 useState + 纯 reducer，UI 局部状态就地 useState。没有全局共享的客户端状态，Redux 是负资产。
- 追问链：mutation 后为什么 update 用 `setQueryData` 先写缓存再 invalidate（useCatalog.ts:129-134）？→ 立即反映编辑结果，避免列表闪旧值。
- 陷阱：别说「小项目所以不用」，要说「状态分类后各归各位」。

**A2. HTTP 客户端的错误处理做了什么？**
- 考点：工程化基本功。
- 参考答案：统一 `request<T>` 封装，非 2xx 抛类型化 `ApiError(status, detail)`（api/client.ts:26-34、91-112）；FastAPI 422 的 detail 是对象数组，`formatDetail` 展平成「字段: 消息」（:42-54）；401 时广播 `dr:unauthorized` 事件，App 监听后清 key 弹登录（:84-89、App.tsx:32-41）；204 走 `requestVoid` 不解析 body（:115-132）。
- 追问链：为什么用 window 事件而不是 context？→ client.ts 是纯模块不在组件树内，事件是最薄的解耦。
- 陷阱：说不出 422 detail 是数组这种细节会显得没真做过。

**A3. 鉴权引导流程（首屏怎么决定进主界面还是欢迎页）？**
- 考点：启动时序设计。
- 参考答案：App 挂载后探测 `GET /api/config`（App.tsx:43-73）：200→verified 进主界面；401→清掉本地 key、置 guest 渲染访客 WelcomePage + 可弹 LoginGate（:110-117）；网络错误→error 屏带重试按钮（authAttempt 计数器触发重探，:75-79）。key 存 localStorage（`dr_api_key`，client.ts:56-82），隐私模式下 try/catch 静默降级。
- 追问链：为什么探测用 /api/config 而不是专门的 /auth 端点？→ 复用现有最轻端点，后端零改动；探测同时把配置带回来。
- 陷阱：localStorage 存 key 的 XSS 风险要主动认账：单机自托管工具，威胁模型不同于公网 SaaS。

**A4. 报告页的布局怎么兼顾「看过程」和「读报告」？**
- 考点：产品判断 + 简单状态。
- 参考答案：默认双栏（时间线+DAG | 报告），报告是核心产出所以给更大权重；一键 `reportExpanded` 切全宽阅读（RunPage.tsx:21-22、121-148），按钮带 `aria-pressed`，有防回归测试断言 class 切换（RunPage.test.tsx:126-150）。流式时报告容器加 `is-streaming` 类保持滚动容器稳定、光标 `▍` 提示生成中（ReportView.tsx:117）。
- 追问链：为什么不用路由参数记录展开态？→ 阅读偏好是瞬时 UI 态，进 URL 反而污染分享链接。

**A5. 动效系统怎么保证「统一且克制」？**
- 考点：设计系统意识。
- 参考答案：三条缓动 token 全站唯一出处：`--ease-expo`（cubic-bezier(0.16,1,0.3,1)，出场）、`--ease-spring`（回弹，按压微交互）、`--ease-atelier`（颜色过渡），配 `--dur-press/reveal/headline`（experience.css:48-54）。滚动 reveal 是一次性 IntersectionObserver 打 class，进过视口就 unobserve、不回退（useRevealOnScroll.ts:28-39）。克制体现在：无视差、无循环动画抢焦点、reduced-motion 双保险——JS 层直接标记已显示（:20-26），CSS 层 `@media (prefers-reduced-motion: reduce)` 全局把动画时长压到 0.001ms（experience.css:1104-1113）。
- 追问链：异步渲染的面板怎么 reveal？→ hook 接受 deps，数据到达后重扫描（useRevealOnScroll.ts:13、41）。
- 陷阱：只谈好看不谈无障碍会丢分。

### B 档 · 进阶（要讲出机制）

**B1. 详细讲 SSE 流解析：分块、CRLF、心跳、终态各怎么处理？**
- 考点：流式协议解析。
- 参考答案：四个点（api/client.ts:236-263）——① 多字节分块：`TextDecoder.decode(value, {stream:true})` 内部缓存半个 UTF-8 字符，循环结束后再 `decoder.decode()` 冲刷尾部；② CRLF：事件边界用 `/\r?\n\r?\n/`、行切分用 `/\r?\n/`，兼容代理改写行尾；③ 注释心跳：只保留 `data:` 前缀行并去掉一个前导空格，`: keep-alive` 行天然丢弃；④ 终态截断：解析层不管语义，上层 onMessage 收到 ORCHESTRATOR done/error 后置 terminal 并 `controller.abort()`（useResearchStream.ts:127-130）——但 abort 只能停后续 read，同一 chunk 里已排队的回调还会同步触发，所以 onMessage 里有 `disposed || terminal` 早退守卫（:115-119）。
- 追问链：为什么 `data` 多行要 join('\n')？→ SSE 规范允许一个事件多条 data 行拼接。
- 陷阱：漏掉「abort 之后同步回调仍会到达」这个点，说明没踩过这个坑。

**B2. 为什么不用 WebSocket？（压力题预演）**
- 考点：技术选型的克制。
- 参考答案：三层理由——① 通信是严格单向的（服务器推事件），SSE 语义正好，WS 的双向能力是多余的复杂度；② 部署面：SSE 就是普通 HTTP，过 Vite proxy / nginx / 公司网关零配置，WS 要升级握手、要处理代理超时；③ 后端已有「进行中推送 / 已结束回放」二合一端点（useResearchStream.ts:96-98 注释），SSE 的文本帧模型和事件回放天然契合。真正需要双向（如中途取消）时走普通 REST 即可。
- 追问链：那 HTTP/1.1 六连接上限？→ 单 run 页面只开一条流，且现代部署走 HTTP/2 多路复用。
- 陷阱：不要贬低 WS，要说「按需选择」。

**B3. reduceStream 的状态推导规则？为什么终态后要冻结？**
- 考点：事件溯源式 UI 状态。
- 参考答案：token.delta 累加进 reportMarkdown 且**不进**时间线（避免几千条 token 事件撑爆列表）；report 事件用完整 markdown 覆盖流式残留；finding 累加 count；info 提取 DAG；耗时取已见最大值防乱序回退、tokens 取事件携带的累计值（useResearchStream.ts:48-92）。终态判定收窄到 `stage === 'ORCHESTRATOR' && (done|error)`（:34-36）：RESEARCHER 的 error 是失败隔离下的单点失败，运行还在继续。终态后 reducer 返回 prev 冻结（:45-47），因为回放 buffer 里终态事件后可能还有尾随事件，不冻结会污染最终报告——有专门测试断言 `stale === done` 引用相等（useResearchStream.test.ts:46-57）。
- 追问链：done 事件的 data 是什么？→ RunStats（elapsed/total_tokens/sources），直接落进 stats（:73-78）。

**B4. 断线后用户到底看到什么？数据一致性怎么保证？（压力题）**
- 考点：降级路径的完整闭环。
- 参考答案：时间线上界面立即出现「实时连接已断开，正在轮询获取进度…」（RunPage.tsx:99-101），StatusBadge 保持 running。背后：stream 置 disconnected 后，React Query 详情轮询继续每 4s 拉 `/api/runs/{id}`，函数式 `refetchInterval` 直到 DB status 终态才返回 false（RunPage.tsx:29-35）；一旦详情带回落库报告，`preferPersistedReport` 让完整版覆盖流式残留（:54-61）——落库版是权威副本，流式残留可能停在半句话。stream 自己到 done/error 时还会立刻 refetch 一次拿最终数据（:41-44）。三个防回归测试盖住：断线用完整报告、SSE error 后立即 refetch + 轮询到终态停、DB 终态压过还在 streaming 的假直播（RunPage.test.tsx:73-124）。
- 追问链：为什么轮询终止条件看 DB 状态而不是 stream 状态？→ stream 报 error 时编排器可能还没把终态写进库（RunPage.tsx:26-28 注释），以 DB 为准才收敛。
- 陷阱：只答「显示断线提示」不答数据收敛路径，等于没答。

**B5. 证据链 UI 的数据从哪来？流式阶段没有 findings 怎么办？**
- 考点：渐进增强。
- 参考答案：三路数据全部来自已有 API——① findings 从 run 详情 `results` 展平（RunPage.tsx:74-76、evidence.ts:75-77）；② 引用序号→URL：优先 `report.citations`，流式没有就从 markdown 尾部「## 参考来源」用 `^\[(\d{1,3})\]\s+(\S+)$` 回退解析（evidence.ts:117-127）；③ 拦截数：扫事件流里 `data.category === 'source_policy'` 的审计事件累加 `blocked`，一条都没有返回 null（:100-110）。降级三级：无 findings→[n] 渲染为不可点击的 inert 角标、不显示概览条（ReportView.tsx:53-57、87）；有 findings 无审计事件→概览条只显示前三项并注明「拦截数不可用」（:101-110）。
- 追问链：为什么 [n] 转 link 要先合并相邻 text 节点？→ micromark 可能把 `[n]` 拆成多个相邻 text 节点，不合并跨节点引用识别不到（evidence.ts:30-40）；link 内部不再递归转换防嵌套链接（:47-49）。

**B6. remark 插件为什么比正则替换 HTML 更好？**
- 考点：Markdown 渲染管线理解。
- 参考答案：`remarkCitations` 在 mdast 层把文本节点 `[n]` 切成 `#cite-n` link 节点（evidence.ts:23-72），再由 react-markdown 的 `components.a` 拦截：`#cite-` 前缀渲染成可点按钮（有证据时）或 inert 角标，普通链接照常 `target=_blank`（ReportView.tsx:40-72）。好处：不碰原始字符串、不用 dangerouslySetInnerHTML（无 XSS 面）、代码块里的 [1] 不会被误伤（只处理 text 节点）、与 remark-gfm 组合无冲突。
- 追问链：点击 [n] 后发生什么？→ setActiveCitation 开证据侧栏，展示该 URL 下全部论断卡（statement→逐字 quote→验证徽章→内容哈希缩写→conflicted 反向链接，EvidencePanel.tsx:100-179），Esc 关闭（:137-143）。

**B7. 进度条百分比是怎么推导出来的？为什么说它是「估算」？**
- 考点：多源状态归并。
- 参考答案：`deriveResearchProgress`（lib/runProgress.ts:162-221）合并两路真相：落库的 workflow steps 和直播事件里的 step 状态（mergeWorkflowSteps：:89-133）——落库终态 step 不被直播事件覆盖，同 node 重跑（resume 后新 step_run_id、attempt 归零）按执行序 collapseByNode 取最新（:95-109）。总步数取 workflow.plan 事件 / definition nodes / steps 的最大值（:135-151）。百分比 = (完成数 + 活动步权重 0.42 / retrying 0.58 / ready 0.12) / total，非终态封顶 96、terminal 封 99、done 才 100（:185-203）——宁可显示 96% 也不假装完成。
- 追问链：为什么 retrying 权重比 running 高？→ 重试说明该步已经跑过一轮，比刚开始更接近完成。
- 陷阱：这套是启发式，面试要主动说「estimated 标志位就是承认它是估算」（:219）。

**B8. React Flow 画布的环检测怎么做？为什么两处都有 BFS？**
- 考点：图算法落地。
- 参考答案：连接前从 target 沿出边 BFS，能走回 source 就说明会成环，拒绝（canConnectNodes：workflowCanvasLogic.ts:29-54），同时挂到 React Flow 的 `isValidConnection` 让非法连线在拖拽时就变红不可放（WorkflowFlowCanvas.tsx:505-509）。编辑器侧 `cyclePath` 是带路径记录的 BFS，把环上节点翻译成角色标题给出人话报错「无法连接：该依赖会形成循环 规划 · 研究 · 规划」（WorkflowEditor.tsx:195-227）。两处分工：画布层要的是布尔值（实时校验），编辑层要的是可解释的错误信息。
- 追问链：平行边允许吗？→ 允许（同一对节点多条边、各自条件独立），normalizeWorkflowEdges 保 id 唯一且不重写已存 id（workflowEditorLogic.ts:51-62，测试 WorkflowCanvasLogic.test.ts:22-49）。

**B9. 保存前的图校验规则？**
- 考点：把后端约束前置到 UI。
- 参考答案：三条（WorkflowEditor.tsx:134-159）：① 至少一个节点；② 连通性——无向 BFS 判整图连通，有孤儿节点直接报「未连接」（画布上孤儿卡片也有 orphan 徽章，靠 primaryComponentKeys 主连通分量判定：workflowCanvasLogic.ts:1-27）；③ 所有分支必须汇入**唯一终端报告角色**——`hasSingleTerminalAgent` 要求出度为 0 的节点恰好一个、且是 produces_report 角色、且这类角色全图只此一个（workflowEditorLogic.ts:94-107）；报告角色集合由角色元数据 `produces_report` 驱动，legacy 回退 synthesizer（:109-117）。校验不过按钮禁用 + pipeline-health 提示，比提交后吃 422 体验好。
- 追问链：为什么早期位置的 synthesizer 也要拒绝？→ 报告角色出现在中游意味着最终报告不是全图汇聚的产物（测试 WorkflowCanvasLogic.test.ts:117-132）。

### C 档 · 深挖(架构与竞态)

**C1. React Flow 受控模式的坑，你们怎么踩过来的？（压力题）**
- 考点：第三方库状态模型冲突。
- 参考答案：React Flow 拖拽期间每帧改节点 position，全受控会导致每帧 setState 打满渲染；全非受控则外部数据（存库的 positions）无法回写。折中：`useNodesState` 本地持有，同步 effect 按 id 合并——只覆盖 type/selected/data 等派生字段，position 取 `props.positions[id] ?? existing.position`，拖拽中的瞬时位置不被打断（WorkflowFlowCanvas.tsx:289-308）。第二个坑：多选拖拽（Shift 框选）结束时如果只把锚点节点位置写回持久层，同步 effect 下一拍会用旧 positions 把其余节点**弹回原位**——修复是 `onNodeDragStop` 用第三参数 draggedNodes 全量合并（:495-503、mergeDraggedNodePositions 纯函数 + 测试 WorkflowCanvasLogic.test.ts:327-351）。第三个坑：语义入口/出口节点 id 可能与用户节点撞名，用探测式分配 `__canvas_semantic__:input:N`（workflowCanvasLogic.ts:72-91）。
- 追问链：viewport 为什么也受控？→ 存库后重开画布要还原视角；无 viewport（克隆模板）时 fitViewOnInit 自动取景（WorkflowEditor.tsx:104-114、WorkflowBuilderPage.tsx:74）。
- 陷阱：说「React Flow 有 bug」是错的——是受控/非受控混合模型的固有难点。

**C2. 409 版本冲突后为什么草稿不丢？完整讲一遍恢复流程。**
- 考点：乐观并发控制的前端侧。
- 参考答案：workflow 带 version 字段做乐观锁，提交体携带当前 version（WorkflowEditor.tsx:286）。另一端先保存后，本端 PUT 吃 409。处理（WorkflowBuilderPage.tsx:98-115）：① 错误文案明确「保存冲突：…当前草稿已保留」（:12-14）；② 编辑器**保持挂载**——React 组件不卸载，用户画的图、填的表全在本地 state 里；③ 只 refetch 列表拿服务端最新 version，回填进当前会话的 workflow.version（不动其他字段）；④ 用户下次点保存，提交体带新 version 通过。测试完整盖住这条链，包括「重试提交携带 version 2」（WorkflowBuilderPage.test.tsx:201-241）。克隆会话（clone=true）不做版本回填，因为走 create 不存在冲突（:100）。
- 追问链：为什么不自动合并服务端内容？→ 图结构的三方合并没有安全语义，把选择权留给人，前端只负责「不丢草稿 + 下次能过」。

**C3. 编辑会话隔离解决什么问题？为什么 key 要自增而不是 workflow id？**
- 考点：异步回调与 UI 生命周期错位。
- 参考答案：场景：编辑 A 点保存（请求在途）→ 关掉 → 打开编辑 B。A 的失败回调迟到后，若直接 `setError` 会把 A 的错误显示在 B 的编辑器里；成功回调会把 B 的编辑器关掉。方案：每次打开分配 `++sessionSequence.current` 的 key（WorkflowBuilderPage.tsx:35-58），错误按 key 存 `saveErrors` 字典、pending 存 `savingSessionKey`，onSuccess/onError/onSettled 全部先比对 key 再操作（:87-115）；`<WorkflowEditor key={editSession.key}>` 让 React 强制重挂载，上个会话的内部 state 彻底清零（:191）。用 workflow id 做 key 不行：同一条 workflow 关了再开是**两个**会话，旧回调仍会命中。测试：旧回调既不能关闭也不能污染新会话（WorkflowBuilderPage.test.tsx:179-199）。角色广场同款机制（AgentSquarePage.test.tsx:174）。
- 追问链：为什么不直接在关闭时取消 mutation？→ React Query 的 mutate 不可取消且服务端已在处理；隔离回调比取消请求更可靠。

**C4. 你们修过哪些前端竞态？各自的修法。（压力题）**
- 考点：竞态直觉，这是必考题。
- 参考答案（四个，从小到大）：
  ① **listWorkflows 迟到响应**：NewResearchPage 依赖 `?workflow=` 参数选中流程，连续导航触发两次请求，旧响应迟到会把选择弹回默认值。修法：effect 内 `let stale = false` + cleanup 置 true，迟到响应早退（NewResearchPage.tsx:28-44）；测试用两个 deferred promise 手工控制完成顺序，先完成第二个再完成第一个，断言 combobox 仍是 beta（NewResearchPage.test.tsx:46-74）。
  ② **多选拖拽回弹**：见 C1，本质是「本地瞬时状态 vs 受控回写」的写覆盖竞态。
  ③ **保存错误串会话**：见 C3，异步回调命中已切换的 UI。
  ④ **SSE 终态后的尾随事件**：abort 停不掉同 chunk 已排队的同步回调，reducer 终态冻结 + onMessage 守卫双保险（useResearchStream.ts:45-47、115-119）。
  另有一个跨端竞态：stream 报 error 时 DB 可能还没写入终态，轮询终止条件必须看 DB（RunPage.tsx:26-28）。
- 陷阱：面试官会追「为什么不用 AbortController 而用 stale 标记」——fetch 封装内没暴露 signal 的地方，布尔标记是零成本方案；两者语义等价（都是丢弃结果），标记不省带宽但省接口改动。

**C5. 自动布局算法讲一下？**
- 考点：轻量图布局，不背 dagre 也能做。
- 参考答案：`layoutWorkflowNodes`（workflowCanvasLogic.ts:344-412）三步：① Kahn 拓扑传播算每个节点的最长路径深度（分层）；② 逐层排序做**重心（barycentric）**一趟：按父节点在上一层的平均位置排，减少连线交叉，平局回退声明序；③ 网格化坐标（层距 190、列距 310），中心 X 取现有节点均值，保持用户视角连续。边的视觉分道独立处理：assignEdgeRouting 给扇出/扇入/同水平带的边分配互不相同的 offset（:140-202），buildRoutedEdgePath 生成带圆角的正交折线，垂直空间不足时绕侧边通道（:258-313）。测试断言分层正确、平行节点分列、相邻 lane 路径不同（WorkflowCanvasLogic.test.ts:232-315、353-364）。
- 追问链：为什么不用 dagre/elk？→ 需求只有「自上而下 DAG + 少交叉」，200 行纯函数可测可控，引库反而要适配 React Flow 坐标系。

**C6. 克隆模板预填是怎么实现的？为什么含 compose/team_fanout 的模板降级为空 Studio？**
- 考点：能力边界的诚实呈现。
- 参考答案：内置模板卡的迷你流程链与可克隆 steps 按名硬编码在 BUILTIN_TEMPLATE_META（BuiltinTemplateGallery.tsx:40-83）。点克隆构造 scaffold WorkflowDef：name 加 `-copy-{时间戳36进制}` 保唯一、viewport 故意不给让 Studio 首开 fitView、以 clone=true 开会话（WorkflowBuilderPage.tsx:60-81）；保存时 clone 会话走 create 并补回脚手架 name（:116-118）。auto/teams 模板的编排由运行时控制原语（Coordinator 动态组队 / team_fanout）驱动，静态「节点+边」schema 表达不了，steps 置 null，克隆降级为打开空 Studio 并在卡片标「运行时编排」徽章（BuiltinTemplateGallery.tsx:8-9、122）。测试盖三条：五张模板卡（custom='True' 不进模板区）、克隆 deep 预填四步链走 create、auto 降级空 Studio（WorkflowBuilderPage.test.tsx:128-175）。
- 追问链：为什么 steps 硬编码在前端而不从后端取？→ 内置定义稳定（deep_research/workflows.py），做展示层元数据成本最低；真正运行仍以后端为准。

### D 档 · 压力/开放

**D1. 「SSE 断了用户看到什么？」一句话版 + 展开版。**
- 一句话：状态角标仍是 running，头部出现「实时连接已断开，正在轮询获取进度…」，报告区在拿到落库版后自动切换为完整报告——用户不会看到假死，也不会看到重复内容。
- 展开：见 B4。关键词：不自动重连（重连=全量重放=重复）、disconnected 显式态、4s 轮询到 DB 终态、preferPersistedReport。
- 陷阱：如果面试官问「那不就不实时了」——承认：断线后降级为准实时（4s 粒度），这是「重复内容 vs 降低刷新率」的取舍，选了正确性。

**D2. 「这套前端如果并发多人编辑同一工作流，还缺什么？」**
- 考点：边界意识。
- 参考答案：现在是乐观锁 + 草稿保留 + 人工重试（C2），够单人/偶发冲突。多人实时协作需要：编辑中的 presence、字段级 diff/merge 或 CRDT、以及把 409 恢复从「版本回填」升级为「服务端内容三方对比 UI」。明确说：这是研究工具不是 Figma，当前投入止于此是刻意的。

**D3. 「为什么测试全离线？不怕 mock 和真实后端漂移吗？」**
- 考点：测试策略辩护。
- 参考答案：分层——① 协议层：SSE 解析直接 mock ReadableStream 分块（含 data 行跨 chunk 断开的用例，client.test.ts:10-40），类型契约由 TS types.ts 对齐后端 Pydantic 模型；② 逻辑层：reducer/进度推导/图算法全是纯函数直测（81 用例里占大头），无 mock 漂移问题；③ 页面层：mock 自己的 hooks 而不是 fetch，测的是组件与 hook 的契约。漂移风险由后端侧 334+ 测试和 e2e 手动验收兜底。反问自己也承认：缺一层真正的契约测试（如 schemathesis 前端消费验证），是已知空白。
- 陷阱：不要吹「测试全绿所以没 bug」，要讲每层测什么、不测什么。

**D4. 「前端里你最得意的一段代码？」**
- 建议答案：`reduceStream`（useResearchStream.ts:39-93）。理由：把「多智能体事件流→UI 状态」压缩成 50 行纯函数，同时编码了三条领域语义——只有编排器的终态才是运行终态（失败隔离的 UI 对应物）、终态冻结抵御回放尾随事件、统计单调不回退。它是后端可靠性设计在前端的镜像，也是整个题库「前端为 Agent 系统服务」定位的最佳注脚。

## 三、速记

- **SSE 五件套**：fetch+Reader（密钥走 X-API-Key 头不进 URL）｜TextDecoder stream:true 防多字节截断｜`/\r?\n\r?\n/` 边界兼容 CRLF｜只取 data: 行滤心跳｜终态 abort + 守卫防同 chunk 尾随回调。client.ts:217-263。
- **断线三步**：不重连（重连=全量重放=重复）→ disconnected 显式态 → 4s 轮询至 **DB** 终态；落库报告覆盖流式残留。useResearchStream.ts:99-147、RunPage.tsx:26-61。
- **终态判定**：`ORCHESTRATOR && (done|error)` 才是终态；RESEARCHER error = 失败隔离，只进时间线。useResearchStream.ts:34-36。
- **证据链三路数据**：findings←详情 results｜[n]→URL：citations 优先、「## 参考来源」回退｜拦截数←source_policy 审计事件，null 则降级注明。evidence.ts:100-127。
- **remark 插件**：mdast 层 [n]→#cite-n link，先合并相邻 text 再切分；components.a 拦截渲染；无 findings 降级 inert 角标。evidence.ts:23-72、ReportView.tsx:42-69。
- **画布三坑**：受控/本地双轨按 id 合并（Canvas:289-308）｜多选拖拽全量写回否则弹回（:495-503）｜语义节点 id 探测防撞（canvasLogic:72-91）。
- **环检测**：连线前从 target BFS 出边找 source；画布返回布尔、编辑器返回环路径报人话错误。canvasLogic:29-54、Editor:195-227。
- **409 恢复**：编辑器不卸载草稿在、只回填服务端 version、下次提交带新版本过。BuilderPage:98-115。
- **会话隔离**：自增 sessionKey + 回调比对 + `key=` 强制重挂载；错误按 key 存字典。BuilderPage:22-124。
- **四个竞态**：listWorkflows stale 标记｜多选拖拽写覆盖｜保存回调串会话｜SSE 终态尾随事件。
- **进度启发式**：完成数+活动权重(running .42/retrying .58/ready .12)/total，封顶 96/99，done 才 100；estimated 标志承认是估算。runProgress.ts:185-203。
- **动效**：expo 出场 + spring 微交互 + atelier 颜色，token 唯一出处；reveal 一次性不回退；reduced-motion JS+CSS 双降级。experience.css:48-54、1104-1113。
- **测试**：15 文件 81 用例全离线；协议层 mock ReadableStream 分块、逻辑层纯函数直测、页面层 mock hooks + deferred promise 控时序。
- **一句话定位**：前端的每个设计都是后端语义的镜像——失败隔离→非终态 error、事件回放→终态冻结、乐观锁→草稿保留。
